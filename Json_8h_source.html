3// Read-only JSON facade and canonical Value serializer shared by every module
4// that loads data-driven config.
5//
6// The backend is a self-contained recursive-descent parser (Json.cpp) rather
7// than Poco, so EVCommon stays dependency-free and modules that only read JSON
8// (rpg / inventory / building / card / voxel / housegen / i18n) no longer pull
9// Poco in just to parse a config file. Writing JSON still goes through
10// `stringify` is the single canonical serializer for common::Value. The
11// legacy data::JsonDocument/Poco facade remains available for mutable legacy
12// integrations, but must not be used as a second Value serialization format.
13//
14// Accessors never throw: a missing key, a wrong type or an out-of-range index
15// yields the supplied fallback (or a null Value), which is what config loading
16// wants and what the per-module helpers this replaces already did.
