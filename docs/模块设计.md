这些都是可以载入的 module，不需要时可以不载入  
全是等待被调用的模块，不会主动去调用

主要参考 love2d 和 Bevy 的设计，也将 cocos2dx 中的一些经典设计拿过来；游戏模型模板可参考 ECS 设计。

> 勾选约定：`- [x]` 表示该模块/能力已可用；`- [ ]` 表示待实现。可按子项逐步打钩推进。


## 类绑定原则

每个 API 都不重名，不使用重载，使用明确的类型，有部分参数有默认值。

枚举类型接口：可使用 `uint32_t` 或直接用 `string`。

计划使用 **string**，主要原因有 3：

1. 方便，无需定义枚举类型，少了很多绑定操作
2. 可扩展，日后 API 想扩展新功能，无需导出新定义，只需在函数中增加对新名称的支持
3. 直观，脚本与 C++ 代码中用 string 都很直观，避免宏、枚举引入头文件与 namespace 等问题

**设计文档：** 详见 [2D渲染API设计.md](./2D渲染API设计.md)。

Love2D 风格即时模式仅作 C++/DevTools 内部逃生舱。  
分期：**A** = 下列「基础能力」；**B** = 「高级能力」。

**基础能力（A）：**

- [ ] ECS 整合（[ECS.hpp](https://github.com/sunxfancy/ECS.hpp) 子模块）与渲染组件（`Transform2D` / `Sprite`）
- [ ] `RenderSystem`：每帧 View 收集并绘制（脚本不 per-sprite draw）

- [ ] `clear` / `present`、与 SDL Window Surface 对接
- [ ] 离屏 Canvas（组件或内部目标，P1）
- [ ] 用户自定义 Shader（P1，先进内部）

**高级能力（B，依赖 A，见设计文档第 8 节）：**
