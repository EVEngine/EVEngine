主要参考love2d和Bevy的设计，但也要将cocos2dx中的一些经典设计拿过来，在关于游戏模型的模板，参考一下ECS设计

## 类绑定原则

每个API都不重名，不使用重载，使用明确的类型，有部分参数有默认值

考虑一下枚举类型的接口
可以使用 uint32_t 或直接用 string

经过考虑，我计划使用string，主要原因有3：
1. 方便，无需定义枚举类型，少了很多绑定操作的费事定义
2. 可扩展，日后api想扩展新功能，无需导出新的定义，只需在函数增加对新名称的支持即可
3. 直观，不但脚本中直观，C++代码中用string也很直观地知道这是啥，避免了用宏，枚举等需要引入头文件，解决namespace等诸多问题


## 模块设计

1. 文件系统 - filesystem
    封装了核心的文件系统功能，提供如下功能：统一的文件系统访问、目录查看、文件增删改查、监视文件变动

2. 事件系统 - event
    主要处理多线程间的信号同步与各种回调事件，处理来自硬件的各种信号
    mouse，keyboard，touch，joystick四个模块分别处理不同的设备输入

3. 窗口系统 - window
    主要处理渲染窗口的设置、位置、样式、全屏等，我们只支持单窗口，目前SDL可以完成所有功能

4. 图形系统 - graphic
    主要处理图形的各种渲染、显卡、shader等，是核心中的核心，并且相比love2d, 拥有更多高级功能
    有如下主要功能：
    1. 渲染图片、图片切片
    2. 渲染基础图形、mesh
    3. 渲染到Canvas
    4. 用户自定义shader
    其他高级功能：
    1. 精灵类，根据属性，自动渲染不同样式的图片
    2. 场景类，可以传入参数的场景，方便调试游戏的部分模块，部分章节
    3. 地图类接口，可以直接渲染tilemap
    4. 摄像机，可以做2d下的光照和法线贴图
    5. 低像素优化，支持小图片的旋转
    6. 简单的3dmodel支持

5. 插件系统 - plugins
    主要负责加载第三方模块和插件，加载dll等
    plugin system 的核心是一套基于string的依赖管理系统，把之前写的PluginFramework的java代码改一改

6. 管理系统 - system
    负责系统版本、时间、状态等的查询和设置

7. 资源管理系统 - image sound video fonts 3dmodel spirit
    负责加载图形、声音、视频、字体、3d模型、动画等不同格式数据（优先实现image和sound，其次是fonts和3dmodel）

8. 网络系统 - network
    封装网络通讯的各种基础操作，这部分poco有很优雅的实现，不过需要考虑异步事件，要整合进event系统中

9.  线程系统 - thread
    负责线程、线程池的管理，提交异步任务，必要时考虑使用一下tbb，注意整合event系统

10. 粒子系统 - particles
    负责创建、渲染、加载设置等关于粒子系统的设置（后期）

11. Box2d物理 - box2d
    负责管理box2d物理引擎（后期）

12. 动画系统 animation
    Skeleton Animations（后期）

13. GPU计算系统 - compute
    并行化和异构计算，封装compute shader的相关操作，想办法实现计算后buffer直接传递到graphic中

14. tilemap地图类 - map
    地图相关的类，重点是地图的读取与保存，多层地图的表示，用C++代码直接生成和访问array来实现，可以方便squirrel侧的数据访问
    同时，在有资源时，这个类也是renderable的

15. 数据库 - database
    数据库的连接，使用poco对sqlite进行链接，实现游戏数据库的简单操作，核心是在实体设定好后，可以进行ORM映射，方便地进行游戏数据的更新与查询

16. 数学库 - math
    这个库是矩阵和向量库，用来实现一些数学运算的，有glm操作的一些直接导出，也有新实现的noise和贝塞尔曲线
