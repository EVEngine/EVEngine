这些都是可以载入的 module，不需要时可以不载入  
全是等待被调用的模块，不会主动去调用

主要参考 love2d 和 Bevy 的设计，也将 cocos2dx 中的一些经典设计拿过来；游戏模型模板可参考 ECS 设计。

> 勾选约定：`- [x]` 表示该模块/能力已可用；`- [ ]` 表示待实现。可按子项逐步打钩推进。


## 类绑定原则

每个 API 都不重名，不使用重载，使用明确的类型，有部分参数有默认值。

枚举类型接口：可使用 `uint32_t` 或直接用 `string`。

计划使用 **string**，主要原因有 3：

1. 方便，无需定义枚举类型，少了很多绑定操作
2. 可扩展，日后 API 想扩展新功能，无需导出新定义，只需在函数中增加对新名称的支持
3. 直观，脚本与 C++ 代码中用 string 都很直观，避免宏、枚举引入头文件与 namespace 等问题

### 21. RPG 框架 — `rpg`

面向 RPG 类游戏的属性 / 效果 / 状态 / 技能 / 结算五套系统，全部以字符串为 key
数据驱动，核心可插拔扩展点（自定义属性运算、施法条件、结算阶段）留给 C++ 侧注册。
**设计文档：** [2026-08-08-rpg-module-design.md](./2026-08-08-rpg-module-design.md)。

- [x] 属性系统：任意字符串属性名 + 多重修改器（add/mulAdd/mulMul/override/clamp*/自定义 op）
- [x] 效果系统：数据驱动 `EffectDefinition`（C++ 注册 / JSON 加载）
- [x] 状态系统：施加/移除/到期、四种叠加策略（none/refresh/extend/stack）、周期 tick 事件
- [x] 技能系统：学习/冷却/消耗/读条/取消、自定义施法条件注册
- [x] 结算系统：具名可插拔流水线（优先级排序、取消、脚本可开关/重排）
- [x] `RPGActor` ECS 实体（三组件）+ 便捷成员方法 + `eve.RPG` 脚本绑定
- [ ] 与 `event` 模块的事件队列打通（目前 tick / cast 事件走独立的 push/poll 缓存）
- [ ] 存档序列化（属性/状态/技能运行时状态落盘格式）

代码：[`src/modules/rpg/`](../src/modules/rpg/)  
测试：[`test/rpg.cpp`](../test/rpg.cpp)
