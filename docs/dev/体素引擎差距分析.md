# 体素引擎差距分析 — `voxel` vs 主流体素引擎

日期：2026-08-18（Phase B-1 正确性/性能；Phase B-2 顶点 AO + 持久化/流式卸载；2026-08-19 Phase B-3 自动流式加载 + 地形生成）  
范围：对照主流体素引擎（Minecraft 类、Teardown、Godot Voxel/Zylann、SVO 学术引擎、WebGPU Voxel 引擎等）评估 EVEngine `voxel` 模块的功能完整度与性能差距，并记录本轮已实施的改进。

## 1. 参考基准（主流体素引擎共性能力）

基于对 Minecraft 类引擎、[Teardown](https://80.lv/articles/teardown-developer-breaks-down-multiplayer-and-voxel-destruction-tech)、[Zylann/godot_voxel](https://github.com/Zylann/godot_voxel)、SVO/Octree 研究引擎及社区 voxel.wiki 的调研，主流体素引擎通常具备：

| 能力 | 说明 | 代表实现 |
|------|------|----------|
| 分块存储 | 16³ / 32³ dense chunk + 稀疏世界索引；大规模世界用调色板/RLE 压缩 | Minecraft 16³ paletted；[Tantan RLE](https://www.gamesinprogress.com/indie-game-developers/tantan/blazingly-fast-voxel-data-generation) |
| 邻接感知 meshing | 同 chunk 与 **跨 chunk** 相邻面消隐（chunk 接缝不产生重复面） | Minecraft / 多数引擎默认 |
| 多线程网格生成 | 编辑/生成后异步并行重建 chunk 网格 | Minecraft、Godot Voxel（worker 池）、[roxlap-scene](https://docs.rs/roxlap-scene) |
| 射线拾取（DDA） | 方块放置/破坏/瞄准必须的世界射线求交 | 全部 Minecraft 类引擎 |
| 顶点环境光遮蔽（AO） | 网格生成时按相邻方块计算角部遮蔽，烘焙进顶点 | Minecraft、godot_voxel `bake_occlusion` |
| LOD / 流式加载 | 视距外降采样（SVO/Octree、Transvoxel 平滑过渡）、按玩家位置流式加载/卸载 | Godot Voxel `VoxelLodTerrain`、[phenotype-voxel](https://github.com/KooshaPari/phenotype-voxel) |
| 动态破坏/增量更新 | 编辑只重建设影响区域；版本号丢弃过期网格 | Teardown（GPU 体素 + 实时破坏）、Godot Voxel 数据块版本 |
| 透明方块 / 排序 | 半透明方块独立 pass 或排序渲染 | Minecraft 半透明通道 |
| 持久化 | 世界数据流式读写（磁盘/网络生成器） | Godot Voxel `VoxelStream` |
| GPU 渲染优化 | 实例化/合批、静态大缓冲、按材质分 pass | 现代引擎通用做法 |

## 2. EVEngine `voxel` 现状盘点（2026-08-18）

### 已有能力（Phase A）

- 32³ dense chunk + 稀疏 `unordered_map` 世界
- 贪婪矩形合并 + 32-bit `PackedRect`（xyz+wh+tex）
- 六向子缓冲、视锥 + 视距 + 面朝向裁剪
- `Graphics::drawVoxelFaceInstances` 实例化 unit-quad（Vulkan）
- 方块类型注册表（各面纹理 / 方向性 / JSON 加载）
- `getVoxel/setVoxel/setVoxelByName` 世界编辑 API

### 差距与不完善项（改进前）

| # | 差距 | 影响 | 严重度 |
|---|------|------|--------|
| 1 | **跨 chunk 接缝不消隐**：相邻 chunk 边界按“空气”处理，共享面在两侧各生成一次 | 实心地形的内部边界重复绘制，顶点数/填充率翻倍；深色 seam 伪影 | 高（正确性+性能） |
| 2 | **边界编辑不失效邻居**：在 chunk 边界面改方块，邻居网格仍保留被遮挡的面 | 挖/填边界后出现残影、z-fighting | 高（正确性） |
| 3 | `selectVisible` 先 remesh 全部 dirty chunk 再做视距/视锥裁剪 | 视距外、相机后的编辑也被无谓重建；大世界帧尖峰 | 中（性能） |
| 4 | **无 DDA 射线拾取**：脚本无法做方块瞄准/放置/破坏 | 玩法（建造、交互）无法落地 | 中（功能缺失） |
| 5 | **单线程 remesh**：大量 chunk 生成/编辑时串行重建 | 世界生成卡顿；与主流多线程 meshing 差距明显 | 中（性能） |
| 6 | 无顶点 AO | 体素视觉平、缺少角部阴影层次 | 低（视觉） |
| 7 | 无 LOD / 流式加载 | 视距受限于单级 32³ chunk 数 | 低（大工程） |
| 8 | 无持久化（存档/读档） | 世界无法保存 | 低（依赖 `data`/`database`） |
| 9 | 透明/半透明方块未建模 | 水面、玻璃等无法表达 | 低（依赖类型系统扩展） |
| 10 | 用户文档缺失：`docs/usr/modules/` 无 voxel 页面 | 脚本开发者无法上手 | 低（文档） |

## 3. 本轮已实施的改进（2026-08-18）

### 3.1 跨 chunk 邻接消隐（差距 #1）

`GreedyMesher` 新增可选 `ChunkSampler`（chunk 坐标 + 局部坐标 → 体素 id）：网格化时，边界上的面会查询相邻 chunk 的真实体素，固体邻居存在则整面剔除。`VoxelWorld` 通过 `chunkNeighborSampler` 接入自己的稀疏世界；无采样器时退化为旧行为（邻居视为空气），Chunk 级用法完全兼容。

效果：实心相邻 chunk 的共享面不再生成，表面矩形数可减少约 1/6（六个方向之一），消除接缝伪影。

### 3.2 边界编辑邻居失效（差距 #2）

`setVoxel` 写入落在 chunk 边界（局部坐标 0 或 31）时，会同时把该方向的相邻 chunk 标记 dirty，下次 `remeshDirty`/`selectVisible` 一起重建；删除方块落在未分配 chunk 时不再凭空创建 chunk（空气不需要存储）。

### 3.3 `selectVisible` 延迟 remesh（差距 #3）

先做视距 + 视锥裁剪，只对可能可见的 chunk 调用 `ensureMeshed`。视距外/相机后的脏 chunk 不再每帧重建；进入视距后自然补网格。

### 3.4 DDA 射线拾取（差距 #4）

`VoxelWorld::raycast`（Amanatides & Woo DDA）：返回首个固体方块命中坐标、命面前的空气方块（用于放置）与进入面的法线；支持负坐标、起点在方块内、`maxDist` 限制。脚本绑定：`world.raycast(ox,oy,oz,dx,dy,dz,maxDist)` + `lastRaycastHit()` / `getRaycastHitX/Y/Z` / `getRaycastPrevX/Y/Z` / `getRaycastFaceX/Y/Z`。

### 3.5 并行 remesh（差距 #5）

`remeshDirty(maxThreads)`：默认 0 = 自动（`hardware_concurrency`，上限 4）；1 = 串行；>1 = 指定 worker 数。每个 worker 处理互不重叠的 chunk 切片，采样器只做只读 map 查询，主线程处理剩余切片后 join；线程创建失败自动回退串行。结果与串行逐位一致（有测试保证）。

### 3.6 文档补齐（差距 #10）

- 新增用户模块文档 [`docs/usr/modules/voxel.md`](../../usr/modules/voxel.md) 并挂入 [MODULES.md](../../usr/MODULES.md)
- 更新本差距分析与 [`体素渲染模块设计.md`](./体素渲染模块设计.md) 状态

### 3.7 顶点环境光遮蔽（差距 #6，2026-08-18 晚）

`GreedyMesher` 在贪婪合并后为每个矩形计算 4 角 AO（经典 Minecraft 式：角部两个侧邻 + 对角，
`side1&&side2 ? 0 : 3 − (side1+side2+diag)`，0..3），打包成 2bit×4 的 32-bit 字，与 `PackedRect`
一一对应。`Chunk` 增加 `ao_[6]` 缓冲，`Graphics::drawVoxelFaceInstances`（Vulkan）新增实例属性
binding 2（null → 全亮 0xFF），`voxel_rect` shader 按顶点角选择 AO 并乘到光照上。
WebGPU 后端暂接受参数但不应用（TODO），CPU 侧 `VoxelRectDecode` 提供解码镜像便于测试。
平坦地面全亮，凹凸台阶角部自然变暗。

### 3.8 世界持久化 + 流式卸载（差距 #8/#7 前半，2026-08-18 晚）

- `VoxelWorld::serializeWorld` / `deserializeWorld`：可移植小端格式（`EVVX` 魔数 + 版本 + chunk
  数 + 每 chunk `(cx,cy,cz)` + 32³ 原始体素），加载后按需重建网格；脚本侧
  `saveWorld() -> ByteData` / `loadWorld(ByteData)`。
- `VoxelWorld::unloadChunksOutside(cx,cy,cz,radiusChunks)`：按玩家中心距离卸载 chunk，
  返回值=卸载数；半径 <0 为 no-op，半径 0 只保留中心 chunk。卸载后自动清空可见批次避免悬垂指针。

以上两项合起来即可实现“玩家移动 → 卸载远处 chunk → 需要时重新生成/读档”的流式生命周期。

### 3.9 自动流式加载 + 地形生成（差距 #7 后半，2026-08-19）

- `VoxelWorld::streamAround(cx, cy, cz, radius, generator)`：一次调用完成
  “卸载半径外 → 在半径内补建缺失 chunk（球形）→ 对新 chunk 调用生成器 → 并行重建网格”。
  生成器为空时使用世界内置地形；均无则创建空 chunk。
- 地形采样**直接复用 procgen 模块现成的 `procgen::TerrainSampler`**（确定性 Perlin fBm：
  大陆/扭曲/山脊参数、可设种子），不新增模块；voxel 侧只做 32³ 列填充适配。
  `world.terrainHeightAt(wx,wz)` 世界坐标采样保证跨 chunk 无缝衔接，按“草皮/泥土/石头”分层。
  脚本侧 `world.setTerrain(seed, top, sub, stone, base, amp, scale)` +
  `world.streamAround(cx,cy,cz,radius)` 即可让世界随玩家移动持续生成。

组合效果：`streamAround` + `saveWorld`/`loadWorld` + `unloadChunksOutside` 构成了完整的
“生成 → 流式进出 → 持久化”生命周期，可直接支撑可移动大世界的原型。

## 4. 尚未实施的差距（建议后续优先级）

| 优先级 | 项目 | 建议方案 |
|--------|------|----------|
| P1 | ~~顶点 AO~~ | ✅ 已实现（矩形 4 角 AO + 2bit×4 打包 + Vulkan shader；WebGPU 待补） |
| P1 | ~~流式卸载~~ | ✅ 已实现 `unloadChunksOutside` |
| P1 | ~~自动流式加载~~ | ✅ 已实现 `streamAround`（直接复用 `procgen::TerrainSampler`，未新增模块） |
| P1 | ~~持久化~~ | ✅ 已实现 `serializeWorld`/`saveWorld`；后续可加 LZ4/RLE 压缩与 `CubeTypeRegistry` 版本化 |
| P2 | LOD | 32³ chunk 降采样为 64³/128³ 低细节块；远距用独立 mesh + Transvoxel 平滑过渡（参考 godot_voxel） |
| P2 | 透明方块 | `CubeType` 增加 `transparent/alpha` 标记，`Chunk` 增加透明面缓冲，独立渲染 pass |
| P2 | 增量局部 remesh | 编辑时只重建受影响矩形（当前 32³ 整 chunk remesh 已足够快，收益有限） |
| P2 | GPU 合批 | 将各 chunk 六向实例缓冲合并为按纹理分组的持久大缓冲，减少 draw call 与每帧上传 |
