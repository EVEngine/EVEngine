## Contracts that should remain distinct

Frame capture checks same-frame attachments and frozen snapshots, not merely image appearance. Renderer parity tests cover different texture dimensions/formats, target sizes, depth conventions, masked materials and backend capability failure. Vegetation shader branches, tensor kernels, descriptor retirement and virtual-geometry cull/raster/LOD are separate algorithms or lifetime boundaries; similar setup is not redundancy evidence.

Window create/close/reopen, fullscreen, DPI conversion, suspend/resume and present-after-restore exercise distinct OS transitions. UI scheduling tests use a real ImGui frame plus ECS/component reconciliation and reentrant/failing builds; a layout geometry test cannot stand in for them. PCM backpressure/ownership and pump-driven starvation/pause/drain, both destruction orders and script Result ownership are distinct; its bounded 5 ms polling loop (3-second deadline) is real backend progress, not a reason to mock away the only audio adapter test.

Material preview shadows compare real pixels against unshadowed capture, whereas MaterialStudio script tests use a real VM with injected editor/resource doubles. The geometry-only script test still executes the actual embedded Squirrel library; it may belong in a smaller script-library lane but is not equivalent to a C++ geometry unit. ControlRig editor/document history, publication revision, failed undo restoration, automation capability ownership and stale replacement lifetimes are real cross-module contracts, even without GPU/OS setup. Avatar appearance checks script-visible checked results and owned snapshots/PBR copy; sprite atlas checks animation layout reaching actual pixels.

## Review limits and next verification

This pass inspected all physical files and declaration/section inventories, read the flagged bodies and neighboring retained contracts, and followed shared graphics/VM setup and effect constructor implementations. It did not prove equivalence of every long render scenario, manually trace every script helper, evaluate both Vulkan and Dawn at runtime, measure setup costs per proposed group, or execute any test. No item marked candidate is a mechanical deletion/migration instruction.

Before changing a candidate, record its precise observable contract; preserve one representative success plus the relevant validation/rollback/provider-absence/destruction-order failure; compare per-case assertions and actual compiled discovery; then run the affected domain/profile on its real backend. Shared subcases require demonstrated reset and failure cleanup, especially module singletons, ECS managers, environment variables and GPU frame resources. Backend/format/target variants must remain explicit.
