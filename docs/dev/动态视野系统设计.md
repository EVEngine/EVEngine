# 动态视野系统设计 — `map` FOV / Fog-of-War

日期：2026-08-10  
状态：Phase A / B 已实现（`src/modules/map/Fov.{h,cpp}`）；Phase C 可选  
存放：`docs/dev/`

## 目标

在现有 `map` 模块上提供**与投影解耦、同时覆盖 2D 格子地图与多层/体素 3D 地图**的动态视野（Field of View, FOV）与战争迷雾（Fog of War, FoW）能力：

1. **格子可见性计算**：给定观察者位置与半径（可选扇形角度），输出当前可见格集合
2. **动态更新**：观察者移动、半径变化、遮挡格变更时，可增量或全量重算
3. **探索记忆**：区分「当前可见 / 已探索未可见 / 未探索」三态，供 RPG / RTS / Roguelike
4. **2D ↔ 3D 同构 API**：同一套 `VisionGrid` + `FovComputer`；2D 为高度 1 的特例，3D 为多层体素或高度场
5. **呈现解耦**：本模块只产出可见性缓冲；2D 叠图遮罩与 3D GPU 雾采样由游戏或后续 `graphics` 适配器消费

与现有模块关系：

| 模块 | 关系 |
|------|------|
| `map` / `TileLayer` / `Pathfinder` | **消费** 尺寸、GID、阻挡语义；遮挡格可复用 `blockGid` / `setBlocked` 思路，但语义是 *opaque* 而非 *unwalkable*（墙可挡视线但可走、玻璃可走但透明等需分离） |
| `spatial` | **可选消费**：FOV 半径圆/球查询候选实体；**不**用 AABB 代替 LOS |
| `graphics` `Camera2D` / `Camera3D` | **不混用**：相机 `setFov` 是透视投影角；本系统是玩法可见性。体积雾 `Volumetric` 是大气效果，不是 FoW |
| `rpg` | 可后接「感知 / 隐身」修正半径；一期不硬依赖 |

设计语言对齐 [模块设计.md](./模块设计.md)、[寻路系统设计.md](./寻路系统设计.md)、[Tilemap设计.md](./Tilemap设计.md)：string key、无脚本重载、图抽象与投影解耦。

## 非目标（一期）

- 连续多边形精确可见性（旋转平面扫描 / 完整 Visibillity Polygon）；一期以**格子/体素**为主
- GPU 上实时全图 shadowcast（可作为二期加速路径）
- 与 `Camera3D` 视锥裁剪合并（那是渲染裁剪；见 `spatial` 的未来 `queryFrustum`）
- NavMesh / 三角形网格上的 LOS
- 自动把 FoW 画进默认 `Map::render`（一期只提供缓冲 + 可选导出纹理接口约定）

## 公开资料与选型依据

下列公开资料用于算法与架构选型（非依赖库）：

| 来源 | 结论对本设计的影响 |
|------|-------------------|
| [RogueBasin — FOV using recursive shadowcasting](https://www.roguebasin.com/index.php/FOV_using_recursive_shadowcasting)（Björn Bergström） | **一期默认算法**：八分扇区、按行/列向外扫描、遇挡体递归切分斜率区间；室内/通道场景高效 |
| [RogueBasin — Comparative study of FOV algorithms](https://www.roguebasin.com/index.php/Comparative_study_of_field_of_view_algorithms_for_2D_grid_based_worlds)（Jice / libtcod, 2009） | Shadowcasting 综合速度优；无绝对完美算法；需在柱影、拐角 peek、对角墙、对称性上可配置 |
| [Precise Permissive FOV](https://www.roguebasin.com/index.php/Precise_Permissive_Field_of_View)（Jonathon Duerig）+ [Adam Milazzo 综述](http://www.adammil.net/blog/v125_Roguelike_Vision_Algorithms.html) | 需要对称性时可选 `permissive`；默认不强制（过 permissive、实现更重） |
| Huang & Weng, *A Survey on 2D Visibility Algorithms* (ACE, 2026) | 归纳 ray casting / rectangle-based / RSC；并引用 **2.5D 切片式 RSC**（Batinovic 等）作为 3D 实用路径 |
| Batinovic et al., *Shadowcasting-Based Next-Best-View Planner* (IEEE RA-L, 2022) | 3D → 垂直 2D 切片系列 RSC + 跨切片遮挡缓冲；复杂度可控 |
| [3D Fog of War 实践](https://lorenzomorini.dev/blog/2/post.html)（Lorenzo Morini） | 真 3D FoW：水平 shadowcast → **垂直延拓** → 可见性体素缓冲 → 后处理三线性采样；区别于 Warcraft III「视觉 3D、逻辑 2D」 |
| MangoFog / Tasharen FogOfWar（Unity 生态） | 2D/3D **同一 revealer 模型**（半径 / 扇形 LOS）+ 遮罩纹理 / Mesh / GPU 绘制切换，印证「计算与呈现分离」 |

**一期算法默认：`shadowcast`（递归阴影投射）**  
**可选二期：`raycast`（调试/对照）、`permissive`（强对称玩法）**  
**3D 默认：`slice_rsc`（分层 2D RSC + 垂直传播）；高度场模式：`heightmap`（单层 + 海拔规则）**

## 核心抽象

```text
FovComputer (facade, 由 Map::newFov / newFovSize / newFovVolume 创建)
  ├─ VisionGrid        遮挡 + 尺寸（2D: W×H；3D: W×H×D）
  ├─ VisibilityBuffer  当前可见 + 已探索记忆（同尺寸）
  ├─ Revealer[]        动态观察者（位置、半径、扇形、高度层）
  ├─ compute()         合并所有 revealer → 写入 VisibilityBuffer
  └─ query API         isVisible / isExplored / sample / exportMask
```

### 为何与 Pathfinder 并列而不是塞进 spatial / graphics

- 寻路问「能否走到」；视野问「能否看见」——阻挡语义不同，但都在**格子索引空间**
- `spatial` 只做 AABB 宽相；精确 LOS 属于窄相玩法逻辑
- `graphics` 的相机 FOV / 体积雾是呈现；本系统是玩法状态机

### 统一坐标与模式

```text
mode:
  "grid2d"     — 经典瓦片地图（默认）
  "heightmap"  — 2.5D：逻辑仍是 2D 网格，每格 elevation；高看低 / 崖壁挡视线
  "volume"     — 真 3D：W×H×D 体素遮挡与可见性
```

| 地图形态 | 推荐 mode | 说明 |
|----------|-----------|------|
| Orthogonal / Isometric / Hex 瓦片 | `grid2d` | 与 Pathfinder 相同：投影只影响世界坐标，不影响格子可见性邻接 |
| 伪 3D（sprite-stack / 分层 TileLayer） | `heightmap` 或按层多次 `grid2d` | 高度差规则见下 |
| 体素地牢 / 桥洞洞穴 | `volume` | 切片 RSC + 垂直延拓 |
| 纯 3D 网格场景无格子 | 非本模块一期范围 | 可用射线 + `spatial`；或自建体素代理网格 |

六角拓扑：一期 `grid2d` 在 hex 上仍用**轴向立方体邻接的 shadowcast 变体**或回退「外接正交 shadowcast + hex 中心采样」；实现时以 `setTopology("auto"|"ortho"|"hex")` 暴露，默认 `auto` 跟 layer orientation（与 Pathfinder 一致）。

## VisionGrid（遮挡场）

```text
VisionGrid {
  width, height, depth      // depth=1 即 2D
  opaque[i]                 // bool：是否完全挡视线
  opacity[i]?               // 可选 float 0..1：半透明（一期可只做 bool）
  elevation[i]?             // heightmap 模式：整型或 float 海拔
  blockGids / clearGids     // 绑 TileLayer：GID → opaque（与 walkable 表分离）
  layer?: TileLayer*        // 可选；syncFromLayer()
}
```

扩展点：

- 不绑 layer：`newFovSize(w,h)` / `newFovVolume(w,h,d)` + `setOpaque`
- 多逻辑层：游戏可将「墙层」同步为 opaque，把「地面层」忽略
- 动态门/破坏：改 `setOpaque` 后 `markDirty()`，下次 `compute` 重算

**与 Pathfinder 的关系（推荐组合用法）：**

```squirrel
// 可行走 ≠ 挡视线：玻璃、栏杆、矮墙需游戏分别配置
pf.blockGid(wallGid);
fov.blockOpaqueGid(wallGid);
fov.clearOpaqueGid(glassGid); // 可见可挡走或反之由游戏决定
```

## VisibilityBuffer（可见性状态）

每格（或体素）状态编码建议：

| 位 / 枚举 | 含义 |
|-----------|------|
| `Unknown` | 从未见过（黑雾） |
| `Explored` | 探索过但当前不可见（记忆轮廓 / 灰色） |
| `Visible` | 当前在某 revealer 视野内 |

API：

- `isVisible(x,y[,z])` / `isExplored(...)` / `getState(...)`
- `clearMemory()` — 重置已探索（新任务/新地图）
- `resetVisibleOnly()` — 每帧计算前清空当前可见，保留 explored
- `mergeOr` — 多队伍视野合并时用

可选强度：`visibility[i] ∈ [0,1]`，便于遮罩羽化；shadowcast 输出先二值，再可选半径衰减与盒模糊（参考 FoW 纹理实践）。

## Revealer（动态观察者）

```text
Revealer {
  id
  x, y, z            // 格子坐标；2D 时 z 忽略或 0
  radius             // 切比雪夫 / 欧氏 / 曼哈顿，由 setRadiusMetric 选择
  angleDeg?          // 扇形半角；缺省 360° 全向
  facingDeg?         // 扇形朝向（2D 平面角）；3D 可另加 pitch（二期）
  eyeHeight?         // heightmap / volume：眼睛所在高度层
  team?              // 可选；computeForTeam
  enabled
}
```

**动态性来源：**

1. Revealer 位置 / 朝向 / 半径变化 → dirty
2. VisionGrid opaque / elevation 变化 → dirty
3. 显式 `compute()` 或 `update(dt)`（若挂模块时钟）

一期策略：**全量重算所有 enabled revealer 并 OR 合并**（半径典型 8–20，格数可控）。  
二期：按 revealer 旧圆与新圆的对称差分、或脏矩形，做增量清除与重投。

## 算法细节

### 2D：Recursive Shadowcasting（默认）

对每个 revealer：

1. 标记原点可见；按半径剪枝
2. 分 8 个 octant；每个 octant 自近及远按行（或列）扫描
3. 维护 `[startSlope, endSlope]`；遇 opaque 格则递归开启子扫描并收紧斜率
4. 扇形：在 octant 入口用 `facing±angle` 裁剪斜率范围
5. 半径：欧氏 `dx²+dy² ≤ r²`（默认）或切比雪夫 `max(|dx|,|dy|) ≤ r`

对角墙与穿角：与 Pathfinder ortho8 类似，提供 `setCornerPeek(bool)`：

- `false`（偏 shadowcast 经典）：更利于潜行柱影
- `true`：更 permissive 的拐角窥视（玩法向）

### 2D：Raycast（可选对照）

从原点向圆周离散角度发射 Bresenham / 超覆盖线，命中 opaque 停止。实现简单、易出尖刺伪影；用于测试与极小半径。

### 2.5D：Heightmap 规则

在 2D shadowcast 扫描时附加海拔判定（Warcraft III 类「逻辑 2D、视觉有高差」的可配置近似）：

```text
viewerElev = elevation[ox,oy] + eyeOffset
targetElev = elevation[tx,ty]
若视线路径上存在格 e，满足 e.elevation >= viewerElev + cliffBlock
且该格位于观察者与目标之间 → 遮挡
高处看低处：若 targetElev + seeDownBias < viewerElev，仍允许（可配置）
低处看高处：反之收紧或不允许翻越崖壁
```

参数全部 string/数值可配，避免写死某一 RTS。

### 3D：Volume = 切片 RSC + 垂直延拓

对齐公开的 2.5D/3D 实践：

```text
1. 在观察者所在水平切片 (z = eyeZ) 上跑 2D shadowcast → 水平可见集合 H
2. 对每个 (x,y) ∈ H，沿 +Z/-Z 垂直延拓：
     连续写入 Visible，直到命中 opaque 体素或超过 verticalRange
3. （可选）对水平边界再膨胀 1 个体素，减轻锯齿（Morini 文中的 edge smooth）
4. 多切片强化（Batinovic）：障碍密集时减小切片间距 / 对邻接切片做遮挡模式缓冲
   一期可只做「单切片 + 垂直延拓」；二期加多切片融合
```

桥、洞穴、多层甲板：因可见性存在于 `W×H×D`，可表达「桥下看不见桥上」——这是相对纯 2D FoW 的核心收益。

### 多观察者合并

```text
resetVisibleOnly()
for r in revealers where enabled:
    run algorithm(r) → OR into Visible，并标记 Explored
```

敌我分离：`computeTeam(teamId)` 只合并该队 revealer，或维护多份 `VisibilityBuffer`（由游戏持有）。

## 脚本 API（无重载，草案）

```squirrel
local map = eve.Map();
local layer = map.newLayer(64, 48, 16, 16);
// ... 填瓦片 ...

local fov = map.newFov(layer);          // depth=1, mode grid2d
fov.setAlgorithm("shadowcast");      // shadowcast | raycast | permissive(后期)
fov.setRadiusMetric("euclidean");    // euclidean | chebyshev | manhattan
fov.blockOpaqueGid(1);
fov.syncFromLayer();

local id = fov.addRevealer(10, 12, 8); // x, y, radius
fov.setRevealerFacing(id, 90.0, 45.0); // facingDeg, halfAngleDeg；全向则不调用

fov.compute();
if (fov.isVisible(20, 18)) { /* ... */ }
if (fov.isExplored(20, 18)) { /* 记忆中的地形 */ }

fov.setRevealerPosition(id, 11, 12);
fov.compute();

// 3D 体素
local fov3 = map.newFovVolume(32, 32, 8);
fov3.setMode("volume");
fov3.setOpaque3(4, 4, 2, true);
local rid = fov3.addRevealer3(4, 4, 1, 10); // x,y,z,radius
fov3.compute();
local v = fov3.isVisible3(8, 4, 1);
```

自定义 2D 网格：

```squirrel
local fov = map.newFovSize(80, 80);
fov.setOpaque(3, 3, true);
```

高度场：

```squirrel
local fov = map.newFov(layer);
fov.setMode("heightmap");
fov.setElevation(10, 10, 3);
fov.setCliffBlock(1);
```

导出遮罩（约定，供渲染）：

```squirrel
// 一期：CPU 采样
local s = fov.getState(x, y); // "unknown" | "explored" | "visible"
// 二期：fillMaskRGBA(image) 或 getMaskTexture 适配器
```

## 与渲染的衔接（非本模块实现，但接口预留）

```text
玩法线程 / 主循环:
  更新 revealer → fov.compute() → VisibilityBuffer

2D 呈现:
  根据 buffer 生成 R8/RGBA 遮罩纹理（可见=1，explored=0.35，unknown=0）
  Sprite / 全屏 quad + shader 混合；可盒模糊羽化

3D 呈现:
  将 volume buffer 上传为 3D 纹理或结构化缓冲
  后处理：深度重建世界坐标 → 三线性采样可见性 → 混合雾色
  （参考公开 3D FoW 文章；不复用 Volumetric 大气雾语义）
```

明确：**一期验收不要求 GPU 遮罩**；要求 CPU buffer 与查询 API 正确。

## 错误与边界

| 情况 | 行为 |
|------|------|
| 坐标越界 | 查询返回 false / `"unknown"`；设置 opaque 忽略或 no-op |
| radius ≤ 0 | 仅原点可见 |
| 未知 algorithm / mode / metric | 回退默认并 `getAlgorithm()` 可查 |
| layer 为空 | `newFov` 失败返回 null |
| volume 下误用 2D API | 绑定层拒绝或映射到 z=0，文档明确用 `*3` 后缀方法 |

## 测试计划

- 空地半径圆：可见格数与度量一致
- 单柱 / 墙后阴影：shadowcast 三角形阴影形态稳定
- 走廊与房间：挡体后格子不可见；挡体本身可见（RSC 惯例）
- 扇形 90°：朝向外侧不可见
- 多 revealer OR 合并
- explored 在离开后保留、`clearMemory` 清空
- `blockOpaqueGid` + `syncFromLayer`
- heightmap：高崖挡低视
- volume：桥上可见、桥下同柱不同 z 不可见（最小体素夹具）
- 与 `test/map.cpp` / `map_path.cpp` 无回归

## 成功标准

1. 同一套 API 可表达 2D 瓦片视野；扩展 mode 后可表达高度场与体素 3D，而无需游戏重写 revealer 逻辑  
2. 默认 shadowcast 在室内障碍下行为符合 RogueBasin 经典约定（挡体可见、影内不可见）  
3. 动态：移动 revealer / 改 opaque 后再次 `compute()` 结果正确  
4. 不污染 `Camera3D.setFov` 与 `Volumetric` 雾语义；不把 LOS 塞进 `spatial`  
5. 文档列出公开算法来源，实现可对照测试夹具验收
