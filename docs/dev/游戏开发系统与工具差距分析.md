# 游戏开发系统与工具差距分析

日期：2026-08-17
范围：对照行业常用「独立引擎」/「运行时即编辑」引擎（Love2D、Godot、Bevy、Defold、PICO-8 等）的常见开发系统与工具，评估 EVEngine 的用户支持程度，并列出差距与补全建议。

> 结论速览：EVEngine 的**运行时系统**覆盖度已非常高（渲染 / 物理 / 音频 / 输入 / 动画 / 脚本 / ECS / UI / 场景 / 寻路 / 程序化生成等），并且热重载、调试器（DAP）、动态切片（Slicer）、MCP/AI 支持等**调试工具**远超同量级引擎。主要差距集中在「创作工具」层（可视化编辑器、资产生成与浏览、性能分析），多为有意设计（编辑器可组合构件，不内置完整 Editor App）。补全优先级建议放在低成本、高收益的**开发期控制台 / 日志 / REPL** 与 **帧统计** 上。

---

## 1. 参考基准：独立引擎常用的开发系统与工具

基于对 Love2D / Godot / Bevy / Defold 等独立引擎（以及 Wikipedia "Game engine" 词条、Godot 官方文档、Bevy 官网）的调研，独立游戏引擎通常具备下列开发系统与工具：

### 1.1 运行时系统（游戏运行时能力）

| 系统 | 说明 | 常见引擎 |
|------|------|----------|
| 渲染（2D/3D） | 精灵、图块、网格、光照、阴影、后处理 | 全部 |
| 物理 | 刚体、碰撞、关节、射线/区域查询 | 全部 |
| 音频 | 解码、播放、空间化、混音 | 全部 |
| 输入 | 键鼠 / 手柄 / 触摸 | 全部 |
| 动画 | 补间、帧动画、骨骼动画、状态机 | 全部 |
| 脚本 | 高可读脚本语言驱动玩法 | 全部 |
| 实体/场景 | ECS 或场景图、实例化、层级 | 全部 |
| AI | 寻路、行为树 / 状态机、导航网格 | 多数 |
| 网络 | 局域网 / HTTP / 同步 | 多数 |
| UI | 即时或保留模式 UI、布局、主题 | 多数 |
| 持久化 | 存档 / 读档、数据序列化 | 多数 |
| 本地化 | 多语言字符串表、字体 | 多数 |
| 程序化生成 | 噪声、地形、内容生成 | 部分 |

### 1.2 创作与编辑工具

| 工具 | 说明 | 常见引擎 |
|------|------|----------|
| 场景编辑器 | 视口、大纲、属性面板、变换操纵 | Godot / Unity |
| 地图/关卡编辑器 | 瓦片笔刷、碰撞标记 | Godot / Defold / Tiled |
| 资源浏览器 / 导入管线 | 拖放导入、缩略图、资产管理 | Godot / Unity |
| 脚本编辑器 / 语言服务 | 补全、跳转、诊断（LSP） | Godot 内建；其余外接 VS Code |
| 调试器 | 断点、单步、监视、调用栈 | Godot / Unity / 外接 |
| 控制台 / 日志 | 运行时打印、错误流、命令行执行 | Godot / Unity / Defold |
| 性能分析器 | 帧时间、CPU/GPU 耗时、内存 | Godot / Unity |
| 帧统计 / 调试叠加层 | FPS、绘制调用、实体数 | Godot / Unity |
| 物理调试绘制 | 碰撞体线框可视化 | Godot / Unity |
| 资产热重载 | 脚本 / 资源修改后即时生效 | 多数 |

### 1.3 发布与流程工具

- 一键导出多平台（Godot / Defold）
- 打包（zip / 单一可执行文件）
- 命令行自动化（批处理、CI）
- 代码生成（GDExtension 等）

## 2. EVEngine 现状盘点

### 2.1 运行时系统（已有，成熟度高）

| 系统 | EVEngine 模块 | 备注 |
|------|---------------|------|
| 2D/3D 渲染 | `graphics` + `stylize` + `daynight` + `weather` + `voxel` | Vulkan + WebGPU，PBR/IBL/CSM/GI/AO/AA/体积光/风格化均可用 |
| 物理 | `physics`（Box2D/Box3D + Cloth + Fluid） | 2D 像素 + 3D 米制；debug draw（2D） |
| 音频 | `sound` + `audio`（OpenAL） | 多解码器；Source 空间化 |
| 输入 | `keyboard` / `mouse` / `touch` / `joystick` | SDL 后端 |
| 动画 | `animation` + `ik` | Tween / 帧动画 / Spine / 骨骼 / 状态机 / Motion Matching / 程序动画 |
| 脚本 | Squirrel（simplesquirrel） | `eve_init/update/render` + 热重载回调 |
| 实体/场景 | `entity`(ECS.hpp) + `scene` + `sceneloader` | 声明式场景树 + ECS |
| AI | `map` 寻路（A\*/FlowField/FOV） | **无导航网格**（网格寻路已覆盖 2D 游戏需求） |
| 网络 | `network` | TCP/UDP/HTTP，异步事件待补 |
| UI | `ui`（ImGui 之上声明式） | 保留模式 + 主题 |
| 持久化 | `database`(SQLite) + DevTools `Snapshot` | **无正式存档系统**（快照仅调试用） |
| 本地化 | 无独立模块 | **缺** |
| 程序化生成 | `procgen` + `housegen` + `math` noise | 地牢/洞穴/迷宫/WFC/贴图/网格 recipe |
| 数据/序列化 | `data` + `database` | JSON/XML/LZ4/hash/SQLite |

### 2.2 创作与编辑工具（已有）

| 工具 | EVEngine | 备注 |
|------|----------|------|
| 场景编辑 | `editor`（Gizmo / 笔刷 / Toolbar / Inspector / Dock / History） | 可组合构件，**不内置完整编辑器**（有意设计） |
| 地图编辑 | `editor.Brush` + `TileBuffer` | 可组合，替代 Tiled 的完整 GUI 不内置 |
| 脚本编辑 | VS Code 扩展 + DAP | `tools/vscode-eve-debug/`；LSP **计划未实现** |
| 调试器 | `devtools/Debugger` + DAP | 断点/单步/监视/快照，功能完善 |
| 动态切片 | `devtools/CallGraph` + `RenderFlow` | 出错时后向切片定位问题，特色功能 |
| 控制台/日志 | `AiPanel`（MCP 会话日志） | **缺通用运行时控制台 / print 捕获** |
| 性能分析 | `devtools/CallGraph` / `RenderFlow` 追踪 | **缺帧时间 / FPS 统计面板** |
| 物理调试 | `World::drawDebug`（2D） | 3D debug draw 缺 |
| 热重载 | `filesystem` watch + `load.nut` | 脚本软重载 + 资产热更，完善 |
| MCP/AI | `devtools/McpServer` + `AiPanel` + 视觉 | 特色功能，超出多数引擎 |

### 2.3 发布与流程（已有）

- CLI：`run` / `create` / `dev-server` / `package` / `test` / `doc` / `get`
- 多平台：Win32 / Linux / macOS / Android / iOS / Web(WebGPU)
- Docker 构建、CI（GitHub Actions）

## 3. 差距清单与建议优先级

优先级：P0 = 低成本高收益（建议近期补全）；P1 = 中成本，可选；P2 = 大工程，明确不做 / 长期规划。

### P0（建议补全）

| # | 差距 | 现状 | 建议 |
|---|------|------|------|
| 1 | **运行时控制台 / 日志 / REPL** | `print` 直接到 stdout；无统一的脚本日志与运行时表达式求值界面 | 在 DevTools 增加 `ConsolePanel`：环形日志缓冲 + Squirrel print 捕获 + REPL 表达式求值 + ImGui 面板 + `eve.dev.console.*` 脚本 API。**本次已实现** |
| 2 | **帧统计 / 调试叠加层** | 无 FPS / 帧时间 / 实体数显示 | DevTools 帧统计面板（基于 `timer` / 绘制调用计数），低成本 |
| 3 | **统一日志模块（可选）** | 各模块各自 `print`/`cerr` | `eve.Log` 级别化日志（debug/info/warn/error）+ 过滤 + 文件落盘，可被控制台与 MCP 消费 |

### P1（可选）

| # | 差距 | 现状 | 建议 |
|---|------|------|------|
| 4 | 语言服务（LSP） | `devtools/Readme.md` 计划未实现 | VS Code 扩展内嵌或独立 LSP 提供补全/跳转/诊断 |
| 5 | 正式存档系统 | 仅 `Snapshot`（调试） | 基于 `data`/`database` 提供键值存档 + 版本迁移 |
| 6 | 本地化模块 | 无 | 字符串表（JSON）+ 占位符 + 字体切换 |
| 7 | 3D 物理调试绘制 | 仅 2D | `World3D::drawDebug` 复用 graphics 调试线 |
| 8 | 资产生成/浏览 GUI | 依赖外部 AI agent 管线 | 可选 DevTools 资产浏览面板 |

### P2（明确不做 / 长期）

| # | 差距 | 说明 |
|---|------|------|
| 9 | 完整 3D 场景编辑器 / 2D 地图编辑器 | 与 Love2D「运行时即编辑」理念冲突；提供 `editor` 可组合构件由用户组装（[编辑器模块设计](编辑器模块设计.md)） |
| 10 | 导航网格（NavMesh） | 2D 网格寻路已覆盖主要需求；3D 场景若需再评估 |
| 11 | 音频中间件（FMOD/Wwise） | OpenAL + Source 满足当前 2D/轻 3D 场景 |
| 12 | 动画 / 材质 / 粒子可视化编辑器 | 数据驱动配置 + 热重载已覆盖；可视化编辑属大工程 |

## 4. 本次补全内容

依据 P0 清单，本工作树（`tools/gamedev-support`）实现并落地了 **运行时控制台 / 日志 / REPL**（差距 #1）：

- `src/engine/devtools/ConsolePanel.{hpp,cpp}`：环形日志缓冲、Squirrel `print` 捕获、REPL 表达式求值、可选的 ImGui 绘制钩子。
- `DevTool` 集成：`attach` 时安装 print 捕获并暴露 `eve.dev.console.*`；`detach` 时还原。
- 脚本 API：`eve.dev.console.log/info/warn/error/debug`、`eval`、`clear`、`recent`、`formatLog`、`setVisible/isVisible/toggleVisible`。
- 测试：`test/console.cpp`。
- 文档：本文件 + [`devtools/Readme.md`](../../src/engine/devtools/Readme.md)。

其余 P0/P1 项（帧统计、日志模块、LSP、存档、本地化等）可作为后续独立工作树推进。
