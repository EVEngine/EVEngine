# 城市布局协同生成模块设计 — `procgen/urban`

日期：2026-08-23
状态：已实现（`src/modules/procgen/urban/`）

## 来源论文

本模块是 Eurographics 2024 论文
*Hierarchical Co-generation of Parcels and Streets in Urban Modeling*
（Zebin Chen、Peng Song、F. Peter Ortner，Computer Graphics Forum 43(2)，
DOI [10.1111/cgf.15053](https://doi.org/10.1111/cgf.15053)）的引擎内算法移植。
论文基于 Rhino/Grasshopper + Houdini 工作流；本项目把它落为 procgen 模块内
的纯 CPU C++20 算法，输出与引擎既有管线一致（`Grid2D` 语义地图与 `MeshBuild`
网格）。

## 目标

- 从任意用户多边形地块（land polygon）生成**地块（parcels）与街道（streets）**
  协同的城区布局，满足论文第 3 节的六条基本设计需求：
  1. 地块形状尽量规则；
  2. 每个地块都有街道入口（可达）；
  3. 街道网络几何连通（无孤立街道）；
  4. 街道总长度尽量小；
  5. 街道交叉口尽量少；
  6. 尽端路可选（由用户控制）。
- 提供两种引擎可直接消费的输出：
  - `urban.parcels` → `Grid2D`（路 = `Semantic::Road`，地块 = `Semantic::Floor`，
    `detail` 存地块 id，并附带地块锚点对象）；
  - `mesh.urban` → `MeshBuild`（平面或挤压地块块 + 街道带）。

## 论文算法 → 代码映射

| 论文章节 | 论文算法 | 实现 |
|----------|----------|------|
| §3 | 地块形状不规则度 `I`（式 1：内角方差 + 边长方差，γ1=0.75、γ2=0.25） | `UrbanGeometry::shapeIrregularity` + `approximatePolygon`（夹角 > 135° 视为共线合并） |
| §3 | 表示：地块网格、地块角图、地块图、街道网络图、街道图 | `UrbanTypes` 的 `UrbanLayout`（corners / parcels / edges / streets）+ `decomposeStreets` |
| §4.1 | ~20 条 streamline 候选（交叉场 + 超流线追踪，YWVW13） | `UrbanCrossField::generateSplitCandidates`：网格交叉场（边界切向约束 + Jacobi 平滑），边界种子双轴追踪；不足时回退均匀弦线 |
| §4.1 | 分割线质量分 `Q = λ1·Qsize + λ2·Qregu + λ3·Qacce`（式 2，λ=0.3/0.5/0.2，τ=0.5） | `UrbanGenerator::splitOneParcel`（支持 λ4·Qorient 朝向偏好，论文 §6/图 16） |
| §4.1 | 短边消除（长度 < 0.2·min(l̄1,l̄2) 的共享边合并顶点） | `UrbanGenerator::removeShortEdges`（先模拟合并，任何受影响地块退化则跳过） |
| §4.2 | 不可达地块分组；I 形/L 形街道入口；Dijkstra 加权最短路接入；尽端路可选消除 | `UrbanGenerator::generateStreets`（分组 + 递归覆盖式 I/L 入口 DFS + `connectAccessToNetwork` 转角感知 Dijkstra + `reconnectStreetEnds` 按 streetPattern） |
| §5 | 全局几何优化（式 3：Eregu/Eside/Estre/Ejunc/Eclose + 边界约束式 9/10） | `optimizeLayoutGeometry`：地块规则角、边平滑（Laplacian）、街道平滑、交叉口 90°、贴近初始布局；土地边界顶点固定/沿线滑动；内置“优化后更差则回滚”保护 |
| §6 | 街道路网形态：loop / cul-de-sac / tree；地块朝向 | `streetPattern` 参数（default/loop/culdesac/tree）与 `orientation` 参数 |

## 模块结构

```text
src/modules/procgen/urban/
  UrbanTypes.h        Vec2、Polygon/Polyline、UrbanLayout、UrbanOptions、BoundarySample
  UrbanGeometry.h/.cpp  面积/质心/点在多边形内/求交、多边形按折线二分、
                        近似多边形、形状不规则度、耳切三角化
  UrbanCrossField.h/.cpp 交叉场构建（边界对齐 + 平滑）、超流线追踪、
                        直线弦回退、候选去重
  UrbanGenerator.h/.cpp 层级协同生成主流程 + 街道生成 + 几何优化
  UrbanOutput.h/.cpp  Params 解析、Grid2D 栅格化、MeshBuild 构建、注册函数
```

源码自动纳入构建（`cmake/scan_source.cmake` glob）；无需改动
`cmake/module_manifest.cmake`。算法仅依赖标准库 + procgen 内部类型，不产生
新的模块依赖（`scripts/module_depgraph.py --check` 通过）。

## 与论文实现的差异（工程取舍）

- **交叉场离散化**：论文在 Rhino 中对地块重新网格化后求解交叉场；本实现用
  规则背景网格 + 最近边界切向初值 + 2θ 缠绕角 Jacobi 平滑，效果等价且实现简单。
- **候选数量**：每地块 ~20 条；流线不足时回退弦线，保证任何简单地块都能分割。
- **优化求解器**：论文用 Kangaroo/ShapeOp 投影求解器；本实现用逐顶点松弛
  （解析梯度 + 角度有限差分），并带“变差即回滚”保护，保证不劣于初始布局。
- **街道密度**：默认路径保持“每个地块可达、网络连通”，网格状布局下街道数量
  比论文示例偏多；这是可达性优先的代价，后续可用更高 `dijkstraJunctionWeight`
  或更大 access 路径上限进一步压低。
