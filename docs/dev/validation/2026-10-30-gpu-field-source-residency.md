# GPU 场探针：源和目标共同候选发布

这是独立探针的设备常驻状态验证，尚未进入 EVEngine 的模拟 owner 或渲染帧。

`reduce.comp` 现在读取已发布源缓冲，按帧步长将相邻源反向移动，写入
候选源缓冲，并用候选源构建八簇质量/一阶矩。求值 kernel 同时写入候选
目标位置与速度。两套 descriptor set 在源、位置、速度三种缓冲之间
同步交换；GPU fence 后只回读一个准入字。任何目标误差界拒绝时，
源和目标候选均丢弃，不推进已发布状态。

Windows MSVC Release、AMD Radeon AI PRO R9700：百万源与百万目标，
120 个计时帧，墙钟 P50 0.3001 ms、P95 0.4089 ms、最大 0.6802 ms。
最后的源位置与 CPU 双相参考最大差 0；矩量最大分量差 5.12322e-9，
16 个采样目标的直接逐源加速度最大误差 1.10455e-8，解析界
8.1489e-5，轨迹最大位置差 2.08959e-6。
此墙钟包括命令录制、提交、fence 等待和准入字回读，不包括初始化、
首次上传、CPU 参考、渲染或一般层次构建。

近场和混合目标在拒绝时均报告 `published_state_unchanged=1`；
混合目标仍有远场候选写入。启用 Khronos Vulkan validation layer 的
十万源/目标、四帧运行成功，无验证错误。

这个路径仅处理固定八个紧凑簇、双状态源运动和牛顿点质量核。
`maxStorageBufferRange`、八簇半径、误差界和近场拒绝都限制其适用范围。
完整目标仍要求引擎可选 GPU 后端、自适应层次与近场、任意动态分布、
设备丢失恢复、增量编辑、GPU 可见实例与 1080p 整帧验收。

最终版本 `make check` 通过：533 项脚本测试、5 项跳过；
`build/gpu-field-source-residency-check.log` 记录完整输出。
