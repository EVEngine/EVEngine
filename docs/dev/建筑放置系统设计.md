# 建筑放置模块设计 — `building`

日期：2026-08-12  
状态：已实现（首版，`src/modules/building/`）  
存放：`docs/dev/`

## 目标

为**策略 / RTS / 经营模拟（ETS）**类游戏提供一套高度灵活、可扩展的建筑放置框架，覆盖：

1. **建筑定义（BuildingDefinition）** — 数据驱动的模板：占地、标签、吸附与旋转、校验策略名、自定义字段。
2. **放置世界（PlacementWorld）** — 格子占用图 + 已放置实例列表；可选地形语义层（陆地/水域/道路等）。
3. **鬼影预览（Ghost）** — 跟随指针的候选姿态；校验结果与失败原因可查询，供 UI 上色。
4. **放置操作（PlacementSystem）** — 吸附 / 旋转 / 校验 / 放置 / 拆除 / 移动；可插拔校验与变更钩子。

与 `inventory` / `rpg` 同一设计语言：纯数据结构 + `*System` 静态行为 + `Module` facade 做脚本绑定；
参考 [模块设计.md](./模块设计.md)。

## 离散楼层地址

逻辑占用地址为 `(domain, level, channel, coordinate)`：cell 使用格坐标，edge 使用规范化边
地址。`level` 是持久实例与编辑快照的一部分；`elevation` 仅表示该楼层内沿平面法向的局部
偏移，不能代替楼层。默认兼容 API 读取 `PlacementWorld::activeLevel`，显式跨层查询不改变
活动层。邻接与 edge topology 只读取实例所在层，避免上下楼层意外连通。BuildingFX 的最终
法向坐标为 `level * floorHeight + elevation`。

楼层过滤属于 BuildingFX 的派生表现状态，不回写 PlacementWorld，也不删除逻辑实例。
每个已 attach 的世界独立保存 `all`、`active` 或 `active_and_below` 模式；`sync` 根据实例
`level` 和世界 `activeLevel` 设置 Renderable 的 visible 标记。因此切层不会改变实例 id、
占用、拓扑、编辑 revision 或撤销记录。

结构模板使用 `structuralRole` 标注领域语义，使用 `supportMode=cell_below` 声明逐占地格的
下层支撑约束，并可通过 `supportTag` 限定支撑实例。该约束进入统一放置 preflight，因此
普通放置、ghost、区域事务、移动、替换和编辑恢复共享同一个 `support_missing` 失败语义。
每个实例保存由权威楼层/占用地址派生的 `supportInstanceIds`。普通拆除和移动支撑体会以
`support_in_use` 拒绝；`removeBuildingCascadeResult` 先验证完整依赖图，再按 dependent-first
顺序一次提交，提交完成后才发布变更事件。替换只有在新 footprint 与标签继续满足全部依赖
时才允许。`rebuildStructuralLinksResult` 在独立候选世界中重新验证和生成所有链接，供存档
恢复与定义热重载调用；任何未知定义或缺失支撑都会保留原世界不变。链接循环以
`support_cycle` 拒绝，不能由渲染层推断或修复。

## 为什么不用固定枚举

沿用仓库类绑定原则：

- 建筑 id、标签、分类、吸附模式、旋转模式、校验规则名、地形语义全部是**字符串**（地形格用 `int` 语义 id，映射表字符串可选）。
- 新增一种建筑或一种放置规则，不需要改引擎头文件。
- 定义可放进 JSON（`BuildingRegistry::loadFromJson`），也可由 C++ 插件注册。

## 可插拔扩展点

| 系统 | 扩展点 | 谁来注册 | 覆盖场景 |
|------|--------|----------|----------|
| 校验 | `PlacementSystem::registerValidateRule(name, fn)` | C++ | 内置 default/boundsOnly/overlapOk 之外：资源够不够、科技树、势力领地、道路邻接等 |
| 吸附 | `PlacementSystem::registerSnapRule(name, fn)` | C++ | 内置 grid/cell/free 之外：贴路边、贴墙、六角格吸附 |
| 变更 | `PlacementSystem::registerChangeHook(name, fn)` | C++ | UI 刷新、经济扣款、成就、寻路动态障碍更新 |
| 数据 | `BuildingDefinition::extra` / `PlacedBuilding::props` / `PlacementWorld::extra` | C++ 或 JSON | 任意自定义字段 |

脚本通过策略名字符串选用已注册规则；自定义回调只能在 C++ 注册（与 inventory 相同约束）。

## 数据模型

### BuildingDefinition

```text
BuildingDefinition {
  id, displayName, category,
  footprintW, footprintH,          // 格子占地（未旋转）
  footprintMask[],                 // 可选 0/1 掩码，长度=W*H；空=实心矩形
  snapMode,                        // "grid" | "cell" | "free" | 自定义名
  rotationMode,                    // "none" | "cardinal" | "free"
  validateRule,                    // "default" | "boundsOnly" | "overlapOk" | 自定义名
  tags[],
  requireTerrain[],                // 占地格地形语义 id 必须命中其一（空=不限）
  forbidTerrain[],                 // 命中则拒绝
  requireAdjacentTag,              // 非空：至少一邻格已有带该 tag 的建筑
  requireAdjacentTerrain,          // >=0：至少一邻格地形语义等于该值；-1=不限
  cost{},                          // string→int 资源代价提示（引擎不扣款，游戏侧处理）
  extra{string→string}
}
```

### PlacedBuilding（运行时实例）

```text
PlacedBuilding {
  instanceId, buildingId,
  originCellX, originCellY,        // 格子原点（左下或左上由世界约定：本模块用左下=最小 x/y）
  worldX, worldY,                  // 世界坐标（吸附后）
  rotationDeg,                     // 度；cardinal 取 0/90/180/270
  props{}, tags[]
}
```

### PlacementWorld

```text
PlacementWorld {
  id, width, height,               // 格子尺寸
  cellSize, originX, originY,      // 世界坐标 = origin + cell * cellSize
  occupancy[width*height] → instanceId (0=空),
  terrain[width*height] → int 语义,
  buildings[instanceId → PlacedBuilding],
  validateRule (世界默认，可被定义覆盖),
  snapMode (世界默认),
  extra{}
}
```

### Ghost

```text
Ghost {
  buildingId, cellX, cellY, worldX, worldY, rotationDeg,
  valid, reason                    // 最近一次 validate 结果
}
```

## 操作语义

| 操作 | 行为 |
|------|------|
| `snap` | 按 snapMode 把世界坐标 → (cell / world) |
| `rotate` | 按 rotationMode 步进或设置角度；占地随 cardinal 交换 W/H |
| `validate` / `canPlace` | 边界 → 占用 → 地形 → 邻接 → 自定义规则；写出 reason |
| `place` / `placeAt` | validate 通过后分配 instanceId、写 occupancy、推事件 |
| `remove` | 清 occupancy、删实例、推事件 |
| `move` | 先校验新位，再清旧占、写新占 |
| `ghost.set*` / `ghost.validate` | UI 预览，不改世界 |

失败原因字符串示例：`unknown_building` / `out_of_bounds` / `occupied` /
`terrain_mismatch` / `terrain_forbidden` / `adjacency_tag` / `adjacency_terrain` /
`validate_rejected`。

## 脚本绑定（`eve.Building`）

```squirrel
building <- eve.Building()
building.registerBuildingsFromJson(json)
world <- building.newWorld(64, 64, 32.0)   // w,h,cellSize
ghost <- building.newGhost()
ghost.setBuildingId("house.wood")
ghost.setFromWorld(world, mouseX, mouseY)
if (ghost.validate(world)) {
    id <- world.placeGhost(ghost)
}
```

`PlacementWorld` / `Ghost` 暴露薄封装成员方法，风格与 `Bag` / `RPGActor` 一致。

> **坑：** 暴露给 Squirrel 的浮点一律用 `float`，不要直接绑 `double`。

## 与其它模块关系

- **不硬依赖** `map` / `spatial` / `physics` / `inventory`：格子与占用自管；游戏可将 `instanceId` 同步进 `spatial` 做邻近查询，或把占用同步到寻路动态障碍。
- **可消费** `math.snap` 概念（本模块内建格子吸附）。
- **成本 / 科技 / 势力**：通过 `cost` 字段 + `registerValidateRule` / `registerChangeHook` 由玩法层实现。

## 非目标（v1）

- 不内置具体 UI（建筑栏、绿/红鬼影绘制）——由 `ui` / `graphics` 或游戏脚本完成。
- 不内置经济扣款、人口、生产链。
- 不做六角/等距格子拓扑（可后续用自定义 snap + validate 扩展）。
- 不做存档统一格式（可用 props/extra + 游戏侧 JSON）。
- 不做脚本侧动态注册 validate/snap 回调。

## 改进（2026-08-18）：统一 Grid 抽象 + 3D 放置 + Tilemap 打通

对照 Unity Grid 组件 + Tilemap + 社区标准 Grid Placement System 架构补齐：

### Grid 抽象层（`grid` 模块，纯数学零依赖）

- `GridConfig`：layout（rectangle / hexagon / isometric / staggered / isometric-z-as-y）、
  cellSize、cellGap、origin、stagger 参数、平面轴（XY / XZ）。
- `GridProjection`：`cellToWorld` / `worldToCell` / `cellToDepthY` /
  `foreachRotatedFootprint`（hex 用立方坐标 60° 旋转，cardinal 沿用 90° 象限交换）。
- `map::TileProjection` 改为委托 grid 的薄封装，map 公开 API 不变。

### `PlacementWorld` 扩展

- 可选 `GridConfig`（默认正交 2D，行为与旧版完全一致）；`setGridLayout` /
  `setGridPlane` / `setCellGap` / `setHexSideLength` / `setStagger` /
  `setGridFromLayer(layer)`。
- `bindTileLayer(layer)`：复用 tilemap 投影；`setTerrainGid(gid, semantic)` /
  `setTerrainGidMapJson` 让地形语义从 GID 懒解析，手动 `setTerrain` 覆盖优先。
- 多通道占用：`BuildingDefinition.channel` 指定通道（如 floor / furniture），
  同格跨通道叠放，占用校验按通道；邻接查询跨通道（`getAnyOccupant`）。
- 3D：`setGridPlane("xz")` 后网格第二轴映射世界 Z、worldY 为高度；
  `cellToWorld3DX/Y/Z` / `worldToCell3DX/Y` / `placeAtWorld3D` /
  `getBuildingWorldZ` / `getBuildingElevation`。

### 放置表面接口（面向接口编程）

- `PlacementSystem::registerSurface(name, fn(world, x, y, hit&))`：兼容入口；物理射线与
  任意 Mesh 由游戏或高层适配模块提供。building 内置 `"plane"`（Y=常数平面，
  `setPlaneSurfaceHeight`）和不可变规则高度场 `HeightfieldSurface`。
- `Ghost::setFromSurface(world, surface, x, y)` / `setFromWorld3D(world, x, y, z)`。

#### 结构化表面契约（Phase 1）

- Canonical C++ 扩展点为 `registerSurfaceProvider(name, fn)`，返回
  `Result<PlacementHit>`；旧 `registerSurface` 仅为兼容适配。
- `PlacementHit` 携带 position、normal、tangent/bitangent、surface id/revision、
  primitive id 和 tags；系统在发布结果前校验有限坐标、归一化法线并重建正交框架。
- Ghost 和已放置实例保留 surface id/revision/normal/tangent 的放置时快照。
- Provider 在调用线程同步执行，不得保存 `PlacementWorld` 借用，也不得回调脚本。
- 完整 footprint patch 采样已由下节实现；仍未提供 provider generation handle 或地形
  变形后的自动重投影。

#### 内置 HeightfieldSurface（Phase 3）

- `HeightfieldSurface::create` 接管有限、行主序且至少 2x2 的样本；配置显式携带平面原点、
  两轴间距、高度 scale/offset、surface id/revision 和 tags。
- `registerHeightfieldSurface` 以 `shared_ptr<const HeightfieldSurface>` 捕获不可变快照；
  注册表负责持有至替换或 `unregisterSurface`，不保存 PlacementWorld 引用。
- 有限范围内双线性插值高度；顶点梯度由中心差分（边界单边差分）生成，再双线性插值，
  从而保持共享片边界 frame 连续。XZ 输出 `normal=(-dh/dx,1,-dh/dy)`，XY 输出
  `normal=(-dh/dx,-dh/dy,1)`，再经统一 frame 规范化。边界包含最后一行/列，范围外
  返回 NotFound。
- 创建失败和注册失败不改变 registry；重建地形必须发布新不可变对象和递增 revision，
  已放置实例与曲线组继续持有提交时的身份/frame 快照。

#### SurfacePatch（Phase 2）

- `sampleSurfacePatch` 先执行建筑 snap，再按旋转后的实际 `footprintMask` 逐格采样；
  `free` snap 保留精确输入锚点；OBB/凸多边形 free footprint 采样中心和全部旋转顶点，
  网格 snap 使用吸附后的锚点。
- 一个 patch 内的样本必须具有相同 `surfaceId` 与 `surfaceRevision`。缺失命中直接传播
  provider 失败，跨 identity/revision 返回 Conflict，不会产生部分可观察状态。
- Patch 计算相对网格平面 up 轴的最大坡度和完整 footprint 高度范围。定义字段
  `maxSurfaceSlopeDegrees`、`maxSurfaceHeightDelta` 由默认校验规则执行；负高度差限制表示禁用。

## Edge 放置域与连接拓扑

- `placementKind=edge` 不复用 cell occupancy；水平边尺寸为 `width*(height+1)`，垂直边
  尺寸为 `(width+1)*height`，并继续按 channel 隔离。
- 外部 north/east/south/west 地址在进入领域层时规范化为 `EdgeAddress{x,y,axis}`，同一
  物理边只有一个权威占用槽。
- `PlacedBuilding` 持久化 placement kind 和规范化边地址；删除、清空与 `restoreExact`
  同时维护边占用，任一失败不会部分写入。
- 连接只发生在相同 channel 且相同 `connectionGroup` 的边实例之间；组为空时回退到
  building id。六位 mask 分别描述同轴起点/终点以及两个端点的四个垂直分支，视觉层
  可据此选择直线、转角、T 形和交叉变体。
- 单段边、轴对齐批量线段、多段正交路径和 Bezier 曲线离散结果共享同一占用与拓扑查询；
  贴合任意 3D 表面的连续曲线网格仍留给后续阶段，不能
  通过复制 cell occupancy 建立第二套事实来源。

### 连续边事务与视觉派生

- `previewEdgePath` 是运行时与编辑器共同使用的路径展开和预检权威入口：它接收两个或更多
  逻辑网格顶点，要求每段非空且轴对齐，拒绝路径内重复物理边，并返回有序边列表而不修改世界。
- `placeEdgePath` 消费上述预检结果后一次提交全部边；`placeEdgeLine` 仅把两个端点委托给
  该路径实现。二者先构造全部规范化
  `EdgeAddress` 并完成边界/占用预检，然后一次写入实例和占用，最后统一发布事件。
  失败路径不会改变实例表、占用或事件队列。
- 每个单位边保留独立 instance id，批量结果以 `Result<EdgeLinePlacement>` 或
  `Result<EdgePathPlacement>` 所有权返回；
  脚本会话保存最近一次成功提交的 id 列表，并以命名状态枚举报告结果。
- `building_editing::BuildingTarget::makeEdgePath` 使用同一 preview 生成一个 area-set 事务，
  因此整条路径只推进一次 revision，并可作为单一手势整体撤销/重做。
- `sampleEdgeCubicBezier` 要求四个有限控制点和 2–4096 固定细分；使用 double 中间计算、
  `lround` 顶点量化及确定性 Manhattan 步进，最多生成 65536 个单位边。输出继续交给
  `previewEdgePath`，因此曲线没有第二套占用或提交逻辑。确定性契约是在同一运行时构建中，
  相同控制点顺序和细分数生成相同顶点序列；跨后端持久化、重放或联网同步应传输已经展开的
  精确边快照，不能依赖浮点曲线重新采样获得逐位一致结果。
- `placeEdgeCubicBezier`、PlacementSession 控制点会话和
  `BuildingPlacementTarget::makeEdgeCubicBezier` 分别覆盖运行时、脚本及编辑事务；编辑事务保存
  展开后的精确边，因此撤销/重做不依赖未来重新采样。
- `BuildingFx::buildEdgeCurveMesh` 是无 GPU 副作用的连续视觉几何阶段。它在 rectangle、
  isometric 与 isometric-z-as-y 的仿射网格基上解析采样 Bezier，为左/右/顶/底四面和首尾端盖
  生成分面法线、弧长 UV 与三角索引，同时支持 XY/XZ 法向挤出。hex/staggered 明确返回
  Unsupported，直到存在逐点非仿射投影契约。当前 `sync` 仍消费单位边实例；曲线组的权威
  持久身份、GPU Mesh 缓存所有权及部分删除降级规则尚待下一阶段建立。
- 拓扑类型不是持久化事实。`isolated/end/straight/corner/tee/cross` 从当前权威边占用和
  connection group 即时派生，避免增删邻居时维护易失真的第二份 variant 状态。
- BuildingFX 在每次同步时按 `variant.<type>.mask.<mask>.<field>`、
  `variant.<type>.<field>`、基础字段的顺序解析，因此邻接变化会自动刷新模型/贴图、尺寸、
  颜色、附加旋转和镜像。3D mesh 通过宿主注入的同步 `MeshResolver` 获取 provider-owned
  借用；缺少配置、resolver 或资源时回退 cube，并分别暴露 `primitive_default`、
  `resolver_unavailable`、`resource_unresolved`，不静默伪装成功。
- end/corner 在没有显式 `mirrorX/mirrorZ` 时根据六位 mask 使用确定性镜像；显式元数据可覆盖。
  resolver 不在锁内调用、不得重入 sync，返回 mesh 必须覆盖所有引用它的 visual 生命周期。

## Corner 放置域与竖向节点

- `placementKind=corner` 使用 `(level, channel, vertexX, vertexY)` 作为独立权威地址，合法
  顶点范围为 `[0,width] × [0,height]`。它不占用相邻 cell 或 edge，适合柱、转角节点、
  管线接头和模块连接件。
- level 0 与其它楼层分别拥有 corner channel 表；clone/swap、清除、替换和精确恢复均复制
  或维护这份权威占用，不从视觉对象反推逻辑状态。
- `supportMode=corner_below` 要求同一顶点的下一层存在可选 `supportTag` 匹配的 corner
  实例。链接进入统一结构依赖图，因此普通拆除保护、保支撑替换、原子级联和热重载重建
  与 `cell_below` 使用相同事务语义。
- C++ 放置入口为 `placeCornerResult`，返回 owning `PlacedBuilding`；脚本 `placeCorner`
  是仅返回 instance id 的兼容投影。当前切片尚未接入 Ghost/PlacementSession 的角点指针
  工作流以及 `building_editing` 的 corner snapshot codec，这两项必须在宣布完整 corner
  编辑链路前完成。

### 原子移动与替换

- `moveBuildingResult`、`moveEdgeResult` 和 `replaceBuildingResult` 是规范 C++ API，返回
  `Result<PlacementEditReceipt>`；receipt 持有提交前后的完整实例值，供编辑器建立撤销命令。
  旧 `moveBuilding -> bool` 只作为兼容投影，不承载新的错误协议。
- prepare 阶段只查询注册表、边界、地形、邻接和权威占用，并以当前 instance id 排除自身；
  失败不会清除旧占用、修改实例或发布事件。全部验证通过后，commit 才清旧占用、写入新
  实例状态和新占用，随后同步派发单个 `move` 或 `replace` 事件。
- replace 保持 instance id、props、garrison、garrison revision 及表面附件，只替换定义身份、
  placement metadata、channel 和定义 tags。新旧定义必须同为 cell 或同为 edge，禁止在一次
  replace 中隐式改变坐标域。
- PlacementWorld 是实例与占用的唯一权威 owner；receipt 是 owning snapshot，BuildingFX 是
  可重建投影。API 为主线程/调用线程同步操作，未知 change hook 只在提交完成后调用，允许
  hook 观察完整新状态。

### 区域放置与热图

- `previewRectangle/previewBrush` 生成 owning `AreaPreview`，按稳定行主序记录每个锚点的
  accepted/reason。预检不修改 world；候选 footprint 还通过局部 reservation 集互检，避免
  同一批次内多个实例覆盖同一权威占用格。
- `placeRectangle/placeBrush` 在同一调用中重新建立完整预检证明，只接受 rejectedCount 为零
  的计划；commit 完整写入全部实例与占用后才发布事件。`AreaPlacement` 返回预检快照和所有
  新 instance id，不暴露可伪造的 prepared transaction。
- PlacementSession 保存最近的 AreaPreview 和提交 id；BuildingFX 只复制该投影，2D 使用立即
  模式色块，3D 使用可销毁的低矮派生实体。detach、clear 或新 preview 会销毁旧 3D 投影，
  不参与持久化，也不成为合法性第二真源。

### 编辑器撤销与重做

- `building_editing::BuildingPlacementTarget::makeReplace` 把新旧完整实例快照编码为同一
  `building.instance.set.v2` 的正向/反向 DomainOperation；LocalWorldAuthority 因而可用正式
  commit/compensate 流程执行替换、撤销和重新提交，而不是由 Building 自建历史栈。
- PlacementWorld 提供完整 owning clone 和 noexcept state swap。补偿先在关闭领域事件发布的
  detached world 上应用全部 inverse，成功后一次交换到原 world；候选失败不会污染权威世界，
  预演也不会向全局 Building change hook/event queue 泄漏事件。
- `BuildingInstanceSnapshot` 当前 schema v6，完整编码 placement kind、规范化 EdgeAddress、
  surface attachment frame 与 free-domain 圆形/OBB/凸多边形 footprint；操作写出
  `building.instance.set/delete.v2`，缺省字段保持旧 cell 记录兼容。替换、撤销和重做均保持
  属性、驻军与表面采样状态。
- set 操作在任何修改前针对最终定义、最终域地址和最终姿态完成一次预检；禁止 cell/edge 域
  转换。通过预检后 replace 与 move 使用同一证明，因此构造冲突 payload 也不会留下半替换实例。
- `makeRectangle` / `makeBrush` 把一次手势编码成单个 `building.area.set.v1`，inverse 是拥有全部
  精确实例快照的 `building.area.delete.v1`。执行时先在关闭事件发布的 detached world 应用完整
  batch，成功后只交换一次状态并增加一次 target revision；任一中途冲突会丢弃整个候选，不泄漏
  建筑、占用、dirty revision 或 Building 事件。补偿同样通过 staging 一次删除整个手势。
- Ghost 旋转后会在下一次校验时用原 provider/input 原子重采样，避免沿用旧方向的 patch。
- `buildingfx` 对表面实例使用命中的精确位置，以 tangent/normal/bitangent 右手框架构造
  3D 姿态；建筑 Ghost 与占地光标共享该变换，光标沿表面法线做微小偏移。
- 尚未实现 provider 主动 revision 通知和已放置实例自动重投影；实例继续保存放置时快照。

### 旋转与视觉元数据

- `rotationMode` 新增 `"hex"`（60° 步进）；`"cardinal"` 语义不变。
- `BuildingDefinition` 新增 `channel`、`renderMode`（"2d"/"3d"）、`visual2d`、
  `visual3d` 元数据（贴图/颜色/锚点/高度等），building 模块保持纯逻辑不渲染。
- 新增 `buildingfx` 渲染桥（`eve.BuildingFx`）：按定义生成 / 同步 / 销毁
  Renderable2D / Renderable3D，提供鬼影 + 占地光标（绿/红）+ 2D/3D 网格可视化。

### 放置会话

- `PlacementSession`：start/stop、place/remove 模式、旋转步进、指针更新（2D/3D/表面）、
  execute 放置或拆除；纯逻辑，输入由游戏脚本喂入。
