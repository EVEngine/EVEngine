# 发布流程

`main` 是最新正式版（GitHub 默认分支，克隆即可编译）。日常开发在 `dev`。一次发布用隔离分支 `vMAJOR.MINOR.PATCH`。设计见 [release-branch-model spec](superpowers/specs/2026-08-19-release-branch-model-design.md)。

## 一次性仓库设置

由维护者在 GitHub 上执行，脚本不会改默认分支或保护规则：

```sh
git fetch origin
git branch dev origin/main && git push -u origin dev
```

默认分支保持 `main`。

### 保护 `main`（建议）

Rulesets → New ruleset，目标 `main`：

1. **Require a pull request before merging**（不必要求 review，除非你想多点一次 Approve）。
2. **Require status checks to pass**：检查名填 `main-gate`。
3. **Block force pushes** / **Restrict deletions**（现有 NoForcePushMain 可保留）。
4. **不要**加 Bypass（不用 GitHub App，也不用管理员 PAT）。

`main-gate` 只放行两类 PR：文档白名单，或 `promote/vX.X.X`（发布脚本开的正式版 PR）。从 `dev` 把引擎代码合进 `main` 会被挡住。

`dev` 可以要求走 PR；不要给它开「必须 status check 才能合」，否则 `GITHUB_TOKEN` 开出的 rebase PR 可能一直转圈。`sync-docs` 在无冲突时仍会直接推 `dev`。

## 发一次正式版

1. 保证要发布的提交已在 `dev`。
2. 在 GitHub 上对当时的 `dev` HEAD 创建一个 **Pre-release**，tag 形如 `v0.1.0`（必须是 `vMAJOR.MINOR.PATCH`）。此时树上仍是 `0.1.0-dev`。
3. `Release` workflow 会：
   - `scripts/release.py start`：建 `v0.1.0`、去掉 `-dev`、把 tag 挪到正式版 commit；
   - 跑严测（现有 Debug CI + 桌面 Release 构建 / `make test/<plat>` + 移动端 Release 构建）；
   - 打五平台 SDK 并挂到该 Release；
   - `scripts/release.py finish`：升正式版；在 `v0.1.0` 上写回 `0.1.0-dev`；**开两个 PR，不直推 `main` / `dev`**：
     - `promote/v0.1.0` → `main`（正式版 commit，不含 `-dev`）
     - `rebase/v0.1.0` → `dev`（rebase 成功或冲突说明）
4. 人点 Merge：先合 `promote/v0.1.0` → `main`，再合 `rebase/v0.1.0` → `dev`。

rebase 冲突时 PR 正文有本地续做命令。把修好的结果推到 `rebase/v0.1.0`，不要 force-push `dev`。

下一正式号以**新的** Pre-release tag 为准（允许比树上数字高，禁止降级）。`finish` 回写的永远是刚发布的同一组数字加 `-dev`。

## 失败与重跑

| 阶段 | 留下什么 | 怎么继续 |
|---|---|---|
| `start` | 可能已有 `vX.X.X` 或已挪 tag | 对同一 tag 重跑 `Release`（`start` 幂等） |
| 严测 / SDK | 正式版 commit 与 tag 在，Release 仍为 pre | 修复后对同一 tag `workflow_dispatch` 重跑 `Release` |
| `finish` | zip 可能已挂上；可能已开 promote / rebase PR | 同一 tag 重跑；已正式 / 已开的 PR 幂等（复用） |
| rebase 冲突 | 不改写 `dev` | 合入 `rebase/vX.X.X` PR |

## 只改 main 上的展示文档

对 `main` 开 PR，且只改：

- `README.md` / `Readme.md` / `Readme.en.md`
- `docs/**`
- `Doxyfile`

`main-gate` 会放行。合并后 `Sync docs` workflow 会把这些提交 cherry-pick 到 `dev`。混入白名单外文件会失败，应改走 `dev`。cherry-pick 冲突会开 PR，不强制改写 `dev`。

## 本地脚本

需要 [GitHub CLI](https://cli.github.com/)（`gh`）。不在 PATH 会报错退出。

```sh
python scripts/release.py --dry-run start --tag v0.1.0
python scripts/release.py start --tag v0.1.0
python scripts/release.py finish --tag v0.1.0
python scripts/release.py sync-docs
python scripts/release.py check-main-pr
```

单测（不访问网络）：

```sh
python -m unittest discover -s scripts/tests -p "test_*.py" -v
```
