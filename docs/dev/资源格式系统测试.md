## 统一执行入口

仅盘点，报告明确标记 `not-run`：

```sh
python3 scripts/resource_format_suite.py --report /tmp/resource-format-report.json
```

按 Readme.en.md / Makefile 准备并构建本工作树后，运行实际的逐用例 CTest：

```sh
make debug JOBS=4
python3 scripts/resource_format_suite.py --build-dir build/linux-debug --report /tmp/resource-format-report.json
```

可重复指定 `--family image --family model` 缩小范围。音频和图形用例需要按 AGENTS.md 准备显示、Vulkan 和音频环境。视觉正确性必须另用引擎 MCP 截图验证。

执行入口先查询 CTest 注册；任何选定用例缺失都失败，不把裁剪构建、未构建、空测试集当作通过。选择范围覆盖 7 类；数量随源码变化。报告保存测试名称、来源和运行输出。`passed` 只表示所选现有用例通过，不能证明所有格式完整。

## 完成格式认证的验收条件

每种格式分别记录导入、原格式导出、规范化转换和只读能力。每项能力必须绑定具体样本和断言，不依据扩展名或第三方库宣传认定支持。

1. 独立工具生成的固定样本：来源、许可、生成版本、哈希。
2. 正常导入：内容语义断言；不能只检查非空指针。
3. 导出再导入：无损格式精确比较，有损格式明确误差预算；额外使用独立解析器避免同一实现互相掩盖错误。
4. 异常：截断、损坏、超限、缺失依赖、路径穿越、未知版本；失败后旧资源保持可用。
5. 生命周期：缓存复用、重载、卸载、依赖失效；运行时消费者确实读取新版本。
6. 后端与平台：相同内容断言分别运行；渲染另留 framebuffer 证据。

`scripts/resource_format_contracts.json` 将资源入口的图片、音频、模型扩展名绑定到具体用例。缺少用例明确记为 `coverage-missing`，未执行记为 `not-run`；其他资源族仍需继续建立逐格式契约。统一入口不替代上述工作。

## 已实现的第一批契约

固定样本在 `test/fixtures/resource_formats/`，由仓库脚本使用 Pillow、FFmpeg 和手写格式结构生成，记录许可、版本和 SHA-256。C++ 测试直接读固定样本，不依赖生成工具。

- 图片：PNG、JPEG/JPG、BMP、TGA、GIF、HDR、EXR、WebP 的尺寸和像素；GIF/WebP 动画首帧；WebP 有损误差；截断输入拒绝。当前 ImageData 只表示静态像素，动画首帧不等于动画播放支持。
- 音频：WAV、FLAC、OGG、MP3 的元数据、完整 PCM 内容、分块解码与回卷；原实例先销毁、克隆先销毁、多级克隆的存储生命周期。
- 模型：OBJ、STL、PLY、OFF、X、DAE、glTF、GLB 的三角形顶点和拓扑。这不证明复杂材质、骨架、动画或外部依赖支持。
- 地图：Tiled 高位翻转标志在单格、矩形、整层写入后保留，空块统计仍按去除标志后的 GID 判断。
- 导出：PNG RGBA8、PNG RGBA16、TGA RGBA8，经引擎回读与 Pillow/FFmpeg 独立读取；16 位 PNG 额外验证位深和完整 16 位通道值。

本轮修复了音频克隆借用原实例数据导致的释放后使用、MP3 回卷前后延迟补偿不一致、BMP 内存读取边界检查、GIF 解码未启用、HDR 非 RLE 像素读取，并接入 WebP 解码。扩大执行还修复了地图写入接口把带翻转位 GID 误清空，以及图片四分之一圈旋转的浮点舍入导致多出一列的问题。法线贴图测试原本按源 OBJ UV 写断言，却采用默认翻转 V 的导入选项，现显式保留源 UV；未改变引擎 UV 策略或放宽断言。第三方修复保存为可重复应用的依赖补丁。WebP 依赖固定版本与下载哈希，仅在 image 模块启用时引入。

```sh
EVENGINE_FORMAT_EXPORT_DIR="$PWD/build/resource-format-exports" \
  python3 scripts/resource_format_suite.py --build-dir build/linux-debug \
  --new-contracts-only --report build/resource-format-report.json
python3 scripts/check_resource_format_exports.py build/resource-format-exports \
  --report build/resource-format-export-report.json
python3 -m unittest scripts.tests.test_resource_format_suite
```

Linux CI 已加入样本完整性检查、完整资源结果复核和导出独立重读，新增 C++ 用例进入现有逐用例 CTest。资源契约用例出现 zeroerr `Assertion Failed` 时强制失败，避免只有警告计数、退出码为零而误报通过；执行器也拒绝跳过、缺失和未注册用例。
