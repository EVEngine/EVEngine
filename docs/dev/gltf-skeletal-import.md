# glTF skeletal asset import

The data-only glTF importer emits `eve.mesh/2`, `eve.skeleton/1`,
`eve.skin/1` and `eve.animation-clip/1`. Import is synchronous and worker-safe:
all inputs are borrowed for the call, the result owns all generated bytes, and
failure discards the unpublished candidate. Publication still uses the atomic
archive store. Import does not invoke scripts, providers or graphics APIs.

## Supported source contract

glTF uses metres, right-handed coordinates, Y up. No additional UE centimetre
conversion is applied after UE's glTF exporter has already converted the data.
Every node is retained in the skeleton, including non-joint ancestors and mesh
nodes. Parents precede children in deterministic breadth-first order. Animation
targets and skin joint references are remapped by node index, never by name.
Separate imports of different documents have separate skeleton identities.

TRS nodes and LINEAR translation, rotation and scale channels are supported.
Key times stay in seconds and strictly increasing. Clip duration is the maximum
key time. Sample rate is a baking hint derived from the minimum adjacent key
interval (1 Hz for a single-key clip); playback uses the original key times.
Loop defaults to false because glTF does not encode a loop policy.

Every contiguous JOINTS_n/WEIGHTS_n set is retained, up to 64 sets. Joint
components are unsigned byte/short. Weights may be FLOAT or normalized unsigned
byte/short. Nonnegative finite weights with positive total are renormalized over
**all** sets when necessary; the report records the affected vertex count as
`baked`. This repairs quantized non-unit sums observed in UE 5.8 exports without
truncating influences. Zero totals and invalid joint indices are rejected.
Missing inverse bind matrices mean identity matrices, as specified by glTF.

Matrix-form skeletal nodes, morph targets, non-LINEAR channels, sparse/compressed
accessors and required extensions fail explicitly. Materials, textures, images
and unrepresented vertex attributes (including tangents) produce `unsupported`
findings; successful archive validation is not a material-fidelity claim.

The reference contract is the [Khronos glTF 2.0 specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html).

## Canonical skin version 1

The new `eve.skin/1` definition has `schema`, `schemaVersion`, `blob`, `skeleton`,
`mesh`, `vertexCount`, `jointCount`, and `influencesPerVertex`. Skeleton and mesh
are typed runtime-required asset dependencies. One skin asset represents one
mesh primitive instance on a node. Named `skin:<node>:<primitive>` and
`animation:<index>` entrypoints expose the additional assets; the existing
default mesh entrypoint is unchanged.

The blob is little-endian:

- Eight bytes: `EVSKIN`, zero, version byte 1.
- Four uint32 fields: vertex count, joint count, influences per vertex, mesh
  node's remapped skeleton index.
- For each joint: uint32 skeleton index and 16 FLOAT inverse-bind elements in
  column-major order.
- For each vertex: `influencesPerVertex` pairs of uint32 skin-joint index and
  FLOAT weight, in source set/component order.

Schema version 1 has no predecessor. Readers reject unknown versions, preserve
unknown definition fields through the existing archive/migration mechanism,
and reject truncated/out-of-budget data. A future layout requires a new version
and explicit migration. Existing EVSKEL/1 and EVANIM/1 layouts are unchanged.

Cook carries all four types and required dependencies into `.evpack`; it does
not turn the skin into an opaque source GLB. Domain playback consumers must
resolve the skin's mesh/skeleton dependencies and honor its influence count;
the existing Model3D GLB playback path is a separate runtime consumer.

## Verification

`test/asset_import_gltf_animation.cpp` covers archive/Cook retention, remapped
bone and key values, malformed targets, cycles, invalid joints, budgets, unknown
interpolation, and multiple quantized weight sets. The same tests run through
`eve_gltf_animation_check` with `EVENGINE_BUILD_PROFILE_CHECKS=ON` in
`asset-core-only`, proving the importer does not require the renderer or UE.

The UE converter publishes using an exclusive random sibling directory with the
destination parent's inherited permissions. Python's mode-0700 temporary
directory must not be renamed into the final output: on Windows that can retain
a creator-only ACL and prevent the desktop runtime from reading converted files.
The request, validation and all-or-nothing publication contracts are unchanged.

## UE conversion and runtime acceptance

Converter 1.1.0 expands dense normalized UINT8/UINT16 GLB weight accessors to
FLOAT before hashing and atomic publication. Every influence set is retained;
other binary streams remain unchanged. This is an explicit conversion for the
current Assimp Model3D path, whose glTF weight reader assumes float storage.
The manifest records the converted stream count in `diagnostics`. The canonical
glTF importer also independently accepts normalized integer weights. This export
normalization currently applies to GLB; sidecar `.gltf` is not covered by this
runtime compatibility step. Model3D CPU playback reduces to its existing four
strongest influences, whereas the canonical skin retains every source influence.

Local acceptance used UE 5.8.2 UEFN Mannequin and
`M_Neutral_Walk_Loop_B`: 7,392 vertices, 93 skin joints, 94 hierarchy nodes,
three influence sets, and a 4.03333-second clip. The exported GLB loaded in
Model3D and produced changing CPU vertex positions and engine-rendered frames.
An independent neutral material was used to inspect deformation; this does not
verify source material fidelity. The canonical archive contains mesh, skeleton,
skin and clip, and its Windows Vulkan Cook contains eight chunks. Both validate.
This does not establish direct playback from the cooked skin schema or acceptance
of the entire UE Content directory. Tangents, Blueprint logic and UE animation graphs remain outside this import contract.
The initial neutral-material run has been superseded by the material acceptance below.

## Material import and original-material acceptance

UE conversion enables `-AllowCommandletRendering` instead of `-nullrhi`, uses
`USE_MESH_DATA` baking and PNG textures. Export warnings are retained in the
conversion manifest. The UEFN sample now exports `M_UEFN_Mannequin` with
`T_UEFN_Mannequin_D` and `T_UEFN_Mannequin_N`; the earlier NullRHI output had an
empty PBR object and no images. Original-material Model3D playback was checked
without tint, material, or lighting-reception overrides.

The importer emits `eve.material/2` and `eve.image/2`. It adds required
mesh-to-material and material-to-image references; textures keep explicit sRGB
(base color/emissive) or linear (normal/metallic-roughness/occlusion) semantics.
Material fields retain baseColor, metallic, roughness, emissive, surfaceMode,
alphaCutoff, doubleSided, the five named texture slots, per-slot Sampler objects,
normalScale and occlusionStrength. Metallic-roughness uses glTF G=roughness,
B=metallic; occlusion uses R. Normal maps already follow glTF conventions after
UE export. Defaults match glTF 2.0, including metallic=1 and roughness=1.

Material v1 migrates to v2 without changing asset identity or base PBR values;
local dependency type versions migrate with it and unknown definition fields survive.
The seven material/texture extensions described in [the material contract](gltf-material-extensions.md)
are admitted. Unknown material extensions and references to missing UV channels fail admission explicitly.
Multiple UV sets follow [the mesh v2 contract](canonical-mesh-v2.md). Image bytes are supplied by
validated buffer views or explicit external resources; no network/file IO occurs
inside the importer. Mutation is restricted to the unpublished candidate, which
is discarded on any failure. Images and materials are budget checked.

Cook retention is distinct from renderer coverage: Model3D directly plays the
converted GLB, whereas EvpackStaticPrefab applies the cooked extended materials described in
[gltf-material-extensions.md](gltf-material-extensions.md). This work does not add a cooked skeletal-scene renderer.
Full five-slot rendering, sampler parity, and exact UE shader-graph fidelity are
not established by this two-texture sample. The acceptance suite covers all five
slots through archive/Cook, missing images, texture transforms and budgets.
