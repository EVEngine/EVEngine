# 感知与目标选择系统设计

日期：2026-09-14（2026-09-15 修订：统一查询面）  
状态：提案（对照 UE5 GameplayTargetingSystem，基于现有 `sensing` / `Targeting*` 协议演进）  
适用范围：`sensing`、`action` 组合、RTS/武器/AI 等消费者；不含编辑器 `EditableTarget`、动画 retarget。

## 1. 结论

EVEngine **已经有**与 UE5 Targeting System 同层的协议骨架，而不是“完全没有对应功能”：

| 层 | 现状 | 对标 UE5 |
|---|---|---|
| 候选事实镜像 | `SensingWorld`（2D circle/box + tag/faction/visibleTo） | Selection 粗查的一部分 |
| 坐标安全约束解析 | `TargetingSpec` / `TargetingQuery` / `TargetingResolver` + `TargetSet` | Filter 管线的一部分 |
| 能力注入 | `ISensingCandidateProvider`、`ILineOfSightQuery` | Task 依赖的 World/Subsystem 服务 |
| Action 组合 | `TargetingMode::{None,Explicit,Query}` + `SensingTargetingAdapter` | GA `PerformTargetingRequest` 的薄适配 |

真正缺的不是再造一套索敌器，而是把双轨收成：

> **一份候选事实（`SensingWorld`）+ 一套可配置查询（`QuerySpec` / 日后 Preset）→ 有序候选结果**

终态上，`SensingWorld` 是**完整、可配置的候选查询组件**；`ISensingCandidateProvider` / 现有 `TargetingResolver` 降为兼容壳或同构前端，而不是长期并行的第二真相源。

**完整**指查询能力完整（形状、过滤轴、排序/截断、可选 LOS），**不是**玩法决策完整。架构宪章不变：`sensing` 只返回候选与可解释分数；技能 / 武器 / 卡牌 / RTS 命令保留最终选择语义（checklist §23、`组合式游戏机制架构.md` §5.7）。

**不要**照搬 UE5 的 Actor/`FHitResult` 中心模型，也不要把威胁表、软锁、职业克制写死进 `SensingWorld`。

## 2. UE5 GameplayTargetingSystem 要点

插件提供数据驱动请求：

1. **`UTargetingPreset`**：有序 Task 列表（Selection → Filter → Sort）。
2. **`FTargetingSourceContext`**：源 Actor / 位置 / Instigator / Socket。
3. **`UTargetingSubsystem`**：同步 `Execute*` 或异步 `StartAsync*`，用 `FTargetingRequestHandle` 取结果并释放。
4. **内置任务**：AOE 选择、基础过滤、按距离排序等；可扩展自定义 Filter/Sort。
5. **结果**：候选列表 +（Sort 后）每项 `Score`；Gameplay Ability 可走 `PerformTargetingRequest` / `PerformFilteringRequest`。

价值不在“能查到附近单位”（我们已有），而在：

- 同一套配置可被技能、AI、投射物、UI 复用；
- 选择 / 过滤 / 打分可插拔，不改调用方；
- 排序分数可调试、可解释。

## 3. 现状与差距

### 3.1 已具备（保留）

- 强类型坐标空间：`World2D/3D`、`Grid2D/3D`，禁止隐式混用。
- `TargetingSpec`：domain、min/maxCount、range、required/excluded tags、zone、world/grid area、LOS 模式。
- `TargetSet`：subjects + 可选 primary / point / area（resolver **从不**隐式设 primary）。
- Capability：缺 provider → `Unsupported`，不假装空成功。
- Physics LOS adapter（World3D）；Action Query 模式已接入。
- RTS `CombatFireSystem` 用 `SensingWorld.circle` + 局内 priority 表做自动索敌（策略在 RTS，不在 sensing）。

### 3.2 主要缺口

| 缺口 | 说明 |
|---|---|
| 双轨语义不一致 | `SensingWorld` 用 faction/`visibleTo`/distance+limit；`Targeting*` 用 `TargetDomain`/zone/LOS/`maxCount` 硬失败。不是同构 API，不能“薄桥即等价” |
| 无统一 QuerySpec | circle/box 参数与 `TargetingSpec` 字段分裂；调用方无法用同一配置描述需求 |
| 无 Preset / Task 管线 | 约束写死在 Spec + resolver；无法像 UE5 那样组合 Selection/Filter/Sort |
| 无排序分数 / top-K 协议 | World 有 limit 截断；Resolver 的 maxCount 是整组失败；两套结果策略 |
| 查询形状偏少 | World 仅 2D circle/box；无 cone/sector/capsule；无朝向 |
| 未用 `spatial` | 模块 `DEPS spatial`，实现仍是线性扫描 |
| 无脚本 Targeting 绑定 | 仅 World 脚本面；`Targeting*` 无 Squirrel API |
| 周边未接满 | 武器 lock-on、npc_ai PerceptionMemory、Zone→sensing 绑定仍在各自 gap 文档中 |

### 3.3 明确不放进 sensing 核心

- Soft-lock / sticky aim / magnet / 手柄吸附
- 威胁表、仇恨、职业克制
- 导弹制导轨迹（武器模块）
- UI 卡牌拖拽合法性（`card` 只管手势）

## 4. 目标架构：统一可配置查询面

```text
upsert/remove 镜像事实
        │
        ▼
┌──────────────────────────────────────┐
│ SensingWorld（唯一候选事实库）         │
│  + QuerySpec / 日后 TargetingPreset  │
│  + 可选注入：阵营关系、LOS、spatial   │
└──────────────────────────────────────┘
        │
        ▼
CandidateSet / RankedCandidateSet   ← 无隐式 primary
        │
        ├─ Action（兼容 TargetingQuery 壳）
        ├─ RTS 索敌（priority 仍可在外层）
        ├─ Weapon / AI / Script
        └─ ISensingCandidateProvider 适配器（兼容旧 Capability 消费者）
```

### 4.1 SensingWorld 的职责边界

**负责：**

- 持有镜像事实：`SubjectRef`/稳定 id、位置、faction、tags、`visibleTo`、可选 zones
- 按 `QuerySpec`（或 Preset）执行查询并返回**有序候选**
- 可选 capability：LOS、spatial 广相
- 快照 / 恢复

**不负责：**

- 选定 primary / “最佳目标”
- 题材威胁分、软锁、技能合法性
- 隐式 World↔Grid 坐标换算

### 4.2 QuerySpec（Phase 1 核心类型）

一次查询的完整、可配置描述；替换“circle/box 一长串 CSV 参数”与“另一套 TargetingSpec”的分裂。

```cpp
/** @brief How overflow relative to maxCount is handled. */
enum class CountPolicy : std::uint8_t {
    FailIfOutOfRange,  // current TargetingResolver behavior (default for Action compat)
    TruncateToMax,     // current SensingWorld limit behavior
};

/** @brief One configurable candidate query against SensingWorld. */
struct QuerySpec {
    CoordinateSpace space = CoordinateSpace::World2D;

    // Geometry (exactly one broad shape, or range-only around origin)
    std::optional<WorldArea> worldArea;
    std::optional<GridArea> gridArea;
    float minRange = 0.f;
    float maxRange = std::numeric_limits<float>::infinity();

    // Fact filters
    TargetDomain domain = TargetDomain::Any;          // needs relation projection when used
    std::vector<std::string> requiredTags;
    std::vector<std::string> excludedTags;
    std::vector<std::string> includeFactions;         // string facts as stored
    std::vector<std::string> excludeFactions;
    std::optional<std::string> visibleTo;             // observer key; not geometric LOS
    std::optional<ZoneRef> zone;

    // Result policy
    std::uint32_t minCount = 0;
    std::uint32_t maxCount = std::numeric_limits<std::uint32_t>::max();
    CountPolicy countPolicy = CountPolicy::TruncateToMax;
    LineOfSightMode lineOfSight = LineOfSightMode::NotRequired;

    // Ordering (Phase 1: distance only; Phase 2: named sort tasks)
    enum class SortKey : std::uint8_t { None, DistanceAscending };
    SortKey sortKey = SortKey::DistanceAscending;

    [[nodiscard]] Result<void> validate() const;
};

struct QuerySource {
    SubjectRef origin;                 // required when domain≠Any or LOS required
    TargetLocation originLocation;     // space must match spec.space
    // optional: opaque socket token for adapters
};

struct RankedCandidate {
    SubjectRef subject;
    TargetLocation location;
    float score = 0.f;                 // Phase 1: -distance when SortKey::DistanceAscending
    std::string scoreReason;           // e.g. "distance"
};

class CandidateQueryResult {
public:
    [[nodiscard]] std::span<const RankedCandidate> ranked() const noexcept;
    [[nodiscard]] TargetSet asTargetSet() const; // strips scores; no primary
};
```

`SensingWorld` 新入口：

```cpp
[[nodiscard]] Result<CandidateQueryResult> query(const QuerySource& source,
                                                 const QuerySpec& spec) const;
```

保留现有 `circle`/`box` 为 **QuerySpec 的语法糖**（内部组 spec，不维护第二套过滤实现）。

### 4.3 语义裂缝：必须显式处理，不能默认同构

| 轴 | SensingWorld 旧语义 | Targeting* 旧语义 | 统一后约定 |
|---|---|---|---|
| 敌我 | faction 字符串 include/exclude | `TargetDomain` 相对关系 | 两者都保留；`domain≠Any` 时要求注入 `IFactionRelation`（或等价回调），缺则 `Unsupported` |
| 可见 | `visibleTo` 观察者键 | 几何 LOS capability | **正交**：可同时配置；禁止互相冒充 |
| 数量 | `limit` 截断 | `maxCount` 硬失败 | `CountPolicy` 显式选择 |
| 空间 | 仅 World2D | 多空间 | 非 World2D 且 World 无该空间事实 → `Unsupported`，不静默降维 |
| 身份 | `string id` | `SubjectRef` | 存储与结果统一为可解析的 `SubjectRef`；非法 id → 结构化失败 |

### 4.4 与 TargetingResolver / Provider 的关系

```text
SensingWorld::query(QuerySpec)     ← 唯一实现真相
        │
        ├─ SensingWorldCandidateProvider  ← 实现 ISensingCandidateProvider（兼容 Action Capability）
        ├─ TargetingResolver              ← 薄封装：TargetingQuery → QuerySpec → TargetSet
        └─ 脚本 circle/box                ← 薄封装：参数 → QuerySpec
```

Phase 1 即以此为目标：**先统一实现，再留兼容适配器**；不是“先永远双轨再薄桥”。

### 4.5 Phase 2+：Preset / Task 管线

在 QuerySpec 稳定后，把“固定字段配置”演进为 UE5 式有序任务：

```text
SourceContext + TargetingPreset
  → Selection / Filter / Sort tasks
  → RankedCandidateSet
```

内置任务最小集：

| Kind | Task id | 行为 |
|---|---|---|
| Selection | `sensing.select.world` | 从 `SensingWorld` 广相 |
| Filter | `sensing.filter.spec` | 复用 QuerySpec 字段子集 |
| Filter | `sensing.filter.los` | `ILineOfSightQuery` |
| Filter | `sensing.filter.cone` | 朝向 + 半角 + 距离 |
| Sort | `sensing.sort.distance` | 近→远 |
| Sort | `sensing.sort.truncate` | top-K |

题材 Sort（威胁、职业）留在游戏模块注册表。

### 4.6 几何、spatial、异步

- 扩展 `WorldArea`：`cone2D` / `sector3D`；广相逐步换 `spatial`。
- 第一期只做**同步**查询；异步 request handle 后置，且不得隐式写 ECS。

## 5. 与现有架构规则的对齐

| 规则 | 本设计如何满足 |
|---|---|
| sensing 不决定目标价值 | 只返回候选/分数；primary 仍由消费者显式设置 |
| 短根 + Link | `SubjectRef` / `ZoneRef`；无 Actor 大根 |
| Capability 注入 | 阵营关系、LOS、spatial、自定义 task 均可选注入；缺则 `Unsupported` |
| `Result` + `[[nodiscard]]` | `query` / validate / 适配器全部结构化失败 |
| 可选依赖可观测 | 不静默空成功 |
| 确定性 | 同步路径；同分 tie-break 用 `SubjectRef` 字典序 |

## 6. 分阶段实施

### Phase 0 — 文档与契约（本提案）

- 固定终态：`SensingWorld` = 唯一事实库 + 可配置查询面。
- 固定词汇：`QuerySource` / `QuerySpec` / `CountPolicy` / `CandidateQueryResult`。
- 标明 Provider/Resolver 为兼容层，不是第二实现。

### Phase 1 — QuerySpec 统一查询面（高杠杆）

1. 在 `sensing` 引入 `QuerySpec` / `QuerySource` / `CandidateQueryResult`。
2. `SensingWorld::query` 成为唯一过滤/排序实现；`circle`/`box` 改为糖。
3. 实现 `CountPolicy::{FailIfOutOfRange, TruncateToMax}`；默认糖路径保持 Truncate（兼容 RTS/脚本）。
4. `TargetingResolver` 改为组 `QuerySpec` 后调 World（或共享纯函数核心）；Action 默认 `FailIfOutOfRange` 保持旧契约。
5. `SensingWorldCandidateProvider`：Capability 兼容适配器（读同一 World）。
6. `domain` 路径：无关系注入时对 `domain≠Any` 返回 `Unsupported`（诚实失败，不做假 Enemy）。
7. 测试：同一事实集上 RTS 糖查询与 Action Spec 查询语义对照；top-K；同分稳定序；缺关系注入失败。

### Phase 2 — Preset / Task 注册表

1. `ITargetingTask` + registry；Preset Definition schema。
2. cone 几何；脚本 `executePreset`。
3. 用户文档 `docs/usr/modules/sensing.md`。

### Phase 3 — 消费者迁移

1. RTS 索敌改为 `QuerySpec`/preset；priority 表留 RTS 或注册 Sort task。
2. Weapon lock 获取改走统一查询；aim assist 仍游戏侧。
3. npc_ai PerceptionMemory adapter；Zone→candidate.zones。

### Phase 4 — 性能与调试

1. `spatial` 广相 + 基准。
2. MCP/debug overlay：area/cone/scores。
3. 评估异步是否必要。

## 7. API 草图（脚本）

```squirrel
local world = eve.Sensing().newWorld().value;

// 糖：内部转为 QuerySpec（TruncateToMax + distance sort）
local n = world.circle(x, y, 12.0, "combat-target", "", "", "player", "", 8).value;

// 显式配置面
local ranked = world.query({
    origin = "unit.hero",
    x = x, y = y, space = "world2d",
    maxRange = 12.0,
    requiredTags = ["combat-target"],
    excludeFactions = ["player"],
    countPolicy = "truncate",
    maxCount = 8,
    sortKey = "distance"
}).value;

local best = ranked.at(0); // score + subject；primary 仍不自动产生
```

C++ Action 兼容：

```cpp
// TargetingQuery 继续可用；内部映射到 QuerySpec + CountPolicy::FailIfOutOfRange
definition.targetingMode = TargetingMode::Query;
```

## 8. 测试与验收

- 同一 `SensingWorld` 事实：`circle` 糖与等价 `QuerySpec` 结果一致（含顺序）。
- `TruncateToMax` vs `FailIfOutOfRange` 对照。
- `domain≠Any` 且无关系注入 → `Unsupported`。
- `visibleTo` 与 LOS 正交组合用例。
- 非 World2D 查询在仅 2D 事实上 → `Unsupported`。
- Action / RTS 回归：旧默认行为不变。
- 架构门：无 sensing→physics/scene 泄漏；LOS 仍 capability。

## 9. 非目标

- 复制 UE5 `FHitResult` / Actor 数组作为一等结果。
- 在 sensing 内实现完整瞄准辅助或摄像机 soft-lock。
- 把 `SensingWorld` 做成通用 AI 决策 / 威胁评估组件。
- 用一个 `gameplay` 大模块吞掉 sensing/action/weapon。
- 把 `EditableTarget` / 动画 retarget 混进本协议。

## 10. 建议落地顺序（工程判断）

优先 **Phase 1：QuerySpec 统一查询面**，而不是“仅做 World→Provider 薄桥”。

理由：

1. 双轨的根因是**过滤语义不一致**，薄桥无法消除 faction↔domain、limit↔maxCount 裂缝。
2. 把实现收进 `SensingWorld::query` 后，Provider/Resolver/脚本糖都变薄，后续 Preset 只是把 QuerySpec 字段拆成可插拔 Task。
3. 仍可用适配器满足现有 Action Capability，不强迫所有消费者同 PR 迁移。
