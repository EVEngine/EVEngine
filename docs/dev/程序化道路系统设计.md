# 程序化道路系统设计

日期：2026-09-17
状态：MVP 已落地（`src/modules/procgen/road/`）
存放：`docs/dev/`

## 目标

在**不使用预制道路/桥梁模型**的前提下，用数学函数生成与参考图一致的视觉层：

1. **几何**：多高程道路、桥面、侧栏、人行道、桥墩
2. **逻辑贴图**：沿弧长/横向 UV 的车道线、斑马线、导向箭头
3. **导航网络可视化**：车道中心线与路口转弯弧（青/绿叠加）

全部由 `SplinePath` 平行输运帧 + 截面挤出 + 图论车道图合成，运行时可烘培为 `MeshBuild`。

## 非目标（MVP）

- 完整路口 CSG 布尔融合（用路口平台 + 边端收缩近似）
- 地形挖填 / 贴地切割
- 真实交通仿真与 AI 寻路驱动
- 中文「道路编辑」产品化编辑器面板（文档预留工具流，运行时先配方 + 示例）

## 与现有能力的关系

| 复用 | 角色 |
|------|------|
| `SplinePath` / `sampleFramesResult` | 中心线与 Frenet 式截面帧 |
| `MeshBuild` 命名 group | `asphalt` / `curb` / `sidewalk` / `deck` / `pier` / `marking` / `nav` |
| `MeshRecipeRegistry` | `mesh.roadNetwork` 配方入口 |
| `TextureRecipeRegistry` | `tex.roadMarkings` 逻辑贴图 |
| `urban` 街道 | 可选上游 2D 中心线；本系统是 3D 车道域 |

**不**新建顶层 `road` 模块目录；算法作为 `procgen` 宿主内的 `road/` 卫星（同 `urban/`）。

## 数据模型

```text
RoadNetwork
  nodes[]:  RoadNode { id, position, junctionRadius }
  edges[]:  RoadEdge {
      id, from, to,
      controlPoints[] → SplinePath (catmullRom),
      lanesForward, lanesBackward,
      style (laneWidth, curb, sidewalk, deckThickness, pier*),
      elevated (bool | height threshold)
  }
  laneLinks[]:  at a node, (inEdge, inLane) → (outEdge, outLane)
```

权威所有者：`RoadNetwork` 拥有节点/边/车道连接；烘培结果是无指针快照（`MeshBuild` + `RoadOverlay` 折线）。

## 数学管线

### 1. 截面剖面 `RoadProfile`

在边局部 `(side, up)` 平面构造折线剖面：

```text
[-W/2-sidewalk-curb … asphalt lanes … +W/2 …]
```

每个区段带 material tag，挤出时写入对应 triangle group。桥面在 `up` 负向加 `deckThickness` 底板。

### 2. 边挤出 `RoadBake::bakeEdge`

1. 边控制点 → `SplinePath`，弧长均匀采样帧
2. 在路口半径处裁剪端点参数，避免与路口平台重叠
3. 沿帧挤出剖面（开剖面条带 + 底板可选）
4. 若帧高度 > `pierClearance`，按 `pierSpacing` 放置轴对齐桥墩盒子
5. 车道标线：在沥青表面上偏移的薄带（白边线、黄虚中线、斑马带）

UV：`u = normalized arc length`，`v = normalized lateral`（逻辑贴图与虚线周期均依赖此约定）。

### 3. 路口平台

对度数 ≥ 2 的节点，用入射边端点左右路肩点构成凸包近似平台，扇形三角化；斑马线沿入射方向铺条。

### 4. 导航叠加 `RoadOverlay`

- 每条车道：中心线偏移 `±(i+0.5)*laneWidth` 的折线
- 路口：同节点合法 `laneLinks` 用三次 Hermite 弧连接
- 箭头：沿折线按弧长放置小三角 mesh（group `nav`）

### 5. 逻辑贴图 `tex.roadMarkings`

纯函数 `(u,v) → RGBA`：沥青底色 + 边线 + 周期虚线 + 可选斑马/箭头 mask。与几何 UV 对齐，可独立预览或烘焙。

## 编辑工具流（产品映射）

与参考图底部工具栏对齐的**语义阶段**（实现可后挂 `procgen_editing`）：

| 阶段 | 文档操作 | 运行时对应 |
|------|----------|------------|
| 道路编辑 | 增删边控制点 | `RoadEdge.controlPoints` / SplinePathDocument |
| 岔路编辑 | 节点连接、匝道 | `RoadNode` + 边拓扑 |
| 导航网络 | 生成 laneLinks / overlay | `buildNavigation` |
| 调整车道 | lanesForward/Backward、laneWidth | `RoadStyle` |
| 烘培模型 | bake → MeshBuild | `bakeRoadNetwork` / `mesh.roadNetwork` |
| 样式编辑 | 剖面与材质色 | `RoadStyle` + `tex.roadMarkings` |

## API 契约

- 失败路径一律 `Result<T>` / recipe `bool + error`；禁止 `lastError`。
- 烘培同步、owner-thread-only；返回值不持有对 `RoadNetwork` 的指针。
- Schema：`eve.procgen.roadNetwork` v1（后续 Document 化时沿用）。

## 验证

- 单元：剖面宽度、挤出顶点/组、桥墩触发、导航折线非空、配方确定性
- 示例：`examples/procedural-road` 烘培立交并画导航折线
- 架构：仍落在 `procgen` 宿主内，无向上 `#include`
