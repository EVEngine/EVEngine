# 场景对象模型使用指南（Node / SceneEntity / Link）

日期：2026-10-08  
状态：DX cookbook（配合 `场景节点ECS打通设计.md`）  
存放：`docs/dev/`

## 一句话

| 你要做什么 | 用什么 |
|---|---|
| 摆位置、父子层级、可见性、纯数据树 | `SceneNode`（`eve.Scene` + `SceneNodeRef`） |
| 给节点挂玩法/行为脚本组件、进 `eve.view` | `eve.SceneEntity`（`attachEntity`） |
| 让节点驱动另一领域对象（渲染体、刚体、相机、音源） | 开放式 `Link`（`linkRenderable3D` / `linkPhysics2D` / …） |

不要发明第四套身份；跨领域一律 Link/Handle，不要在脚本里长期握裸指针。

## 三层分别是什么

```text
SceneNode（arena 纯数据）
  └─ 懒创建 SceneObject（C++ ECS 身份）
        └─ 根引用若干 eve.SceneEntity（脚本）
```

- **SceneNode**：变换与树结构的权威；没有脚本时零 ECS 开销。
- **SceneObject**：节点的 C++ ECS 挂点；只有 attach / 引擎组件需要时才创建。
- **SceneEntity**：脚本侧实体；可有组件槽、`update(dt)`、参与 `eve.view(cls)`。

## 常见写法

### 1. 只要摆场景

```squirrel
scene.beginBuild()
scene.beginNode("root")
scene.addNode("prop")
scene.setBuildPosition(1, 0, 2)
scene.end()
scene.mountBuildAs("level")
local n = scene.getNodeRef("prop")
n.setRotation(0, 45, 0)
```

### 2. 节点上挂行为

```squirrel
class GuardAI extends eve.SceneEntity {
    function onAttach() { /* ... */ }
    function update(dt) { /* 读 node() 读写变换 */ }
    function onEnable() {}
    function onDisable() {}
}
local e = scene.attachEntity("prop", GuardAI)
e.disable()          // 跳过 update
e.enable()
```

### 3. 在 update 里安全卸载

`detachEntity` 可在 update 外立刻用。在 `update(dt)` 内请用延迟队列：

```squirrel
function update(dt) {
    if (shouldDie) scene.scheduleDetachEntity(nodeId, this)
}
```

`scene.update(dt)` 在所有 `update` 回调结束后统一 `flushDelayedDetaches`。

### 4. 按类型收集节点

```squirrel
local ids = scene.collectIdsWith(GuardAI)
```

### 5. 跨领域：用 Link，不要把 Body/Renderable 塞进继承树

```squirrel
scene.linkPhysics3D("prop", body)      // 或 NodeRef.linkPhysics3D(body)
scene.linkRenderable3D("prop", mesh)
```

Link 的 owner / 失效 / 双向销毁策略由提供 kind 的模块注册（见 `SceneLink.h`）。

## 反模式

- 为了“方便”做 `GameObject` 大根类同时继承 Scene + Physics + RPG。
- 在 `update(dt)` 里同步 `detachEntity` 再继续遍历同类实体。
- 跨帧保存 `SceneNode*` / `Body*`；应保存 nodeId、`EntityHandle` 或领域 Handle。
- 用组件表达“是什么”（应用继承短根）；用继承表达短暂状态（应用组件）。
