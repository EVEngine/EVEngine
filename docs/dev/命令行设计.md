命令行工具设计
============

这是一个命令行工具模块，是PC-dev版的核心入口，可以执行诸多命令行指令，包括：
1. 创建新工程
2. 运行当前程序
3. 运行开发服务器
4. 打包
5. 下载依赖项
6. 自动测试
7. 查看文档
8. 无头 MCP 主机（AI 中心开发模式）

其中核心是执行、测试、创建、打包

执行逻辑：
1. 创建脚本VM
2. 查看当前文件夹下是否有启动脚本 boot.nut
    有： 加载
    没有： 加载默认boot脚本
3. 运行脚本

开发服务器逻辑：
1. 创建脚本VM
2. 查看当前文件夹下是否有启动脚本
    有： 加载
    没有： 加载默认boot脚本
3. 监视当前文件夹下的文件变动
4. 记录重启点
5. 重载文件夹下脚本变动
6. 运行脚本

测试逻辑：
1. 检测是否有测试配置 test.nut
2. 加载脚本，根据命令行参数执行对应测试
3. 测试除了自动单元测试，还可以执行测试场景，加载人物、地图和剧情

打包逻辑：
1. 下载platform下对应工程项目和引擎的二进制类库
2. 编译并链接需要的模块
3. 生成对应的可执行文件

打包时可选参数，是clone整个引擎源码，还是clone platform，或者是clone platform下某个平台


下载第三方插件逻辑：
我们首先维护一个仓库，用来存放第三方用户编写的类库的地址，有人开发了第三方库后，发个pr将其链接添加进去
1. 查看仓库中最新版本的地址列表
2. 下载对应仓库中的源码，或者release中的dll so库
3. 存放到当前目录的third-party下

无头 MCP 主机逻辑（eve mcp）：
1. 创建脚本VM（全模块）
2. 附加 DevTools（复用 eve_eval / eve_run_script / snapshot）
3. 启动 EditorHost：JSON View ↔ Squirrel ViewModel 双向绑定 + 窗口渲染
4. 启动 MCP：默认 stdio（Codex 直接接入），--port 走 TCP
5. 主循环：mcp.poll() + editorHost.frame()；stdin EOF / eve_host_shutdown / 窗口 quit 退出

`eve mcp [--port N] [--root <dir>]`：AI 通过 eve_host_* 工具创建窗口、提交 JSON 编辑器、
注册 ViewModel、读取交互事件、截图、运行脚本；编辑器可持久化到项目 editors/ 目录并在
重启后自动恢复。协议与示例见 docs/dev/AI与MCP支持.md。
