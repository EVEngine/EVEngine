## 背景

现有 `weapon::ProjectileRuntime` 把弹道模式（Linear / Ballistic / Homing）做成枚举特化：
一次 spawn 只选一种积分路径，命中、穿透、引信、分裂等攻击语义仍散落在 RTS/游戏侧。

参考「纯行为组合」投射物架构的目标是：

> **载体只是飞行中的事实容器；弹道、触发、攻击效果各自是可拼装行为，互不硬编码。**

同一颗“子弹”可以是：

- 直线弹 + 命中伤害 + 命中即销毁
- 抛物线榴弹 + 引信爆炸（无碰撞也可引爆）
- 制导火箭 + 命中穿透 N 次 + 耗尽后释放
- 母弹到期分裂出若干子载体

而无需为每种组合写一个新的 `ProjectileMode` 或 `IWeaponLogic`。

## 决策

1. **落在 `weapon` 模块**，不新建顶层 `projectile` / `combat_carrier` 模块。
   弹道池与武器开火同层；`combat` 仍只负责伤害结算，通过消费载体事件接入。
2. **保留 `ProjectileRuntime`** 作为轻量三模式轨迹池（RTS 等现有调用方不变）。
   新框架是并列的组合式运行时，并提供从 `ProjectileDefinition` 生成默认配方的桥。
3. **不引入 CombatActor / ProjectileActor 大根类**。载体是池化 slot + generation handle，
   行为是配方上的数据规格，不是继承树。
4. **`weapon` 不依赖 `combat` / `physics` / `graphics`**。命中探测与目标位置通过
   `ICarrierHitProbe` / `IProjectileTargetProvider` 注入；伤害用拥有型事件载荷表达。

## 概念模型

```text
CarrierRecipe（静态配方）
├── motionOps[]     弹道算子（按序叠加）
├── triggers[]      触发器（何时）
└── impacts[]       效果（做什么；绑定 trigger kind）

CombatCarrierRuntime（权威池）
├── spawn(recipe, request) → CarrierHandle
├── update(dt, targets?, hits?) → CarrierFrame
│     advanced / released / events / childSpawns
└── snapshot / restore
```

### 弹道算子（Trajectory）— 只改运动，不谈伤害

| Kind | 语义 |
|---|---|
| `SteerHoming` | 按 `maxTurnRateDegrees` 把速度转向目标（不积分位移） |
| `ApplyGravity` | `velocity.y -= gravity * dt` |
| `Accelerate` | 沿当前速度方向增加速率 |
| `IntegrateLinear` | `position += velocity * dt` |

组合示例：

- 直线弹：`[IntegrateLinear]`
- 抛物线：`[ApplyGravity, IntegrateLinear]`
- 制导：`[SteerHoming, IntegrateLinear]`
- 加速导弹：`[SteerHoming, Accelerate, IntegrateLinear]`

### 触发器（Trigger）— 只决定时机

| Kind | 语义 |
|---|---|
| `OnExpire` | 本帧年龄跨越 `lifetime` |
| `OnFuse` | 本帧年龄跨越 `fuse` |
| `OnInterval` | 存活期间每隔 `interval` |
| `OnHit` | `ICarrierHitProbe` 报告接触 |
| `OnProximity` | 目标进入 `proximityRadius` |

### 效果（Impact）— 只响应触发

| Kind | 语义 |
|---|---|
| `EmitHit` | 压入 `CarrierEvent`（伤害/元素/载荷字段，供游戏或 combat 适配） |
| `Splash` | 压入带 `splashRadius` 的事件（范围中心=载体位置） |
| `Pierce` | 消耗一层穿透预算；本轮触发抑制释放 |
| `Bounce` | 按接触法线反射速度并消耗弹跳预算；抑制释放 |
| `Release` | 请求释放（若同轮被 Pierce/Bounce 抑制则忽略） |
| `SpawnChild` | 排队按 `childRecipeId` 在当前位置生成子载体 |

处理顺序：同一触发上的 impacts 按配方顺序执行；`Pierce`/`Bounce` 置位 `suppressRelease`；
最终 `release = any(Release) && !suppressRelease`。整帧在候选副本上推进，探测失败则整帧回滚。

## 生命周期与确定性

- Owner thread only；注入 `Duration`，不读墙钟、不隐式 RNG。
- Handle 带 generation；slot 重用使旧 handle 失效。
- `update` 原子：先算完全部候选与事件，再发布；子载体在同一帧末尾、容量允许时生成。
- Homing / Proximity 共用可选 `IProjectileTargetProvider`；Hit 共用可选 `ICarrierHitProbe`。
- 浮点逐步确定（同编译器/后端）；跨后端比较使用项目声明的位置容差。

## 与现有层的接缝

| 层 | 职责 |
|---|---|
| `action` / `weapon` 开火 | 在 Active 帧 `spawn` 载体（替代或并存 `IProjectileService`） |
| `CombatCarrierRuntime` | 弹道 + 触发 + 效果组合；产出事件 |
| 游戏 / `rts` | 实现 HitProbe（扫掠/障碍）；消费事件 |
| `combat::DamageRuntime` | 将 `EmitHit`/`Splash` 事件适配为 `DamageRequest` |

`ProjectileRuntime` 继续服务只需要三种轨迹、自行处理碰撞的调用方。
需要穿透/引信/分裂时改用 `CombatCarrierRuntime`。

## 非目标

- 不把物理引擎碰撞写进 `weapon`。
- 不在载体层结算护甲/暴击/仇恨。
- 不规定 VFX/音效；表现层订阅事件即可。
- 不替换 `IWeaponLogic`；开火逻辑仍可插拔，仅把“生成什么”换成配方 id。

## 架构规范对照

| 规范 | 落地 |
|---|---|
| 领域短根 / 无 GameObject | 池化 Carrier + 数据配方，无实体继承根 |
| Result / nodiscard | spawn/update/release/restore 均 `[[nodiscard]] Result` |
| 单一权威 owner | `CombatCarrierRuntime` 拥有 slot；事件为拥有型副本 |
| Link 失效 | generation handle；探测用 EntityHandle |
| 可选依赖可观测 | 缺 HitProbe 时 `OnHit` 配方在 update 返回结构化失败 |
| 确定性 | 注入 Duration；整帧候选提交 |
