# 背包 / 物品栏模块设计：物品 / 容器 / 装备 / 扩展点

日期：2026-08-10  
状态：已实现（首版，`src/modules/inventory/`）

## 目标

提供一套**高度灵活、可定制化**的背包与物品栏框架，覆盖 4 个互相配合的子系统：

1. **物品定义（Item）** — 数据驱动的物品模板（堆叠、重量/体积、标签、自定义字段）。
2. **容器（Bag）** — 固定格数的运行时背包/箱子/商店栏，支持容量策略与接纳规则。
3. **库存操作（InventorySystem）** — 放入 / 取出 / 移动 / 交换 / 拆分 / 合并 / 转移，以及变更事件。
4. **装备栏（EquipmentSet）** — 具名槽位（武器/头盔……）与背包之间的穿脱，松耦合于 RPG 属性。

与引擎既有模块（`rpg` / `map` / `particles`）保持同一套设计语言：纯数据结构 + `*System`
静态行为 + `Module` facade 做脚本绑定；参考 [模块设计.md](./模块设计.md) 与
[RPG系统设计.md](./RPG系统设计.md)。

## 为什么不用固定枚举

沿用仓库既定的类绑定原则（见 [模块设计.md](./模块设计.md)「类绑定原则」）：

- 物品 id、标签、分类、容量策略名、接纳规则名、堆叠规则名、装备槽名全部是**字符串**。
- 新增一种物品 / 一种容器策略，不需要改引擎头文件、不需要重新编译。
- 数据可完全放进 JSON（`ItemRegistry::loadFromJson`），也可由 C++ 插件注册。
- 未知字符串在规则查找失败时走安全回退（拒绝放入 / 使用默认规则），而不是编译失败。

## 可插拔扩展点一览

| 系统 | 扩展点 | 谁来注册 | 覆盖场景 |
|------|--------|----------|----------|
| 接纳 | `InventorySystem::registerAcceptRule(name, fn)` | C++ | 内置 default/any 之外：等级限制、职业限制、任务物品专属栏 |
| 容量 | `InventorySystem::registerCapacityPolicy(name, fn)` | C++ | 内置 slots/weight/volume 组合之外：负重随力量变化、无限仓库 |
| 堆叠 | `InventorySystem::registerStackRule(name, fn)` | C++ | 内置 sameItem / sameItemAndProps / never 之外：按耐久区间合并等 |
| 变更 | `InventorySystem::registerChangeHook(name, fn)` | C++ | 成就统计、UI 刷新、与 RPG 属性联动（装备加成） |
| 数据 | `ItemDefinition::extra` / `Bag::extra` / `ItemStack::props` | C++ 或 JSON | 任意自定义字段无需扩结构体 |

## 数据模型

### ItemDefinition（`ItemTypes.h` / `Item.h`）

```text
ItemDefinition {
  id, displayName, maxStack, weight, volume,
  tags[], category, equipSlot, extra{string→string}
}
```

- `maxStack <= 0` 按 `1` 处理。
- `equipSlot` 为空表示不可装备；非空时仅为提示字符串，装备栏是否接受由 `EquipmentSet` 槽位配置决定。
- `extra` 存放图标路径、品质、脚本钩子名等游戏自定义数据。

### ItemStack（运行时堆叠）

```text
ItemStack {
  instanceId, itemId, quantity, durability(-1=N/A),
  props{string→string}, tags[]
}
```

空槽：`itemId.empty() || quantity <= 0`。`instanceId` 在放入时由 `InventorySystem` 分配，用于跨帧精确引用。

### Bag（`Bag.h`）

```text
Bag {
  id, kind, slotCount,
  maxWeight, maxVolume,
  acceptTags[], rejectTags[],
  acceptRule, capacityPolicy, stackRule,
  slots[ItemStack], extra{}
}
```

- `kind` 是自由字符串（`"backpack"` / `"chest"` / `"shop"` / `"quest"`……），引擎不解释。
- 内置 `acceptRule == "default"`：若 `acceptTags` 非空则物品须命中其一；命中 `rejectTags` 则拒绝。
- 内置 `capacityPolicy`：`"slots"` / `"weight"` / `"volume"` / `"slotsAndWeight"`（默认）/
  `"slotsWeightVolume"` / `"unlimited"`。
- 内置 `stackRule`：`"sameItem"`（默认）/ `"sameItemAndProps"` / `"never"`。

### EquipmentSet（`Equipment.h`）

```text
EquipmentSet {
  slots: slotName → ItemStack
  allowedTags[slotName] → tags[]   // 空 = 不限制
}
```

`equipFromBag` / `unequipToBag` 只搬运物品；是否把装备加成写进 `RPGActor` 属性，由游戏通过
`registerChangeHook` 或脚本在变更事件后自行处理——背包模块**不硬依赖** `rpg`。

## 操作语义

| 操作 | 行为 |
|------|------|
| `canAdd` / `addItem` | 按接纳规则 → 容量策略 → 优先填满可堆叠槽 → 再占空槽；允许部分成功 |
| `removeItem` | 按 itemId 从前往后扣减数量 |
| `removeAt` | 按槽位精确移除（可指定数量） |
| `move` / `swap` | 同容器内槽位移位或交换；目标可堆叠则自动合并 |
| `split` | 从一槽拆出数量到空槽 |
| `transfer` | 跨容器移动（先 canAdd 目标，再扣源） |

所有成功变更都会推入 `InventoryChangeEvent` 队列（`action` 为
`add`/`remove`/`move`/`swap`/`split`/`merge`/`transfer`/`equip`/`unequip`），供脚本
`poll` 风格读取；同时触发已注册的 C++ `ChangeHook`。

## 脚本绑定（`eve.Inventory`）

`inv <- eve.Inventory()`：

- 定义：`registerItemsFromJson` / `clearItemDefinitions` / `getItemDefinitionCount` /
  `hasItemDefinition` / `getItemMaxStack` / …
- 容器：`newBag(slotCount)` → `Bag`；`newEquipmentSet()` → `EquipmentSet`
- 事件：`getChangeEventCount` / `getChangeEventAction` / …（每次变更后由 System 写入，
  `clearChangeEvents` 或下次批量操作前由调用方清理）

`Bag` / `EquipmentSet` 暴露薄封装成员方法，风格与 `RPGActor` / `TileLayer` 一致。

> **坑 / 设计约束：** 与 RPG 模块相同——暴露给 Squirrel 的浮点一律用 `float`（或 lambda
> 包一层），不要直接绑 `double`（见 `RPG系统设计.md` 脚本绑定一节）。

## 非目标（v1）

- 不内置具体 UI（格子绘制、拖拽）——由 `ui` 模块或游戏脚本实现。
- 不内置掉落表 / 商店定价公式。
- 不做存档序列化统一格式（可用 `extra`/`props` + 游戏侧 JSON 自行落盘）。
- 不做脚本侧动态注册 accept/capacity/stack 回调（`std::function` 无法跨语言）；
  脚本可通过配置 `acceptTags` / `capacityPolicy` 名选用已注册规则。
