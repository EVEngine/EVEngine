# 寻路系统设计 — `map` Pathfinding

日期：2026-08-09
状态：已实现（`src/modules/map/Path*.{h,cpp}`）
存放：`docs/dev/`

## 目标

在现有 `map` 模块上提供**可扩展、与投影解耦**的格子寻路能力：

1. 单体寻路：A\*（支持不同拓扑与代价）
2. **群体寻路优化**：同目标多单位用 **Flow Field（势场）** 一次 Dijkstra，多次跟随
3. 适配不同地图结构：orthogonal / isometric / staggered / hexagonal
4. 可行走性与代价可配置（GID 屏蔽、动态遮挡、单元代价）

与现有模块关系：

- **消费** `TileLayer` 的尺寸、GID、`Config.orientation`（仅用于选择拓扑）
- **不替代** 投影 / 渲染：`tileToWorld` 仍由游戏在路径节点上自行换算
- 设计语言对齐 [模块设计.md](./模块设计.md)、[Tilemap设计.md](./Tilemap设计.md)：string key + 可插拔拓扑

## 非目标（一期）

- 连续空间 NavMesh / 动态避障（RVO/ORCA）
- 多目标冲突消解（CBS / WHCA\*）
- 分层门户 HPA\*（可后补；接口已按图抽象预留）
- Tiled `properties` 自动解析 walkable（游戏侧用 `blockGid` / `setBlocked`）

## 核心抽象

```text
Pathfinder (facade, 由 Map::newPathfinder 创建)
  ├─ PathGrid          可行走性 + 代价 + 尺寸（可绑 TileLayer 或纯自定义）
  ├─ PathTopology      ortho4 / ortho8 / hex（含 staggered 邻接）
  ├─ findPath (A*)     单体最优路径 → Path
  └─ buildFlowField    群体：目标反向 Dijkstra → FlowField
       └─ followFlow / findGroupPath*  各单位局部跟随
```

### 为何图抽象而不是写死 TileLayer

不同投影只改变**世界坐标**与**邻接关系**；寻路在**格子索引空间**进行。

| 地图 orientation | 默认拓扑 | 说明 |
|------------------|----------|------|
| Orthogonal       | `ortho4`（可选 `ortho8`） | 矩形四/八连通 |
| Isometric        | 同上 | 菱形是投影，tile 索引邻接同正交 |
| Staggered        | `hex` | 与 Tiled stagger 一致的六邻接 |
| Hexagonal        | `hex` | 同上，含 `hexsidelength` 的布局不进寻路 |

`setTopology("auto"|"ortho4"|"ortho8"|"hex")`；`auto` 按 layer orientation 选择。

### `PathGrid`

```text
PathGrid {
  width, height
  walkable[i] / cost[i]     // cost≤0 视为不可走
  blockedGids: set          // 绑 layer 时：GID ∈ set → 不可走
  blockEmpty: bool          // GID 0 是否阻挡（默认 true）
  topology + diagonal
  layer?: TileLayer*        // 可选；syncFromLayer() 刷新 walkable
}
```

扩展点：

- 不绑 layer：`newPathfinderSize(w,h)` + `setBlocked` / `setCellCost` → 任意逻辑网格
- 绑 layer：改瓦片后 `syncFromLayer()` 或 `setDirty` 后下次寻路自动同步
- 自定义拓扑：后续可注册 `NeighborFn`（一期用内置三种 string）

### 单体：A\*

- 启发：`ortho4` Manhattan；`ortho8` Octile；`hex` 六角距离
- 对角（ortho8）若两侧正交格阻挡则禁止穿角
- 失败返回 `nullptr` / 空 Path

### 群体优化：Flow Field

多单位、**同一目标**时，对每个单位跑 A\* 会重复扩展。

优化：

1. 从目标做一次 **0-代价 Dijkstra**（或均匀代价 BFS），得到全图 `integration`（到目标代价）
2. 每格指向邻接中 integration 更小的方向 → `FlowField`
3. 每个单位从起点沿 next 指针追溯到目标 → `Path`（O(路径长)）

复杂度：建场 O(W·H·log + E)，N 个单位各 O(L)；相对 N 次 A\* 显著更优。

`Pathfinder` 可缓存「同目标 + 未 dirty」的 FlowField，避免每帧重建。

### 脚本 API（无重载）

```squirrel
local map = eve.Map();
local layer = map.newLayer(32, 24, 16, 16);
// ... 填瓦片 ...

local pf = map.newPathfinder(layer);
pf.setTopology("auto");
pf.blockGid(1);              // 墙
pf.setDiagonal(false);       // ortho 是否八向

local path = pf.findPath(2, 3, 20, 18);
if (path != null && path.getLength() > 0) {
    local x = path.getX(0);
    local y = path.getY(0);
}

// 群体：同目标
local field = pf.buildFlowField(20, 18);
local p2 = pf.followFlow(field, 5, 5);
local nx = field.nextX(5, 5);
local ny = field.nextY(5, 5);
local c  = field.costAt(5, 5);
```

自定义网格（无 TileLayer）：

```squirrel
local pf = map.newPathfinderSize(64, 64);
pf.setBlocked(10, 10, true);
pf.setCellCost(11, 10, 2.5);
```

## 错误与边界

| 情况 | 行为 |
|------|------|
| 起点/终点越界或不可走 | `findPath` 返回空 Path（length 0） |
| 不可达 | 空 Path |
| 未知 topology 字符串 | 回退 `ortho4`，可查 `getTopology()` |
| layer 为空 | `newPathfinder` 失败返回 null |
| FlowField 未覆盖起点 | `followFlow` 空 Path |

## 测试

- ortho A\* 绕障最短（四向 / 八向穿角禁止）
- hex / staggered 邻接可达性
- FlowField：多起点同目标路径末端为目标，且建场次数语义上一次
- `blockGid` / `syncFromLayer` 刷新
- isometric layer + `auto` 拓扑等同 ortho 邻接
