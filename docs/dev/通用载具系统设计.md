# 通用载具系统设计 — `vehicle` + `weapon`

日期：2026-08-23
状态：已实现 Phase 1–4（分支 `codex/vehicle-system`）
存放：`docs/dev/`

## 目标

为 EVEngine 提供一套**通用载具框架**，覆盖：

1. **多种载具类型**：汽车 / 坦克 / 船 / 摩托 / 悬浮载具等——区别只在"移动模型"。
2. **武器节点**：载具模板声明武器挂点，运行时挂载 `weapon` 模块的武器实体；
   挂点可以是炮塔（限位+转速）、机枪座或固定挂架。
3. **多种游戏形态**：
   - 红警式 RTS（2D 顶视、命令队列、自动索敌）
   - 突袭式坦克战术（装甲区、穿透、履带破坏语义）
   - 战地式 FPS（座位、玩家驾驶、炮手瞄准/开火、3D 悬架）
4. **可扩展性**：玩家可注册新的移动模型 / 驾驶者 / 武器逻辑 / 伤害修饰器，
   也可以直接写 ECS System 挂在 `VehicleEntity` 上。

## 非目标

- 不做寻路（游戏侧用 `map` / `spatial` 或自己的寻路系统）。
- 不做网络同步与存档（事件队列 + 组件状态可序列化，留给游戏侧）。
- 不做轮子/履带的渲染表现（悬架状态可查询，渲染由游戏侧完成）。
- 一期不做物理关节轮（Box3D 有 wheel joint，物理模块尚未暴露，见"局限"）。

## 借鉴：Unity 第三方载具系统

| Unity 方案 | 借鉴点 | 本设计落点 |
|---|---|---|
| Edy's Vehicle Physics | 中央 `VehicleController` + 可选附加组件；轮子按角色（转向/驱动/刹车）区分；路面材质表 | `VehicleEntity` 中央实体 + 可选面（座位/命令/物理）；轮子槽位带 drive/steer 标记 |
| NWH Vehicle Physics 2 | 动力总成组件链 + `WheelUAPI` 抽象，任意轮子实现可插拔 | `IVehicleMobility` + `IVehicleDriver` 双注册表；`PhysicsBody` 组件抽象 2D/3D 后端 |
| Realistic Car Controller Pro | 从单一大类拆成模块化（教训：不做 God Class） | 移动/驾驶/伤害/挂点全是独立接口，实体只聚合数据 |
| Tork（开源街机方案） | Vehicle 中枢 + Core/AddOn 组件 + `GetAddOn<T>`；`IVehicleDriver` 输入接口 | `Mounts`/`Seats`/`Addons` 槽位 + 驱动者接口 |
| AVC / ARC | 同一控制器覆盖汽车/摩托/船与旋翼机 | 统一 `IVehicleMobility`，wheel/ship/track 只是注册名 |
| 坦克类资产（RTCP 等） | 炮塔独立瞄准、后坐、简化履带（非逐节物理） | `WeaponMount` 限位/转速 + 自动瞄准；track 用差速整体模型 |

## 模块与分层

```cmake
# weapon 独立成模块：建筑/炮台/步兵也能用
eve_declare_module(NAME weapon LAYER 4 SCRIPT Weapon SLOT weapon
                   GROUP 2d 3d)
# vehicle 依赖 weapon；physics 为可选依赖（纯 RTS 可裁掉）
eve_declare_module(NAME vehicle LAYER 5 SCRIPT Vehicle SLOT vehicle
                   DEPS weapon
                   OPTIONAL_DEPS physics
                   GROUP 2d 3d)
```

依赖方向全部向下（L5→L4→L0），`scripts/module_depgraph.py --check` 零新增反向边。
物理缺失时编译 `VehiclePhysicsAbsent.cpp`：轮式/履带回退 kinematic，`attachPhysics*` 返回 false，悬架 mobility 不注册。

## 实体与组件

沿用引擎惯例：**实体是纯数据，行为在 `*System` 静态类**。

### VehicleEntity

| 组件 | 内容 |
|---|---|
| `Identity` | 实例 id / 模板 id / 阵营 |
| `Definition` | 模板指针（模块注册表持有） |
| `Input` | throttle / steer / brake / handbrake / fire / aimYaw / aimPitch |
| `Motion` | x / y / heading（度）/ speed / arrived |
| `Health` | hp / maxHp |
| `Orders` | RTS 命令队列 |
| `Mounts` | 挂点槽位列表（挂点实体 + aimMode） |
| `PhysicsBody` | 2D/3D 刚体指针（不拥有）+ space |
| `SuspensionState` | 3D 悬架每轮压缩量 / 接地标志 |
| `Seats` | FPS 座位槽位（驾驶员/炮手/乘客） |
| `Flags` | destroyed 等 |

### WeaponEntity / WeaponMountEntity（weapon 模块）

`WeaponEntity`：Definition / State（弹药/冷却/装填/连发）/ Aim（炮口朝向）。
`WeaponMountEntity`：Identity（类型/节点路径）/ Limits（限位/转速/射界）/ State（挂载武器、当前朝向、destroyed）。
挂点独立成实体，炮塔被打掉 = 挂点标记 destroyed，不影响载具实体本身。

## 移动模型（IVehicleMobility）

```cpp
class IVehicleMobility {
public:
    virtual const char* name() const = 0;
    virtual void update(VehicleEntity& v, float dt) = 0;  // 读 input，写 motion/刚体
};
```

| 注册名 | 行为 | 物理 |
|---|---|---|
| `kinematic` | 顶视积分移动（RTS 默认） | 无 |
| `wheel` | 轮式：油门加速 + 转向 | 2D 刚体（速度写入）/ 3D 悬停 / 回退 kinematic |
| `track` | 履带：差速转向（左右履带 = throttle ± steer） | 2D/3D 刚体 |
| `ship` | 船：与轮式同构（语义留给水面游戏） | 2D/3D |
| `suspension` | 3D raycast 悬架：每轮向下射线，弹簧力+阻尼+驱动+侧向抓地 | Body3D + World3D::rayCastFiltered |

物理绑定：`vehicle.attachPhysics2D(v, world)` / `attachPhysics3D(v, world, heightY)`
（C++ 与脚本均可，physics 模块开启时可用）。车体形状类别位 = 2，
悬架射线掩码排除该位，避免轮子射到自己的底盘（物理模块新增
`Shape3D::setFilterBits` 与 `World3D::rayCastFiltered`）。

## 命令系统（RTS）

命令类型：`move` / `attack_move` / `attack` / `stop` / `hold`。
`move`/`attack_move`/`stop`/`hold` 会清空旧队列；`attack` 追加。
队首命令转成输入（朝向目标、到达半径、减速）；完成时推 `order_completed` 事件。
无命令时保留手动/座位输入——这是 FPS 直接驾驶与 RTS 命令共存的开关。

实现补充（已落地）：

- `move`/`attack_move` 接近目标时按距离和转向角减速，保证能进入 `arriveRadius`
  并真正停下（否则转弯半径大于到达半径时会绕着目标无限转圈）。
- `attack` 命令下 `aimMode=="auto"` 的挂点在射程内自动开火（`fireAt`），
  `attack_move` 只边走边瞄准。
- 武器弹匣打空、冷却结束且有备弹时自动开始装填（`reload_start`/`reload_end`
  事件照常推送），游戏侧仍可手动 `startReload`/取消。

## 驾驶与座位（FPS）

```cpp
struct PlayerControl { throttle, steer, brake, handbrake, fire, aimYaw, aimPitch };
class IVehicleDriver {
    virtual const char* name() const = 0;
    virtual bool sample(VehicleEntity& v, int occupantId, VehicleInput& out) = 0;
};
```

- 游戏每帧 `vehicle.setPlayerControls(playerId, ...)` 写入玩家输入。
- 内置 `player` 驾驶者：`VehicleSystem::setPlayerControls` 表 → 座位采样。
- 座位模板：`{ name, driver, cameraMode, mountIndex }`；`name=="driver"` 的座位写移动输入，
  `mountIndex>=0` 的座位控制对应挂点（瞄准 + 开火）。
- 相机模式（`first`/`third`/`orbit`）由游戏侧读取 `getSeatCameraMode` 自行实现，
  vehicle 模块不依赖 camera 模块。

## 武器挂点集成

- 模板 `mounts[]` 在 `newVehicle` 时通过 weapon 模块创建 `WeaponMountEntity` 并挂载武器。
- RTS：`attack`/`attack_move` 命令下，`aimMode=="auto"` 的挂点自动转向目标。
- FPS：炮手座位的 `aimYaw/aimPitch` 直接驱动挂点；`fire` 触发
  `Weapon::fire`（走武器冷却/弹药/连发管线）。
- 开火事件由 weapon 模块事件队列暴露，游戏侧播放特效/音效/生成弹道
  （`IProjectileService` 能力接口）。

## 伤害管线

```cpp
vehicle.applyDamage(v, amount, zone, sourceId);
```

流程：`IVehicleDamageModifier` 多重监听（游戏侧叠加规则，如科技减伤/暴击）
→ 装甲区倍率（`armorZones[]`，未命中默认 1.0）→ 扣血 → `damaged`/`destroyed` 事件。
已毁载具不再接受伤害。

## 数据定义（JSON）

```jsonc
{
  "id": "tank.t90", "category": "tank", "mobility": "kinematic",
  "maxSpeed": 120, "accel": 80, "turnRate": 90, "radius": 24, "maxHealth": 600,
  "armorZones": [ { "name": "front", "mult": 1.0 },
                  { "name": "side", "mult": 0.5 } ],
  "mounts": [ { "name": "turret", "weapon": "cannon.125", "type": "turret",
                "limits": [-180, 180, -8, 20], "rotSpeed": 45, "aimMode": "auto" } ],
  "seats": [ { "name": "driver", "cameraMode": "first" },
             { "name": "gunner", "cameraMode": "third", "mountIndex": 0 } ],
  "suspension": { "maxTravel": 0.25, "driveForce": 3000, "lateralGrip": 10,
    "wheels": [ { "x": -0.9, "y": -0.35, "z": -1.2, "radius": 0.3, "rest": 0.35,
                  "stiffness": 30000, "damping": 3000, "drive": true, "steer": true } ] }
}
```

武器模板见 weapon 模块：`logic`（hitscan/projectile/自定义）、伤害、穿透、射程、
散布、射速模式（single/burst/auto）、弹药（弹匣/备用/装填）、投射物参数、特效 id。

## 脚本 API 摘要

```squirrel
// RTS：命令驱动
vehicle <- eve.Vehicle()
vehicle.registerVehiclesFromJson(json)
tank <- vehicle.newVehicle("tank.t90", 120, 300)
tank.moveTo(400, 260)          // 模块方法亦可：vehicle.moveTo(tank, 400, 260)
tank.attackMove(500, 300)

// FPS：玩家驾驶 + 炮手开火
car <- vehicle.newVehicle("car.fps", 400, 300)
vehicle.enterSeat(car, 0, playerId)
vehicle.setPlayerControls(playerId, throttle, steer, 0.0, fire, aimYaw, aimPitch)
```

每帧：`vehicle.update(dt)` + `weapon.update(dt)`（先 vehicle 后 weapon，炮塔转动才正确）。

## 扩展点汇总

| 想加什么 | 怎么做 |
|---|---|
| 新载具类型（气垫船/潜水艇） | `Vehicle::registerMobility("hover", impl)`（C++） |
| 新武器（导弹/深水炸弹） | `Weapon::registerLogic("guided_missile", impl)`（C++） |
| 新驾驶行为（AI/触屏） | `VehicleSystem::registerDriver("ai", impl)`（C++） |
| 新弹道/特效 | 实现 `weapon::IProjectileService` 能力（C++ 或脚本） |
| 自定义伤害规则 | `cap::addListener<IVehicleDamageModifier>(...)` |
| 隐形/修理/雷达等玩法 | 游戏侧 ECS System + 自建组件挂到 `VehicleEntity` |
| 脚本自定义逻辑 | JSON 数据驱动 + `eve.view(eve.VehicleEntity)` 遍历实体 |

## 局限与后续

- 3D 悬架是简化模型：不读回俯仰/侧倾、轮子无碰撞体、履带无视觉滚动。
  后续可在物理模块暴露 Box3D wheel joint 与更完整的 raycast 轮。
- 船只有 2D/3D 同构移动，没有浮力/水流；浮力可仿照悬架用 raycast 实现。
- 网络同步/存档未做；事件队列 + 组件状态足够序列化，游戏侧自行接入。
- 寻路未做；RTS 命令的目标点由游戏侧提供。
