# 战斗系统与动作编辑器

## 目标与边界

EVEngine 的战斗框架以现有 `action` 执行管线为中心，而不是引入统一的
`CombatActor`/`GameObject` 继承根。技能、武器和 AI 命令继续作为适配器提交
`ActionRequest`；标签、属性、消耗、效果、动画、音效、特效和相机仍由各自模块拥有。

设计借鉴 Combat System Framework 的数据驱动能力、Gameplay Tag、属性/效果组合及动作时间线工作流，
也吸收通用 Action Editor 将动画、攻击判定、特效、音频、相机和打断事件放到同一时间轴的做法。
EVEngine 的差异是：运行时和编辑器共享同一个版本化资产模型，表现模块只消费类型化事件；
`action` 不向上包含 animation/audio/graphics/camera，从而保持模块裁剪和后端无关性。

## 运行时模型

`ActionDefinition` 是动作的权威定义，保留既有的条件、目标选择、成本预留、效果准备/提交和阶段状态机，
并可附带一个 `ActionTimeline`：

- schema id：`eve.action.timeline`
- 当前版本：`3`；v1/v2 资产在解码候选中迁移，保存时统一规范化为 v3
- 动作总时长必须精确等于 `windup + active + recover`
- 轨道类型：Animation、Gameplay、Effect、Audio、Camera、Movement、Tag、Custom
- `ActionNotify` 表示单点事件；`ActionNotifyState` 表示有明确 Enter/Exit 的区间
- 事件按时间、边界种类、轨道 id、条目 id 稳定排序；静音轨道不投射事件
- `ActionRuntime::advance` 使用注入的确定性 `Duration` 采样 `(previous, current]`，首次启动可包含零时刻
- `ActionRuntime::advance` 同时返回当前激活区间的拥有型 `ActionActiveBlock`，包括局部时间与区间时长

投射结果拥有自己的 payload，不借用热重载定义中的指针。下游适配器根据 `type` 和 payload 处理伤害窗口、
输入缓冲、碰撞忽略、运动扭曲、VFX、音频或镜头，不需要 `action` 依赖这些提供方。

`ActionBlockRuntime` 将同一个 advance 依次投递为 Enter/单点事件、持续 Update，并按 execution 保存最后一份
激活投影。动作被打断时，宿主调用 `interrupt`，它会为仍激活的区间补齐 Exit；已经成功退出的条目立即从
清理集合删除，因此失败重试不会重复退出它们。编辑器跳转使用 `sample`，该路径强制设置 preview/scrubbing
上下文，handler 契约禁止产生持久副作用。handler 由 `ActionNotifyRegistry` 共享持有，回调同步发生在 owner
thread，不得保存借用参数或重入同一个 `ActionBlockRuntime`。

Audio、VFX 与 Prefab Spawn 共用 `ActionSpatialBinding` 解析 payload 中的空间字段：`attachment` 支持
`follow_target`、`follow_position_only`、`world_transform_at_start`；`spatialTarget` 选择 `source` 或
`target`，后者可配 `targetIndex`；`bone` 保存稳定骨骼/插槽名；`positionOffset`、
`rotationOffsetDegrees`、`scale` 是三个有限数值组成的数组。scale 必须逐轴大于零。该值只保存拥有型数据，
实体 handle 与骨骼名由具体表现模块在每次同步调用时解析，不把 Scene/Bone 裸指针跨帧带入 action 核心。

`presentation:vfx-state` 已由 Particles provider 创建并独占真实 `ParticleEffect`，在 Enter 启动、Update 同步偏移、
Exit/interrupt 停止并销毁；`presentation:audio-state` 由 Audio provider 独占解码后的 `SoundData` 与 `Source`，
并按相同边界播放和清理。单点 `presentation:vfx` 要求正的有限 `lifetimeSeconds`，单点
`presentation:audio` 以解码片段时长除以 pitch 得到截止时间且禁止 looping；需要循环的资源必须使用
NotifyState。两类单点资源在触发后保留，由 handler 按 action `Duration` 确定性过期并停止销毁，
不读取墙上时钟。provider 是可选模块能力：未创建对应模块时 descriptor 仍可编辑，但运行 dispatch
明确返回 handler `NotFound`。Scene 通过 `IEntitySpatialProvider` 将 generation-qualified `SceneObject` handle
解析为当前世界姿态；`follow_target` 每次 Update 同步完整姿态，`follow_position_only` 只同步位置，
`world_transform_at_start` 固定 Enter 时的姿态。没有任何 provider 接受该实体时返回 `NotFound`；Scene 根节点
收到非空 `bone` 时由宿主在同步 `ActionNotifyContext` 中提供借用的 `IAttachmentPointSource`；Avatar 已实现该
接口并按语义骨骼名或原生骨骼名采样最新姿态。骨骼局部 position offset 由该接口转换到世界坐标；上下文引用
只在本次 dispatch 有效，handler 不保存指针。没有 attachment source 时返回 `Unsupported`，不会静默退化到对象原点。

Prefab Spawn 使用内置状态类型 `gameplay:prefab-spawn`。`ActionPrefabSpawnBinding` 先原子校验非空
`uri`、空间字段与 `lifecycle`；生命周期可取 `recycle_on_block_exit`（默认）、`custom_duration` 或
`independent`。`custom_duration` 还必须提供正的有限 `customDurationSeconds`。SceneLoader 的可选 provider
通过 `Model3D` 解码 URI，并为每个网格创建真实 `Renderable3D`；同 URI 回收后复用 ECS 实体和 GPU 资源，
但逻辑 lease 每次回收都会递增 generation，旧 lease 不能再更新新实例。运行时在 Enter 解析骨骼/目标世界姿态，
Update 按 attachment 模式同步，Exit/interrupt 对 `recycle_on_block_exit` 隐藏回池；`custom_duration` 按注入的
action `Duration` 维护到期，`independent` 则脱离动作块并保持可见。provider 缺失时 descriptor 仍可编辑，
dispatch 明确返回 `NotFound`。独立实例通过 `IActionPrefabInstances` 暴露拥有型检查记录和 generation-qualified
handle；外部系统可调用 `recycleIndependent`，回收后旧 handle 稳定返回 `NotFound`，不能越权回收仍由动作块
持有的实例。实例池随 SceneLoader 启停并撤销 capability，registry handler 不再决定独立实例寿命。
预览 `sample` 仍只校验且不生成 ECS/GPU 副作用。SceneLoader 另以
`IActionPreviewSinkProvider` 提供 Editor 专用预览层：`prepare` 在不可见的独立池中加载真实
`Renderable3D`，`present` 才原子切换可见实例；跳帧、离开区间或销毁编辑器都会立即回收预览实例，
并且 `custom_duration` 按 block local time 隐藏。该池与运行时 Prefab 池分离，不会把预览对象变成
`independent` 游戏实例。多个 Audio/VFX/Camera/Scene provider 可按 listener 顺序组合预览层，
不存在单一 factory 抢占其它表现模块的问题。

## 持久化约定

编码器接受 v1-v3，未知更高版本返回结构化 `Result` 错误；同版本未知字段在读取时忽略，
规范化保存只写出 v3 已知字段。v3 增加多动画分段的源裁剪、混合曲线、物理分段、循环/层/Foot IK 和 Root Motion 遮罩。
根对象的 `metadata` 与每个事件的 `payload` 是扩展数据的正式位置。
解码先构造并完整校验候选值，再发布结果，不会留下部分修改。

稳定 id 在轨道、Notify 和 NotifyState 范围内全局唯一。时间必须非负且落在动作时长内；区间要求
`start <= end`。这些约束同时用于磁盘读取、运行时提交和 Editor 事务提交。

## Editor 动作编辑器

`ActionTimelineEditor` 是 UI 工具包无关的动作编辑控制器。`configureWorkspace` 会原子安装四个语义面板：

- 左侧 Actions 资源列表
- 中央 Action Preview 预览
- 右侧 Action Inspector 属性面板
- 底部 Action Timeline 时间线（默认活动面板）

宿主可以用 `ui`、ImGui、Web UI 或自动化客户端渲染同一组描述。控制器已经提供：

- 新建语义轨道、Notify 和 NotifyState
- 轨道锁定保护、静音切换、条目移动和删除
- 框选、多选、复制、粘贴以及稳定的新 id
- 每次修改通过 `action.timeline.replace` 可逆 DomainOperation 提交
- Undo/Redo 通过 `LocalWorldAuthority` 与 `LocalTransactionBackend` 执行，不维护第二份资产状态
- Play/Pause/Seek/Update 预览传输，以及本帧跨越的拥有型事件列表
- 时间标尺、帧/时间吸附、围绕锚点缩放与有界平移
- 轨道增删改名、静音和锁定，以及动画分段的 Trim In/Out 和 Blend Curve Inspector
- 框选/追加多选后拖动整体，或用 `Shift+[` / `Shift+]` 对齐开始/结束；锁定轨道会使整个批处理原子失败
- 多选 Inspector 编辑外层 Start/End 时按相对位置等比缩放全部条目，精确到纳秒并作为一次可撤销事务提交

运行宿主由 `ActionRuntime` 唯一负责 gameplay 时间与激活状态，`ActionBlockRuntime` 路由 Enter/Update/Exit，
`MontagePlayer` 只消费同一份 advance 中的事件和 `ActionActiveBlock` 并驱动多 Clip 姿态，不再自行计算第二份激活状态。
`MontageCoordinator` 每层固定两个槽位做 ping-pong 混合，generation handle 在槽位复用后拒绝旧引用。运行时支持跳转、物理分段同步、
暂停、中断混出、低帧率边界扫描和循环尾/头两段扫描。Clip 热更新先完整验证候选，再原子替换并保留当前时间、权重与执行身份。

## 生命周期与线程约定

`ActionTimelineTarget` 是可变时间线的唯一权威 owner。编辑器及其 target、authority、transaction backend
同生共死，所有方法仅允许 owner thread 调用。接口不持有跨帧临时指针，不在锁内调用脚本或未知回调。
热重载应先用 `ActionTimeline::fromValue` 构造有效候选，再替换整个 target；运行中的
`ActionTimelineEvent` 因拥有 payload，不会因定义替换而悬空。

## 后续表现层扩展点

3D 模型预览、Root Motion 轨迹、波形和特效缩略图应实现为消费上述公开状态的面板适配器；
它们不能成为动作资产 schema 的第二来源。新增内置 Notify 类型时，只注册稳定 `LogicalId` 及其 payload
契约，不在核心层加入表现模块 include。
# 战斗系统与动作编辑器

## Gameplay Tags

`tags::GameplayTagRegistry` 是标签定义的唯一权威所有者。标签名采用点分层级，例如
`Combat.Action.Attack.Light`；稳定 ID 由完整规范名的 64 位 FNV-1a 计算，并在载入时复核，
以免资源中的名称和 ID 漂移。注册表资源使用 `eve.gameplay-tags` schema version 1；未知字段
被忽略，未知版本、非法名称和不匹配的 ID 会导致整个候选注册表被拒绝，不会留下部分状态。

`TagStore` 保留原有精确匹配 API，并增加显式的 `IncludeDescendants` 查询。层级匹配只接受点
边界，因此 `Combat.Action.AttackHeavy` 不会命中 `Combat.Action.Attack`。编辑器侧的
`GameplayTagPicker` 借用同一个注册表并只持有筛选、根节点和选择状态；其返回值均为拥有型副本，
开发者编辑器和游戏内编辑器可以共享该模型而不产生第二份标签定义。

## Ability 授予与激活

`action::AbilityRuntime` 在通用 Action 管线之上拥有 Ability Definition、Owner Grant、冷却和
Activation Link；`ActionRuntime` 仍然是动作阶段的唯一所有者。Ability 可选择 NonInstanced、
PerOwner 或 PerExecution 实例策略，并通过 Independent、ExclusiveReplaceable、
ExclusiveBlocking 三种组规则控制并发。替换行为使用注入的 simulation tick 取消旧 Action，
不会读取墙钟。

冷却只由调用方传入的 `Duration` 推进。Gameplay Event Trigger 使用层级 Gameplay Tag 的点边界
匹配，首先返回确定性排序的 Grant ID，再由调用方附加目标参数并显式激活，避免一次事件分发在多个
Action 中途失败时留下不可解释的部分提交。Grant 到 Definition、Activation 到 ActionExecution 都是
强类型 Link；终态通过 `synchronize()` 清理，任一销毁顺序都能检测缺失或终态引用。

## Damage、Poise 与 Hit Reaction

`combat::DamageRuntime` 对一个聚焦的 `CombatState` 组件值执行事务式结算，不引入 CombatActor 或
GameObject 根类。Damage Request 使用 `SubjectRef` 表示来源/目标，可携带只用于审计的
`ActionExecutionId` Link；目标领域仍负责 SubjectRef 的解析、销毁和恢复。

默认路径直接应用生命、韧性与击退，项目也可注入 `IDamageRule` 进行护甲、抗性、暴击或难度修正。
Provider 在任何状态修改前执行，返回值经完整校验后才一次提交；Outcome 的 `ruleSource` 明确记录
Default/Provider，缺少可选 Provider 是可观测的正式路径。受击反应优先级固定为 Death、Knockdown、
Stagger、Flinch、None，Poise 恢复是显式且有界的操作。该路径不读取时钟和 RNG；同一组输入只经过
这一套 double 运算，回放保存其最终值。

## Notify 与 NotifyState 注册表

`action::ActionNotifyRegistry` 是 Notify 类型契约的唯一权威所有者，同一份 descriptor 同时供
Editor 列表、payload 校验与运行时路由使用。内建契约覆盖 Gameplay Event、Damage、VFX、Audio、
Camera，以及 Hitbox、无敌、Combo、碰撞忽略和 Root Motion 区间；区间类型明确校验 Enter/Exit，
不会被当成单点事件误用。

扩展类型必须使用与 Timeline 一致的 `namespace:name` LogicalId，并声明必需 payload 字段。路由前先完整校验，缺少
handler 与 handler 返回的失败都是可观测 `Result`；注册表以 `shared_ptr` 持有 handler，每次 apply 在
边界事件和持续 Update 之后按类型字典序维护 handler，共享实例只执行一次，失败向上传播。所有方法
限 owner thread 调用，插件卸载前必须先显式注销，不保留事件或 context 的跨帧借用引用。

## 可交互 Timeline Widget

`editor::ActionTimelineWidget` 将权威 Timeline 投影为宿主坐标中的轨道、Notify、NotifyState 和播放头，
通过 `IEditorOverlay` 输出矩形、手柄、文字与标记，不依赖 ImGui 或特定渲染后端。开发者 Editor 和
游戏内 Editor 只需实现同一组 overlay/inspector 接口即可复用它。

鼠标命中区分单点本体、区间本体和左右手柄。Drag 期间只保存 Widget 的拥有型预览值，
Pointer Up 才通过 `ActionTimelineEditor` 产生一个可撤销事务；Cancel 不修改资产。Inspector 先同时校验
时间、LogicalId、JSON payload 和 Notify descriptor，然后一次替换条目，不会在后续字段失败时留下
部分时间修改。

Widget 还提供 Copy/Paste/Delete/Undo/Redo/PlayPause 的右键菜单描述和快捷键路由，粘贴以播放头
为锚点；新建条目只能从注册表中选择形状匹配的类型，并在提交前校验必需 payload。

## 事务式动作预览

`editor::ActionPreviewController` 通过 `action::IActionPreviewSink` 将权威播放头、动画资源 URI、
VFX/Audio/Camera cue、状态边界和当前位置的 `ActionActiveBlock` 组合成拥有型 `ActionPreviewFrame`。
宿主先在 `prepare` 中验证并暂存
一帧需要的资源，时间线仍未改变；只有准备成功后才提交播放头并调用不可失败的 `present`，因此资源失败
不会造成画面和时间线各走一半。若准备后发现 revision 或播放头已变化，控制器调用
`discardPrepared` 并返回结构化冲突。

Root Motion 由可选 `action::IActionRootMotionSource` 提供。缺少 Provider 会在帧中明确标记
`Unavailable`，不会静默生成零轨迹；Provider 返回拥有型三维采样点，Controller 可通过
`IEditorOverlay` 绘制路径。Controller、Editor、Sink 和 Provider 都由宿主拥有并保证生命周期，
接口仅允许 owner thread 调用，不跨帧保留输入引用，也不在锁内调用未知回调。

脚本 `ActionTimelineEditor` 会组合当前已注册的全部 `IActionPreviewSinkProvider`，并让
`seekSeconds`、`seekX`、`update` 统一经过 Controller；`hasPreviewHost()` 可观察是否存在 3D/音频等
预览层，`refreshPreview()` 用于资产参数事务提交后在当前播放头重建投影。没有 provider 的裁剪配置
仍保留纯时间轴编辑，但该状态不会伪装成已经具有表现预览。

其可选 Montage runtime 只把 registry 中实际安装了 handler 的事件和 active blocks 交给
`ActionBlockRuntime`，用于驱动当前编辑器进程拥有的 Audio/VFX/Prefab 表现并维护到期资源；没有安装
handler 的 gameplay 语义仍完整保留在 `MontageAdvance` 中交给项目宿主消费，编辑器不会伪装执行伤害、
输入或碰撞规则。跳转、循环重启、取消和脚本对象释放都会对已路由 block 补齐 interrupt 清理。

完整 3D 配置可使用 `editor::AnimationRootMotionPreviewSource`。它按 URI 在
`animation::AnimClipRegistry` 中即时解析唯一 Clip，并采样指定 root bone 的局部位移；不缓存 Clip
指针，所以 Clip 先销毁时下一次采样得到明确 NotFound，Clip 热重载则沿用 Registry 维护的稳定实例。
同一 URI 存在多个 Clip 会以 Conflict 拒绝，避免预览结果依赖注册顺序。裁剪掉 animation 模块时，
同一适配器返回 Unsupported，Editor 核心仍可独立使用。

## Projectile 与对象池

`weapon::ProjectileRuntime` 提供 Linear、Ballistic、Homing 三种确定性弹道，并使用固定容量、generation
校验的 slot pool。Spawn、显式 Release 和生命周期到期都通过结构化 `Result`/Handle 工作；slot 重用会
提升 generation，因此旧 Handle 不会误指向新弹丸。池满、非法参数和 stale handle 都是可观测失败。

`update` 只消费注入的 `Duration`。Homing 通过可选 `IProjectileTargetProvider` 解析 ECS generation handle；
整批状态先在候选副本中推进，任一目标失效或 Provider 失败都会拒绝整帧且不发布部分位移。运行时不拥有
目标、不持有跨帧裸指针，也不调用墙钟或隐式 RNG。相同编译器/后端输入要求逐步确定；跨后端回放按项目
声明的位置容差比较。

需要把弹道与攻击语义解耦、用行为组合拼装穿透/引信/分裂/弹跳时，使用并列的
`weapon::CombatCarrierRuntime`：配方由 motionOps（弹道算子）+ triggers（时机）+ impacts（效果）组成，
命中探测经 `ICarrierHitProbe` 注入，伤害以拥有型 `CarrierEvent` 交给游戏或 `combat::DamageRuntime`
适配。详见 [`战斗载体与投射物行为组合框架.md`](./战斗载体与投射物行为组合框架.md)。
`ProjectileRuntime` 仍保留给只需三种轨迹、自行处理碰撞的调用方；
`carrierRecipeFromProjectile` 可将旧定义桥成默认载体配方。

## 玩家与 AI 动作控制

`action::AbilityControllerRuntime` 是玩家输入和 AI 决策共用的能力激活入口。玩家侧使用
`PlayerAbilityIntentQueue` 维护拥有型 FIFO 意图；AI 侧实现 `IAbilityIntentSource`，按注入的
`SimulationTick` 返回零个或一个拥有型意图。控制层覆盖请求的 `requestedTick` 并统一调用
`AbilityRuntime::activate`，因此冷却、实例化、互斥组和 Action 生命周期仍只有一个权威所有者。

意图源失败时不会改变 AbilityRuntime；意图一旦由 Source 交付便按 exactly-once 消费，即使激活被拒绝
也不会隐式重试。接口不保留 tick、request 或 ECS 裸指针，调用时不持有引擎锁。

## 战斗属性、再生与事件

`combat::CombatAttributeRuntime` 在通用 `attributes::AttributeSet` 之上提供 Gameplay Tag 寻址的 Health、
Mana、Stamina 等战斗属性。每个定义声明初值、上下界和每秒再生率；注册、设置、增减和再生都返回结构化
`Result`，无效输入不会发布部分状态。

`advance` 只消费注入的 `Duration`，按标签字典序提交再生。每次实际变化返回拥有型 Gain/Loss 事件，
首次到达下界额外返回 Depleted；运行时不持有监听器或调用未知回调，UI、音效和游戏逻辑可在提交后安全
消费事件。属性运行时是其 `AttributeSet` 与定义的唯一 owner，不向外暴露可变引用。

## 标准战斗能力目录

`combat::standardCombatAbilities()` 提供 20 个经过校验、可直接注册到 `AbilityRuntime` 的标准原型：
轻/重/蓄力/空中/按住攻击、格挡、招架、闪避、冲刺、跳跃、二段跳、传送、投掷、远程攻击、装备、
卸下、治疗、Buff、受击反应和死亡。目录定义身份、Windup/Active/Recover、冷却、实例策略、互斥组与
适配器类别；项目通过同一 Action Timeline/Notify 与执行器绑定动画、位移、伤害和表现资源。

这些原型没有复制 Unity CharacterController 或特定动画资源，也不宣称是完整游戏内容；它们是引擎原生、
后端无关的可注册起点，避免示例目录成为第二套运行时规则。
