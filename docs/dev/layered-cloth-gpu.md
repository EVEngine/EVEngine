# Vulkan GPU 多层布料

这是 CPU 原型之后的真实计算后端。位置、历史位置、约束乘子、散列与最终顶点流驻留在 GPU；模拟和绘制不回读坐标，也不逐帧调用 CPU `updateMeshVertices`。CPU 仅记录命令、提交参数；`readPositions` / `readDiagnostics` 是显式诊断操作。

## 架构与并行约束

`LayeredClothGPU` 位于原 `physics_cloth` 卫星，通过 Pimpl 独占 8 个缓冲、计算程序与 Sequence；借用已存在的 Gpgpu、Graphics，两个 provider 和 Vulkan device 必须在组析构后才关闭。全部 API 在渲染/提交线程调用，不回调、不支持并发。

每个子步：积分与乘子清零 → 多轮 XPBD 距离约束 → GPU 散列重建 → 接触汇总/权重归约 → Jacobi 连续点面/边边接触与摩擦。每轮输入位置只读，输出另一个缓冲；每个线程只写自己的位置与自己持有的有向边乘子。结构、剪切和距离弯曲共 12 邻居，采用 0.2 松弛。乘子在子步内保留，不像 CPU 组合原型在每轮耦合重新初始化。默认顶边逆质量为 0。

接触线程先累计自身顶点对其它三角形的修正，再遍历自身相邻三角形，累计其它顶点作用于这些三角形的反作用。重心梯度和逆质量分母与点面约束一致，避免浮点原子加和多线程写同一顶点。接触计数有整数原子操作；链表顺序仍可能变化，不承诺跨运行 bit-exact。当前 CPU/GPU 对照只验证自由落体/积分，不声称两种材料或接触算法全等价。

## 散列、溢出与范围

- 哈希坐标不限于固定世界包围盒，完整整数 cell 坐标随条目保存，哈希冲突后再检查坐标。
- 顶点与三角形都按厚度扩展子步起点到当前迭代位置的运动 AABB，插入覆盖的 cell。点面、反作用和边边查询使用运动包围盒；以双方包围盒交集的首个 cell 为唯一计数位置，避免重复修正。边候选复用三角形散列，不额外存边表；每条拓扑边由唯一三角形拥有。
- 条目预算为 `32*(N + T)`。某点或面需要超过 64 个 cell 或预算不足时，GPU 标记溢出，当前轮在 GPU 全扫描，不进行 CPU 回退，也不静默丢接触。`readDiagnostics` 的末项记录溢出事件。
- 该路径保证不因散列容量而忽略候选，不代表保证无穿透。高密度或溢出时仍可退化为二次复杂度。
- 当前只支持规则网格，最多 8 层、单边 128 点，并要求各缓冲不超过 128 MiB；不意味着所有上限组合都能分配。没有任意网格 GPU 烘焙、缝合或初始交叉消解。
- 风目前是统一加速度；有可配置地面平面，但未迁移 CPU 的三角形空气动力、skin/backstop、撕裂及刚体双向接触。

## 连续接触的数值契约

点面和边边都使用保守推进：以相对顶点位移的最大长度作为距离变化上界，沿子步内线性轨迹推进；接触容差为 `max(厚度*1e-4,1e-7 m)`，最多 64 轮。达到轮数上限采用最后采样的保守接触方向，可能提前限制运动；不是精确算术 CCD，也不宣称任意极端变形绝不穿透。没有固定时间采样间隔。检测和响应仍受外层 Jacobi 预算约束：高速跨面回归用 48 次接触迭代验证收敛，默认 8 次不能视为零残余穿透保证；目前也未单独回读保守推进达到上限的次数。起点已进入接触壳时保留起始侧，避免下一步高速穿越后按终点侧推出。

使用首次接近时的重心/线段权重和法线，约束终点的有符号间距。边的两个端点以及对方两个端点按权重和逆质量分配反作用。双方 gather 始终以同一个规范边对顺序求解，避免平行/退化线段最近点不唯一造成配对不一致。无浮点原子累加。地面夹取在接触修正后再次执行，避免最终接触轮把粒子推入地面。

仍未完成：持久接触流形、静/动摩擦分离、接触岛独立缩放、精确退化几何谓词及初始交叉修复。共享固定点构成外部支撑，只有所有参与顶点都自由时才要求封闭系统质量中心守恒。空间散列全局扫描的性能突变仍存在。

## 密集接触稳定化

固定 `0.2` 系数直接累加所有接触时，约束数量增长会放大单轮位移。本轮增加两阶段 GPU 求解：先 gather 修正及质量缩放后的块行和上界，再归约出全局上界，最后统一缩放所有粒子的接触修正。没有按各粒子的接触数分别除法，因为不同缩放会破坏接触双方的配对反作用。

对一个接触，令逆质量为 `w_i`、标量位置梯度的绝对值为 `g_i`（点面为 `1` 和三个重心权重，边边为四个线段权重），分母 `D=sum(w_j*g_j²)`。粒子行权重为 `sqrt(w_i)*g_i*sum(sqrt(w_j)*g_j)/D`。每粒子累加其接触行权重后，整数 `atomicMax` 归约正浮点位模式得到 `R`。共同缩放系数为 `min(0.2, 0.9 / (max(1,R)*(1+摩擦系数)))`。这是冻结接触梯度时的保守松弛及摩擦余量，不是完整非线性系统的全局稳定性证明。

mode 6 汇总修正，mode 4 应用。每次接触迭代新增一次 dispatch；不新增提交或逐帧 CPU 读回。最终顶点缓冲的前 `16*N` 字节暂存 `vec4(修正,行权重)`，最终 mode 5 全量覆盖成绘制数据；旧帧的读取和新 scratch 写入仍由同队列屏障排序。Stats 内部缓冲从 16 扩至 32 字节，前四项公开诊断布局不变，额外槽仅作 GPU 工作状态，每轮清零；没有新增公开 API。

已复现的 8 层、1 mm 间距、10 cm 厚度场景，旧单轮最大修正 `0.8064 m`，新值 `0.0432 m`，质量中心误差小于 `1e-6 m`。极端质量比尚未系统扫描；当前不等质量覆盖来自边接触与折叠回归。单层回折用例在 96 轮内收敛到 8 cm 分离，最大修正约 5.7 cm。

一分钟自由下落回归使用四层、16 粒子、2 子步、8 迭代、地面和摩擦，1800 个 `1/30 s` 步长。布料可以滑开，平均高度相同不能当作穿透；独立双精度三角形几何距离检查每 4 秒取一次样，验证最小间距与最终分离。距离 oracle 覆盖面内投影、边界距离和边穿面，并有平行面、相交、退化点/线的已知结果测试。离散采样和有限小网格仍不能证明所有时间点、复杂服装拓扑或分钟级剧烈折叠无穿透。

代价与限制：全局 `R` 会让一个密集接触区域降低其它区域的收敛速度；后续应按接触岛求预算。它控制过冲，不消除低迭代预算的残余穿透，也不提供静摩擦的持久锚点。当前地面仍是位置夹取，没有地面切向摩擦模型，无侧向约束的多层布料可能在落地后滑开。

## 计算到绘制

末次 dispatch 从当前状态生成双面顶点，法线、UV、层颜色均由 GPU 生成。驻留流是 22 个 32-bit word 的顶点 ABI，Vulkan 实现对 `MeshVertex` 的 stride 和关键 offset 做静态断言。rest mesh 和索引只上传一次；每帧直接绑定计算输出作为 VBO。

新 `storage_vertex` 用途增加 Vulkan VERTEX_BUFFER 使用标志。Sequence 发现该用途时将整批录制工作提交到 graphics queue，包括录制的初始上传、计算和可选诊断下载；不使用异步计算队列。计算 dispatch 前后有 all-commands memory barrier，按同队列提交顺序覆盖先前顶点读取与之后计算写入，再覆盖计算写入与之后绘制读取。单次 update 等一次提交 fence，没有逐 dispatch 的 CPU 同步。

`drawMeshResidentVertices` 只在同步记录 draw 的作用域借用 buffer handle，不持久更换 Mesh 的资源或所有权。调用者保证 native buffer 来自同设备且带 vertex usage；检查后端、mesh owner、布局、容量和开放渲染 pass。生产者必须活到已提交帧完成；组只允许在最后一次 draw 的帧已经 present 后析构，不能在仍录制的 pass 中销毁。组析构执行一次 graphics-queue retirement dispatch/fence 后释放资源，Graphics/device 必须仍有效。GPU 错误不会退回 CPU；失败 update 返回 Result，脚本适配器检查后抛出带诊断异常。

该直接绘制路径不自动参加 ECS 阴影、运动矢量或 GPU-driven 实例剔除。其它 Graphics 后端默认返回 Unsupported。

## 接口边界与所有权

没有新增模块、ECS System、Link、持久化格式或通用 registry。模块六面变化：脚本面新增 `eve.LayeredClothGPU`，Graphics 增加借用 resident VBO 绘制方法，Gpgpu 增加 Vulkan buffer usage 与同队列调度约定；能力 provider、事件、工具协议、ECS/Link 面未新增。现有 cloth→graphics/gpgpu 依赖方向保持不变。没有宣称新的裁剪级别，也没有静默豁免架构规则。

```nut
local clothModule = eve.Cloth();
local compute = eve.Gpgpu();
local sheets = eve.LayeredClothGPU(compute, gfx, 3, 20, 16, 0.12, 0.09, -1.14, 2.6, -0.9);
sheets.setSolver(2, 8);
sheets.setContact(0.05, 0.25);
sheets.update(1.0 / 60.0); // 在渲染 pass 前
// 打开并设置正确相机状态的 3D pass 后：
sheets.draw();
```

参数控制：`setGravity`、`setWind`、`setFloor`、`setInterCollision`、`setSelfCollision`、`setParticleInverseMass`、`reset`。C++ 的 `update` 与 `draw` 返回必须检查的 `Result<void>`。dt 为 0 或有限的 [1e-6, 0.05] 秒；拒绝更小的正步长以避免子步平方下溢导致 XPBD 分母无效，0 不推进。`reset` 恢复初始位置、固定点与单粒子质量修改；组级 gravity/wind/contact 参数保留。

## 验证

专项测试在 `test/integration/layered-cloth/physics_layered_cloth_gpu.cpp`，使用真实窗口、Vulkan compute 与 resident drawing，无 mock、无 provider 不可用时的跳过。覆盖积分参考与 CPU 对照、固定点/重置、质量反作用/关闭接触、显式溢出 GPU 扫描、驻留顶点绘制。软件 Vulkan 只能证明执行路径和数值行为；不据此报告实体 GPU 帧率。

首版 5 项 GPU 测试、339 条断言通过；第二轮增加高速穿面、边中段交叉、接触壳起步、反向穿越、有限退化边、摩擦、自接触过滤、散列容量耗尽与扫描对照，以及 124 步有限状态/固定点/计时检查。第三轮密集接触、回折、一分钟自由下落及独立几何校验，共 15 项、3900 条断言通过。正式结果与环境限制见 [验证记录](layered-cloth-gpu-validation.txt)。
