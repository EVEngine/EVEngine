EVEngine整体架构
============

### 目标

提供 C++20、Vulkan/WebGPU 后端、Squirrel 脚本和可裁剪模块组成的 2D/3D 游戏引擎，支持运行时内容编辑、资源热重载和领域状态恢复。热重载与存档按各域的所有权、版本和失败合同实施，不承诺任意对象、任意帧均可自动恢复。

> 2026-11-11 源码核验：本页描述结构与已存在的能力；具体欠项以[模块设计](模块设计.md)及各领域设计文档为准。勾选表示实现存在，不代表本轮执行了所有宿主、后端或平台验收。

### 基本技术选型

框架 C++20、cmake、zeroerr

脚本语言 squirrel
  一款带类和多态的脚本语言非常适合游戏，这个语言本身也是为此而设计的

脚本绑定 simplesquirrel
  这个绑定库非常好用，可以简单地把C++类导出并支持squirrel继承C++类

图形系统 vulkan
  vulkan是opengl的替代，选用其的主要原因是mac下opengl不再更新，并且不能使用compute shader
  vulkan整体写起来复杂，但优化上限较高，潜力很大


### 核心特性

1. 类似love的简版引擎，可选节点树支持
2. 解释运行，在文件夹中放好脚本和资源，直接在当前目录就可以用引擎运行游戏
3. 热重载，随时监听文件系统变动，脚本和资源改变时可以不重启引擎直接刷新
4. 状态热更新，通过已接入的领域 provider、快照与显式恢复合同保存/重建状态；未接入的对象不自动获得该能力
5. 运行快照与开发回放，在受支持的脚本根/领域状态边界捕获、恢复和重放；外部资源、solver 缓存与跨平台确定性按各域合同声明
6. 脚本反射，假如你继承了类，可以根据模型自动生成编辑用的GUI
7. ORM模型，在有数据库的时候会联动数据库
8. 开发工具，可以在运行时临时修改对象的状态，并提供写入初始数据的功能

### 模块组合与状态边界

模块声明来自 `cmake/module_manifest.cmake` 及其有序片段；启动列表、链接闭包与第三方依赖从同一清单派生。runtime 与 editing/editor 卫星分离。可裁剪性必须说明 L1 编译、L2 链接、L3 运行或 L4 可观察证据，不能从目录或 include 图直接推断。详见[模块编排与裁剪架构](模块编排与裁剪架构.md)。

ECS 使用领域短根、组件和 typed Link/Handle；Scene、渲染、物理与玩法各自拥有其权威状态。跨域引用需定义代际失效、双方销毁及恢复重建。低层调用高层通过消费方接口与 capability 组合，禁止新增向上的模块 include。

### 接口设计原则

本节以现行架构规范为准，替代早期“所有对象由脚本析构”“优先字符串和多参数”的统一假设：

1. 可能失败的操作使用结构化 `Result`/Diagnostic；关键结果必须观察。查询真假才使用 `bool`。旧绑定的异常或 bool 形状不作为新 API 的模板。
2. 领域协议优先强类型值；脚本/工具边界再进行明确的字符串或 Value 投影。绑定名称可保持不重载，但不能牺牲类型、错误和版本合同。
3. 所有权按类型逐项定义：模块/Graphics 拥有的资源、VM owning instance、同步借用和跨帧代际 handle 不得混同；脚本 GC 不自动拥有全部返回对象。
4. 公共 API 文档说明所有权、线程、失效与重入。不得跨帧保留临时指针，不在锁内调用未知脚本或回调。
5. 时间、dt 与命名 RNG 由调用方注入；持久化声明 schema/version、迁移和未知字段策略，恢复在候选状态验证后发布。
6. 按调用基数、频率、观察者可知性和原子性选择直接接口、capability、事件或 Link。昂贵 API 明确成本与摊销维度，不用默认参数混淆成本档位。

规范入口：[代码质量与系统完整性](重构代码质量与系统完整性规范.md)、[领域建模](领域短根继承与跨域组合架构.md)、[Result](Result检查与不得丢弃返回值规范.md)、[模块接口与机制](模块接口契约与机制选型规范.md)。

### 代码风格

采用根目录 `.clang-format`。仅格式化改动行（`git clang-format`），不重排无关旧代码；提交前运行 `make check`，宿主构建与领域测试按改动范围另行验证。
