# 架构行为图、影响分析与任务上下文：第二阶段

日期：2026-10-12。状态：两领域查询链路已实现，本地验证通过，托管 CI 结果见 PR。基于第一阶段 PR #530；不是完整调用图、世界数据库或运行时因果追踪。

## 可查询的证据图

图由当前构建启用的 BindingContractRegistry 投影而来，不创建第二份手工接口目录，不访问游戏状态或执行脚本。接口、绑定、实现、owner、状态字段与测试使用带类型前缀的稳定 ID；ID 不包含源码行号。行号和源码指纹是可更新的证据属性。实现 ID 包含模块，避免不同领域的同名 C++ 符号混淆。

关系包括 `binds`、`calls`（仅直接绑定目标）、`state_owner`、`owns`、`reads`、`writes` 和 `tested_by`。绑定关系来自源码提取；owner 与字段访问来自领域侧车的审阅声明；测试关联只证明测试已登记，不声明本次执行通过。所有未登记 owner 的接口都保留未知覆盖状态。图是包含各个来源证据的多重图，同一关系可携带不同契约的指纹。

Scene 的 `SceneNodeRef.setVisible` 保留原映射。第二个真实领域为 Inventory：`Bag.setExtra` 写入、`Bag.getExtra` 读取 `Bag.extra_`，状态 owner 是 Bag。键由脚本动态指定，因此只声明字段级访问；不能据此断言某个特定键会影响另一处逻辑。

## Agent 查询接口

- `eve_architecture_query`：从稳定节点 ID 查询有界双向邻域。也接受 `inventory/Bag.setExtra` 这样的裸接口 key。
- `eve_architecture_impact`：沿绑定、实现和写入字段查找候选读取／写入接口。owner 和测试仅作为上下文，不从它们继续扩散到其他状态。读取接口不会被推断为写入者。
- `eve_task_context`：提供任务文本、候选影响子图、接口契约、源码位置、状态 owner、测试引用、源码指纹和未知关系。任务文本是随包携带的描述，不是自动生成计划或自然语言推理结果。

例如调用 `eve_task_context`，参数为 `seed="inventory/Bag.setExtra"`、`task="调整任务标记的存储方式"`，会返回共享字段的读取接口 `Bag.getExtra` 及对应契约和测试。该结果表示需要检查的候选影响，不证明运行时一定执行了这些接口。

三个接口均支持 `maxNodes`（1–256，默认 64）、`maxDepth`（0–8，默认 6）、`maxBytes`（1024–65536，默认 16384）。节点／深度截断显式返回 `truncated`。JSON 载荷超出字节预算时返回 `context_budget_exceeded`，不会静默删除关键证据。预算不含 MCP 传输封装。未知种子返回 `unknown_seed`。

可用接口种子与 `expectedInputHash` 校验第一阶段源码证据指纹；失配或无可核对映射返回 `stale_evidence`。当前版本身份是构建生成的源码证据，不是运行时世界快照或完整二进制身份。跨构建使用上下文包时应重新查询并核对指纹。

## 更新、性能与边界

侧车按模块发现，字段访问包含 `reads` 与 `writes`。生成器验证源码实现、owner 锚点及测试引用；侧车和证据源码是生成步骤的构建依赖。裁剪模块后相关接口及图节点缺席。

首次查询从注册表快照构图并缓存进程内不可变证据，初始化时间和常驻内存随启用接口数及已登记关系数增长；后续有界遍历使用邻接表，输出预算不意味着首次构图工作也被限制在相同节点数内。生成注册表由链接构建固定，脚本热重载不会替换它；更新源码证据需要重新生成并启动新构建。查询仅用于开发工具，不进入模拟热路径。尚未实现跨进程缓存、持久图索引、动态脚本调用分析或运行时追踪。

上下文包只报告已知结构；不会自动包含设计目标、领域规则、运行场景或未登记契约。源码指纹失效不等于证明行为变化。扩展新领域需要审阅元数据、增加真实脚本测试并登记生成依赖。
