# Physics 分层与后端契约

日期：2026-08-26
范围：`eve.physics` 的 World/Body/Shape/Joint、cloth、surface fluid，以及其
CPU/GPGPU 组合边界。本文不定义 procgen provider/editor 的实现细节。

## 1. 分层

Physics 的公开 facade 可以继续同时暴露领域对象、加速对象和调试/渲染便利
API，但内部依赖按以下方向组织：

```text
domain core  ──>  backend contract  <──  CPU solver / production accelerator
      │                                      │
      └──────────────> presentation bridge ─┘
```

- `domain core`：`World`、`World3D`、`Body`、`Body3D`、`Shape3D`、`Joint3D`、
  查询、事件和 fixed-step。`physics-core-only` 的显式源列表只包含这条边界，
  不 include `graphics/` 或 `gpgpu/`。
- `backend contract`：`physics/SimulationBackend.h` 中的
  `ISimulationBackend`、`SimulationStep`、`SimulationObservation`、
  `SimulationSettings` 和 `IAcceleratorBackendProvider`。核心 owner 只依赖
  这个接口。
- `accelerator`：CPU reference、现有生产 `ClothGPU` Vulkan compute 路径、
  `FluidSimulator` 的现有 GPGPU 路径。生产路径必须实现
  `ISimulationBackend`；`MockAccelerator` 仅用于 contract test，不能作为生产
  替代。
- `presentation bridge`：debug draw、cloth mesh draw、fluid surface
  reconstruction。它可以依赖 graphics，但不能反向成为 solver 的必要依赖。

`IAcceleratorBackendProvider` 是 optional capability。选择器先创建明确的 CPU
fallback，再查询 provider；provider 缺失、拒绝 domain、返回空 backend 或创建
异常时，选择结果仍为结构化的 `Applied + Unsupported warning`，并暴露
`usedFallback=true`。不能把 provider 失败伪装成 GPU 成功。

## 2. ISimulationBackend observable contract

每次 step 必须接收调用方注入的 `SimulationStep{tick, delta}` 和
`SimulationSettings`：

- `tick` 必须严格大于已完成 step 的 `lastTick`；`delta` 必须 finite 且在
  `[0, 0.05]` 秒内；iteration/substep 在 `[1, 1024]` 内。
- 成功后才提交 solver 状态和 `SimulationObservation`。失败的 step 不得改变
  solver 状态、tick、stepCount、duration 或事件缓冲。
- `stepCount`、`lastTick`、精确纳秒 `simulatedDuration` 是确定性状态；秒数是
  兼容投影，必须与精确 duration 一致。
- `restoreObservation` 只恢复 backend-owned progress metadata；World 的
  snapshot restore 负责把它与 domain 状态作为一个事务提交。
- `SimulationDeterminism` 必须显式返回 `BitExact`、`ToleranceBounded` 或
  `ExplicitlyNondeterministic`，不能由调用方猜测。

### CPU/GPU parity

CPU 和生产 GPGPU 使用相同的 tick、duration、settings、初始数据和输入事件时，
比较 backend-neutral observable，而不是比较 GPU buffer 地址或内部布局：

| 领域 | 必须 exact | tolerance-bounded state（建议基线） |
| --- | --- | --- |
| rigid body | tick、stepCount、duration、body identity/topology、event ordering | 位置/速度/冲量：`max(1e-5, 1e-4 * unitScale)` |
| cloth 2D/3D | tick、stepCount、duration、particle count、pin topology | position/velocity：`max(1e-4, 1e-4 * sceneUnit)` |
| surface fluid | tick、stepCount、duration、particle count、SDF identity | position/velocity：`max(1e-5, 1e-3 * sceneUnit)`；density：相对误差 `1e-3` |

这些是 contract test 的初始阈值，不是允许生产代码静默放宽的全局常量；若
某个场景需要更大误差，必须按领域记录原因、owner 和测试 fixture。当前 CPU
cloth、ClothGPU 和 FluidSimulator 都声明 `ToleranceBounded`；这不表示它们
已经通过本机实测 parity，实际测试仍需在可用的 GCC/Vulkan 构建上执行。

## 3. 时间、失败和迁移

- 新调用方使用 `SimulationStep`，不读取 wall clock；旧 `update(float)` 只是
  兼容 facade，内部生成下一个 tick 并显式消费 Result。
- 生产 accelerator 失败时可以回到 CPU，但必须在 status/diagnostic 和
  `usedBackendFallback` 中可观察。fallback 不迁移 GPU 临时 buffer，也不把
  GPU 私有数据写入存档；CPU domain state 是继续执行的权威状态。
- 在 GPU/CPU 切换时，只迁移 backend-neutral domain state、输入、tick 和
  settings。迁移后按目标 backend 的确定性等级继续，不承诺跨 backend bit exact。
- backend step、provider creation、restore、fallback 都是关键失败路径；调用
  方必须检查 `Result`，或使用带理由的 `ignore(reason)`。

## 4. SnapshotEnvelope

`World` 和 `World3D` 统一使用 `common/Snapshot.h` 的
`SnapshotEnvelope`，schema 分别为 `physics:world2d` 和 `physics:world3d`，
版本从 1 开始。payload 保存稳定 body id、拓扑所需的 body 集合、gravity、
单位设置和 observation 的 `tick/revision/stepCount/duration/lastDelta`；
runtime handle、Box2D/Box3D raw id、指针和 GPU 资源不持久化。

restore 顺序是：先验证 envelope/hash/type/schema/version，严格解析 payload，
验证 tick/revision 与 payload 副本一致，验证 body topology，再执行 backend
metadata restore 和 body/config 提交。解析、hash、版本、拓扑或 backend restore
失败时不触碰 live world；提交中出现异常时回滚 gravity、body 状态、backend
observation 和 tick，并且只在成功后清理 contact events。

当前版本采用未知字段拒绝策略，未知版本拒绝；未来变更必须通过
`SnapshotMigrationChain` 产生新 payload 并重新 hash，不能在 restore 中猜测或
部分接受新字段。

## 5. RuntimeHandle 与 Link

- `Body`/`Body3D` 保持 body registry；`Shape3D` 和 `Joint3D` 分别使用独立的
  `RuntimeHandle<PhysicsShapeHandleTag>`、`RuntimeHandle<PhysicsJointHandleTag>`
  registry，避免把 Box3D raw id 当作公共身份。
- `PhysicsLink`、`PhysicsShapeLink`、`PhysicsJointLink` 只保存 world + typed
  handle，不保存长期裸指针。`resolve()` 同时检查 world ownership、slot、
  generation 和对象 liveness；销毁 world、body、shape 或 joint 后返回
  `StaleHandle`。
- 这些 handle 是进程内、非持久值。restore/hot reload 重新创建 domain object
  后必须重建 Link；两种销毁顺序都要先移除 registry，再让 wrapper 失效。

## 6. 验收矩阵

- source/static：module dependency/layering、test manifest、`git diff --check`
  和 physics-core boundary include 检查。
- compile：独立 `/tmp` `physics-core-only` configure/build；不复用共享
  `build/linux-debug` 或共享 third-party build。
- contract：CPU/production GPU 的 same-input observable parity、provider
  present/absent、failed step unchanged、snapshot round-trip/hash/version/
  topology、两种 destruction order 的 stale resolve。
- runtime：Vulkan GPGPU cloth/fluid smoke 与 CPU fallback smoke 分别执行；GPU
  资源不可用时结果必须是显式 fallback，而非测试 skip 伪装成 GPU 通过。

若本机缺少正式 GCC C++ 前端，只能报告 configure/build 和 runtime 尚未验证；
不能用 Clang 结果替代仓库规定的 GCC 验收。
