# Physics 分层与后端契约

日期：2026-08-26
范围：`eve.physics` 的 World/Body/Shape/Joint、rope、cloth、surface fluid，以及其
CPU/GPGPU 组合边界。本文不定义 procgen provider/editor 的实现细节。

## 3D 刚体多后端迁移决策（2026-10-13）

状态：World、Body、Shape、Joint 的完整原生操作已迁入 `physics/box3d`，
由 `IWorldBackend3D`、`IBodyBackend3D`、`IShapeBackend3D`、`IJointBackend3D`
承接。Box3D 保持默认；Jolt 原生提供者的已实现范围与限制见第 7 节。

目标是在同一套 World3D/Body3D/Shape3D/Joint3D API 后支持 Box3D 和 Jolt。
Box2D 的 2D 路径保持独立。Box3D 暂时仍是默认值，切换默认值以相同场景的
正确性、耗时和内存实测为依据，不以第三方功能列表代替验收。

本轮已迁移的消费者边界：`World3D::queryBodyContactsOwned` 返回拥有数据的
接触点集合及 `Complete` / `Truncated` 覆盖状态，校验世界归属和 generation；
旧缓存查询作为脚本兼容适配器保留。Scene 编辑器由此不再读取 Box3D 原生
接触容量。`Joint3D::localFrames` 返回拥有数据的两端局部坐标，快照使用领域
坐标变换和注册接口，不再读取 Box3D 原生 ID；快照 schema 保持 v2。
Jolt 通过同一创建入口进入引擎，未实现能力明确拒绝，详见第 7 节。

### 状态与接口边界

- 世界创建时选择刚体后端，世界存续期间固定；不提供带活动刚体的原地热切换。
  刚体后端身份与 CPU/GPU 执行方式是两个维度，不向 `SimulationBackendKind`
  塞入 Jolt/Box3D 来混用这两个概念。
- 一个世界只有一份权威 solver 状态。适配层拥有 native world、body、shape、
  constraint 和临时分配器；引擎 Handle、持久身份和脚本 wrapper 继续由引擎
  领域管理。禁止同时推进一个隐藏 Box3D 世界来补全 Jolt 功能。
- 后端接口须覆盖创建/销毁、形状资源、状态读写、冲量、关节、过滤、查询、
  事件和步进；仅包装 `step()` 不构成完整刚体后端。第三方类型不得作为新的
  公开 API。现有 `raw()` 消费者须迁移到领域操作，含编辑器和快照路径。
- 连接机制：每个世界绑定一个已知实现，高频直接调用，修改须对该世界原子
  生效，因此采用世界持有的窄接口；后端选择在创建阶段完成，热路径不通过
  字符串或 capability registry 反复查找实现。
- 所有调用先保持仿真线程亲和。Jolt 内部 worker 只写后端拥有的事件收集区；
  完成步进后转换为引擎身份、排序并发布，不在 worker 或持锁时调用脚本。
- 后端能力以强类型集合报告。显式选择不可用后端，或请求未实现能力时，返回
  结构化 `Unsupported`，且不改变世界；不得静默换用另一个刚体后端。

### 已实现的所有权与创建契约

`World3D::createWithBackend` 是带结构化失败的显式创建入口。启用构建选项时
可选择 Jolt，关闭时返回 `Unsupported`。旧构造函数继续选择 Box3D。
恢复候选继承目标世界的后端身份；两种求解器不互相代替。

四个 facade 的旧标量/void API 仅用于兼容；内部原生操作统一调用 nodiscard
Result 接口并消费失败。native ID 不再从 facade 暴露，Box3D 专属测试通过适配层
内部 Access 检查原生行为。几何源数据由 Shape3D 单独持有；后端持有 cooked
资源与 native shape。重建先验证并创建候选，成功后释放旧形状，失败保留旧形状。

世界销毁先使 wrapper/Link 失效，再释放原生世界；body-first 同样先处理关节和
子形状。父级销毁期间，失效 shape 后端保留 cooked 资源直到父级原生销毁完成。
事件由适配层收集到引擎队列，返回 facade 后再发布；内部 solver 回调不调用脚本。
恢复交换两个稳定适配器中的 native world，而不销毁步进驱动借用的 world-ID
地址；回调上下文重绑定到正确适配器，再提交引擎 registry 和 generation。

World/Body/Shape/Joint 均限定仿真线程、步进之间调用。连接机制四轴为：每对象
一对一、每帧高频、实现创建时已知、修改需要同步原子结果；因此采用持有的虚接口，
没有每帧字符串查找。没有新增 ECS System、公共领域根、持久 schema 或 RNG。
physics-core-only 的 EVPhysicsCoreCheck 只提供 L1 编译裁剪证据，不扩大为独立
运行时裁剪承诺。Box2D 路径保持原有独立领域实现。

### 行为与持久化契约

共同核心先覆盖静态/动态/运动学刚体、基础形状、碰撞过滤、射线/扫掠/重叠、
接触与传感器事件、基础关节。九类现有关节、单向碰撞、逐三角形材质、角色
移动和接触点明细逐项列出支持情况；不能只实现落体就宣称现有 API 完整可用。

单位保持米、秒、千克及现有四元数约定。固定步时间继续注入；同一后端的
复现契约与跨后端的行为契约分开验证。跨后端不要求逐帧位置、接触数或求解器
冲量相同，而验证场景规定的穿透、约束误差、静止漂移和响应范围。原有
CPU/GPU 同算法 parity 阈值不能直接套在不同刚体求解器上。

快照继续使用版本化引擎 schema，不保存 native ID 或第三方二进制布局。
导入先检查能力并构造未发布候选世界，全部成功后才提交；不支持的关节或形状
不得留下部分恢复的世界。后端专有重放缓存与可移植场景快照必须区分。
world-first 和 body-first 销毁、shape 重建、restore 后 generation 变化必须
继续使旧 Link 失效，且不能通过另一个世界解析。

## 1. 分层

Physics 的公开 facade 可以继续同时暴露领域对象、加速对象和调试/渲染便利
API，但内部依赖按以下方向组织：

```text
domain core  ──>  backend contract  <──  CPU solver / production accelerator
      │                                      │
      └──────────────> presentation bridge ─┘
```

- `domain core`：`World`、`World3D`、`Body`、`Body3D`、`Shape3D`、`Joint3D`、
  查询、事件和 fixed-step。`physics-core-only` 的显式源列表只包含这条边界，
  不 include `graphics/` 或 `gpgpu/`。
- `backend contract`：`physics/backend/SimulationBackend.h` 中的
  `ISimulationBackend`、`SimulationStep`、`SimulationObservation`、
  `SimulationSettings` 和 `IAcceleratorBackendProvider`。核心 owner 只依赖
  这个接口。
- `accelerator`：CPU reference、现有生产 `ClothGPU` Vulkan compute 路径、
  `FluidSimulator` 的现有 GPGPU 路径。生产路径必须实现
  `ISimulationBackend`；`MockAccelerator` 仅用于 contract test，不能作为生产
  替代。
- `presentation bridge`：debug draw、cloth mesh draw、fluid surface
  reconstruction。它可以依赖 graphics，但不能反向成为 solver 的必要依赖。

`physics_rope` 是位于 `physics/rope` 的可裁剪运行时卫星，依赖 `physics` 和 `schema`，
但 Physics 核心不反向依赖它。`Rope3D` 自己拥有粒子、结构边、塑性状态与解析碰撞体。它可借用宿主模块的
`World3D` 和 `DistanceField3D` 作为碰撞提供者，但不拥有或销毁它们：调用方必须
在提供者销毁前解除关联。World3D swept query 覆盖凸体、三角网格和高度场，并在
动态刚体接触点施加反向冲量；SDF 被定义为静态环境，只提供距离、法线和 TOI。
渲染模块只读取材料长度采样，不持有或回写 solver 状态。

`IAcceleratorBackendProvider` 是 optional capability。选择器先创建明确的 CPU
fallback，再查询 provider；provider 缺失、拒绝 domain、返回空 backend 或创建
异常时，选择结果仍为结构化的 `Applied + Unsupported warning`，并暴露
`usedFallback=true`。不能把 provider 失败伪装成 GPU 成功。

## 2. ISimulationBackend observable contract

每次 step 必须接收调用方注入的 `SimulationStep{tick, delta}` 和
`SimulationSettings`：

- `tick` 必须严格大于已完成 step 的 `lastTick`；`delta` 必须 finite 且在
  `[0, 0.05]` 秒内；iteration/substep 在 `[1, 1024]` 内。
- 成功后才提交 solver 状态和 `SimulationObservation`。失败的 step 不得改变
  solver 状态、tick、stepCount、duration 或事件缓冲。
- `stepCount`、`lastTick`、精确纳秒 `simulatedDuration` 是确定性状态；秒数是
  兼容投影，必须与精确 duration 一致。
- `restoreObservation` 只恢复 backend-owned progress metadata；World 的
  snapshot restore 负责把它与 domain 状态作为一个事务提交。
- `SimulationDeterminism` 必须显式返回 `BitExact`、`ToleranceBounded` 或
  `ExplicitlyNondeterministic`，不能由调用方猜测。

### CPU/GPU parity

CPU 和生产 GPGPU 使用相同的 tick、duration、settings、初始数据和输入事件时，
比较 backend-neutral observable，而不是比较 GPU buffer 地址或内部布局：

| 领域 | 必须 exact | tolerance-bounded state（建议基线） |
| --- | --- | --- |
| rigid body | tick、stepCount、duration、body identity/topology、event ordering | 位置/速度/冲量：`max(1e-5, 1e-4 * unitScale)` |
| cloth 2D/3D | tick、stepCount、duration、particle count、pin topology | position/velocity：`max(1e-4, 1e-4 * sceneUnit)` |
| rope 3D | tick、stepCount、duration、particle/element count、cut/attachment topology | position/velocity/element force：`max(1e-4, 1e-4 * sceneUnit)` |
| surface fluid | tick、stepCount、duration、particle count、SDF identity | position/velocity：`max(1e-5, 1e-3 * sceneUnit)`；density：相对误差 `1e-3` |

这些是 contract test 的初始阈值，不是允许生产代码静默放宽的全局常量；若
某个场景需要更大误差，必须按领域记录原因、owner 和测试 fixture。当前 CPU
cloth、ClothGPU 和 FluidSimulator 都声明 `ToleranceBounded`；这不表示它们
已经通过本机实测 parity，实际测试仍需在可用的 GCC/Vulkan 构建上执行。

## 3. 时间、失败和迁移

- 新调用方使用 `SimulationStep`，不读取 wall clock；旧 `update(float)` 只是
  兼容 facade，内部生成下一个 tick 并显式消费 Result。
- 生产 accelerator 失败时可以回到 CPU，但必须在 status/diagnostic 和
  `usedBackendFallback` 中可观察。fallback 不迁移 GPU 临时 buffer，也不把
  GPU 私有数据写入存档；CPU domain state 是继续执行的权威状态。
- 在 GPU/CPU 切换时，只迁移 backend-neutral domain state、输入、tick 和
  settings。迁移后按目标 backend 的确定性等级继续，不承诺跨 backend bit exact。
- backend step、provider creation、restore、fallback 都是关键失败路径；调用
  方必须检查 `Result`，或使用带理由的 `ignore(reason)`。

## 4. SnapshotEnvelope

`World` 和 `World3D` 统一使用 `common/Snapshot.h` 的
`SnapshotEnvelope`，schema 分别为 `physics:world2d` 和 `physics:world3d`，
版本从 1 开始。payload 保存稳定 body id、拓扑所需的 body 集合、gravity、
单位设置和 observation 的 `tick/revision/stepCount/duration/lastDelta`；
runtime handle、Box2D/Box3D raw id、指针和 GPU 资源不持久化。

restore 顺序是：先验证 envelope/hash/type/schema/version，严格解析 payload，
验证 tick/revision 与 payload 副本一致，验证 body topology，再执行 backend
metadata restore 和 body/config 提交。解析、hash、版本、拓扑或 backend restore
失败时不触碰 live world；提交中出现异常时回滚 gravity、body 状态、backend
observation 和 tick，并且只在成功后清理 contact events。

当前版本采用未知字段拒绝策略，未知版本拒绝；未来变更必须通过
`SnapshotMigrationChain` 产生新 payload 并重新 hash，不能在 restore 中猜测或
部分接受新字段。

## 5. RuntimeHandle 与 Link

- `Body`/`Body3D` 保持 body registry；`Shape3D` 和 `Joint3D` 分别使用独立的
  `RuntimeHandle<PhysicsShapeHandleTag>`、`RuntimeHandle<PhysicsJointHandleTag>`
  registry，避免把 Box3D raw id 当作公共身份。
- `PhysicsLink`、`PhysicsShapeLink`、`PhysicsJointLink` 只保存 world + typed
  handle，不保存长期裸指针。`resolve()` 同时检查 world ownership、slot、
  generation 和对象 liveness；销毁 world、body、shape 或 joint 后返回
  `StaleHandle`。
- 这些 handle 是进程内、非持久值。restore/hot reload 重新创建 domain object
  后必须重建 Link；两种销毁顺序都要先移除 registry，再让 wrapper 失效。

## 6. 验收矩阵

- source/static：module dependency/layering、test manifest、`git diff --check`
  和 physics-core boundary include 检查。
- compile：独立 `/tmp` `physics-core-only` configure/build；不复用共享
  `build/linux-debug` 或共享 third-party build。
- contract：CPU/production GPU 的 same-input observable parity、provider
  present/absent、failed step unchanged、snapshot round-trip/hash/version/
  topology、两种 destruction order 的 stale resolve。
- runtime：Vulkan GPGPU cloth/fluid smoke 与 CPU fallback smoke 分别执行；GPU
  资源不可用时结果必须是显式 fallback，而非测试 skip 伪装成 GPU 通过。

若本机缺少正式 GCC C++ 前端，只能报告 configure/build 和 runtime 尚未验证；
不能用 Clang 结果替代仓库规定的 GCC 验收。

## 7. Jolt 原生刚体提供者

`EVENGINE_BUILD_JOLT=ON` 构建 `physics/jolt/`；OFF 时不编译原生 Jolt 源码，
显式选择 Jolt 返回 `Unsupported`。默认构造器和 `newWorld3D` 仍选择 Box3D。
C++ 使用 `World3D::createWithBackend(RigidBackend3D::Jolt, ...)`；脚本兼容入口
为 `Physics::newWorld3DWithBackend("jolt", gravityX, gravityY, gravityZ, sleep)`。
兼容入口将 canonical Result 失败转换为异常，不静默替换求解器。

当前提供者支持静态/动态/运动学刚体、位置/旋转/速度/世界与局部力及冲量、阻尼、
重力倍率、启停/休眠/逐体 CCD、固定旋转与分轴运动锁、运动学目标变换，
以及盒/球/胶囊/凸包/静态三角网格/高度场/复合形状；支持密度编辑、自定义
质量/质心/正定惯量与自动质量重算。质心修改通过 Jolt 装饰形状实现并通知约束，
只改变质量分布，保持碰撞几何的世界位置。
材质支持逐三角形 material slot、摩擦/弹性组合策略、切向表面速度；
查询支持多命中射线、AABB、球/胶囊/盒 overlap 和 sweep、相机球扫掠、点包含，
以及 query-only capsule mover、凸形状最近点和 cloth probe。接触/触发 begin/end 和关节 stress 在步进之后发布。

九类关节均有原生提供者：distance 由 Jolt DistanceConstraint 与 AxisConstraintPart
组合，弹簧、硬限位、电机分别进入同一个 Jolt solver；其余机械关节使用 SixDOF 的
轴约束、限位与电机；revolute/prismatic/motor 在创建时分配独立的速度约束，
和位置弹簧进入同一个 Jolt solver，运行时启停无需分配。filter 只维护连接体碰撞屏蔽引用计数，不添加虚假约束。
多轴电机的力/力矩上限遵循 Jolt 的逐轴限制，不承诺与 Box3D 向量模长裁剪相同；
电机速度目标保留世界坐标，在每个 native 子步转换到约束坐标。成功修改关节会
唤醒仍在 broad phase 中的连接体。
共同支持连接碰撞开关、局部帧、约束反力/力矩、stress 阈值，以及各类常用的
弹簧、限位、电机、轮悬挂/转向控制。改变形状质心后通知所有连接约束，不能让
旧 COM 偏移留下失效的锚点。销毁关节、先销毁任一 body 或先销毁 world 均先
移除 native constraint；同一体对多条屏蔽关系以最后一条释放为恢复碰撞时点。

Jolt 仍明确拒绝接触刚度频率/阻尼/推离速度调参，以及六轴全锁（应使用 static）。
树高、岛数、回收接触数、完整内存和分阶段 profiler 统计同样保留 Unsupported；
总步进耗时测量真实 native Update。失败不返回伪造的零，不静默切换求解器。
这些限制与已支持能力分开记录，不能描述为全部 Box3D 行为对等。

### 7.0 原生接触求解结果、hit 与滚动阻力

`cmake/patches/jolt-solved-contacts-rolling.patch` 为固定版本 Jolt 增加内部求解完成回调：
普通接触在 StoreAppliedImpulses 读取实际累计 lambda；CCD 在其真实速度约束求解后
报告冲量。没有使用 EstimateCollisionResponse。补丁在 Jolt 源码目标创建前幂等应用，
漂移则配置失败；提供者优先包含同一源码树的头文件，不能混用旧预装 ABI。

回调在 native body 锁内执行，只复制数值和 generation-qualified 引擎句柄，
不调用脚本、事件系统或加锁 BodyInterface。当前 provider 使用单线程 job system。
查询和 hit 队列在 native Update 返回后使用；返回值拥有全部数据，销毁 world 后仍有效。
失效句柄、移除/重建形状和失活 body 不返回旧接触。传感器和被内建过滤拒绝的接触
不经过实体约束求解，因此不会制造冲量或 hit。

queryBodyContactsOwned 返回最后一个 collision 子步实际求解的点，法线由被查询 body
指向另一方；normalVelocity 是求解前相对法向速度（接近为负），normalImpulse 是该子步
实际累计法向 lambda。totalNormalImpulse 累加本次外层 Update 内同一 native 子形状/点槽的
实际子步 lambda。featureId 是后端局部点槽，不是跨帧、跨后端的稳定几何身份；流形重排
时点槽可变化。CCD 使用独立槽表示单一平均撞击点，不伪造逐点冲量分布。Jolt 休眠体不再
生成原生接触约束，因此不承诺查询仍列出休眠接触；未产生新步进时保留最近已完成结果。
结果按形状、feature 和位置排序，截断显式报告 Truncated，不改动兼容查询缓存。

hit 按引擎形状对在外层 Update 内聚合，要求任一形状启用 hit、真实冲量大于零，且
求解前 approach speed 严格超过世界阈值。保留最快撞击的位置、法线和速度，汇总该形状对
所有实际法向冲量；按形状 ID 排序发布，每帧清空。默认阈值 1 m/s。不同求解器的 speculative
contact 和 CCD 时机不同，不承诺事件发生在相同帧或冲量逐位相等。

滚动阻力进入 native 速度约束迭代，求解相对角速度并把累计角冲量投影到球形上限：
`max(材料系数 A, B) * max(有效半径 A, B) * 流形法向冲量之和`。球/胶囊使用半径，
box/凸包使用四分之一 inner radius，网格自身半径为零；规则对应 Box3D，网格材料按命中
三角形解析。角冲量按双方逆惯量及接触缩放施加，包含旋转摩擦，不影响无接触物体。
CCD 使用相同投影规则。该扩展不缓存跨帧滚动 warm-start，有限迭代收敛和几何 inner radius
可与 Box3D 不同；不把线性/角阻尼冒充滚动阻力，不承诺逐帧相同轨迹。

### 7.1 几何、查询和 mover 的具体语义

凸包使用原生 ConvexHullBuilder 按 [4, 254] 顶点预算简化，再生成碰撞形状。
预算约束最终凸包顶点，不约束输入点数；重复点和内部点不会耗尽预算，源点上限与
Box3D 一致为 100000。简化保留源点的子集，可能缩小碰撞体积；不承诺两个求解器
选择相同顶点或保留相同体积。退化、非有限输入或非法预算在替换前拒绝。
原始点集和预算仍由 facade 持有，重建及快照恢复沿同一路径重新烹制。

后端 setDensity(value, false) 更新形状密度及待应用的原生叶形状，保留当前刚体质量、
惯量和质心；resetMassProperties、切换刚体类型或下一次质量/形状重建统一应用所有待更新密度。
与 Box3D 一致，设置相同密度是无操作，即使 updateMass=true 也不冲刷待更新质量。
旧 compound 自持原生叶引用，延迟期间查询和碰撞几何保持有效，无跨帧临时指针。

三角网格保留源三角形编号，通过 Jolt per-triangle user data 跨原生重排归属；
material slot 存于形状 owner，接触和查询按同一源编号解析。顶点焊接使用 Jolt
Indexify 与请求的容差，焊接导致退化时拒绝整个替换。树构建开关映射为 Jolt
build-quality 策略，不承诺树布局相同。矩形高度场使用 Jolt MeshShape 承载，
保留 +X/+Z 坐标、逐行样本、固定 cell 对角线与 clockwise 绕序；不填充/裁剪成
Jolt 原生方形 HeightField，不引入另一个物理世界。高度保留 float，和 Box3D
压缩高度场按量化误差容差比较。复杂几何仅允许 static，改变体类型亦先验证。

mover 无隐藏刚体、无外部回调，也不向刚体施加推力；每次先查询接触平面并
解初始穿透，再连续扫掠、裁剪沿墙滑动，最多 8 次迭代。接触容差 2 mm，
扫掠安全间隔 0.1 mm；任意 up 与坡度策略按本次调用归一化，不修改世界策略。
返回 owning displacement/normal/grounded 等数据，零位移亦执行解穿透。
不同 solver 不承诺逐次迭代数或接触平面数一致，只按位移/不穿越/落地容差验收。
查询顺序以 fraction、shape ID、triangle ID 稳定排序；AABB owning 结果有 256
容量并显式标记 truncated，旧无截断字段的 AABB 入口超容量返回失败。

### 7.2 控制与跨后端容差

世界 CCD 开关控制 native motion quality，body 的 bullet 请求独立保留，关闭后重新开启可恢复。
最大线速度发布到已有刚体并用于新刚体。接触回收距离映射到 Jolt 的 contact point warm-start
匹配距离；设零关闭 body-pair cache 并逐步失效接触缓存，避免保留精确重合点的旧冲量。
原生碰撞树边界、awake contact 数和 Update 总耗时可读，sensor 不计入 awake contact。

one-way 使用 facade 在步进前准备的世界平面；回调只读取内建策略，不调用脚本或锁定
BodyInterface。持久接触也重新判断，拒绝的接触关闭响应且不发布伪造 trigger；显式 body/shape
屏蔽也作用于 sensor。恢复普通接触时重新发布 begin。移动平台平面仍按现有逐步准备语义。

非零等值限位使用相邻可表示浮点数形成极窄区间，避免 SixDOF 将等值误作零姿态锁定；
按 solver 容差验收（测试平移误差小于 1.5 cm、角度误差小于 0.015 rad），不保证数学上零宽或 bit-exact。
Jolt 角限位本身在零角附近约半度内有锁定容差。

显式逐体休眠阈值关闭该体的 native 自动休眠，唯一适配层策略按注入 dt 累积安静时间，
判据为线速度模长加角速度乘局部包围盒半径的保守上界，持续达到 native time-before-sleep
后休眠；不承诺与 Box3D 的岛级休眠时刻相同。未设置阈值的刚体保持 Jolt 原生策略。

爆炸沿凸形状最近点施加 native impulse，采用球/胶囊/盒/凸包投影面积、线性 falloff、
mask 和 explosionScale；预先验证全部冲量后再修改刚体，结果按 body ID 排序。
最近点与 cloth probe 使用 Jolt GJK；和 Box3D cloth proxy 一样只处理凸形状，内部点返回自身。
点包含直接查询 leaf，停用刚体仍可查询其几何。所有这些行为均有 Box3D/Jolt 共享测试。

### 7.3 快照与验收边界

既有 v2 快照可重建九类关节和复杂几何拓扑；仍遵循 v2 的原有字段集合，
不新增 native pointer、native cooked blob 或第二套持久格式。它不是 Jolt solver
warm-start 状态，也不保存所有运行时电机/弹簧/材质/局部 shape 编辑参数；恢复后
这些配置需要由上层重放，不承诺恢复后逐位复现。失败 candidate 不替换当前世界。

原生 `PhysicsSystem` 由世界状态唯一拥有；刚体记录弱引用世界，形状记录弱引用
刚体。复合形状先完成 cooking 才替换，父对象销毁先使 facade 失效，原生形状
资源保留至原生父对象释放。恢复仍使用 detached candidate，交换世界状态而不
更换 step-driver 的稳定上下文；进程内 Link 需要重新解析/重建。

Jolt 使用 CPU 单线程 job system，接触回调不调用脚本，不获取未知服务，不发布
外部事件；求解结束后统一发布。begin/end 遵循 Jolt contact 生命周期（睡眠可能
结束活跃 contact），不承诺与 Box3D 的逐帧事件序列相同。模拟 dt/tick 由现有
SimulationStep 注入；同一版本/构建/输入下按数值容差验证，不承诺跨求解器
bit-exact。容量耗尽返回 Failed 并停止继续步进，保留销毁能力；此类求解失败可能
已部分推进原生状态，必须重建世界，不能继续用于回放。

原生 ABI 来自 pinned third-party 的 `cmake/Jolt.cmake`，包括双精度位置、静态
Jolt 和动态 MSVC CRT；原生符号只由 physics 适配层引用，SHARED 时属于 EVWorld。
`test/physics_jolt.cpp` 覆盖 provider-present 的落地/事件/几何/材质/查询/销毁、
九类约束拓扑恢复、mover 连续扫掠/滑动/穿透/任意 up、失败原子性，以及
provider-absent 的显式拒绝；网格/高度场、mover、distance/revolute/prismatic
运动与查询用例由 Box3D/Jolt 共用。EVPhysicsCoreCheck 在 provider-present 时
也编译 Jolt 原生适配器，证明 L1 不依赖 graphics/gpgpu；不新增 L3/L4 裁剪声明。
