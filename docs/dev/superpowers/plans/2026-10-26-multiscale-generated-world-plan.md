## 1. 交付原则

每阶段独立形成可审查、可构建的变更。每个 PR 只引入该阶段闭合能力，不以半成品接口破坏现有消费者。
新增能力默认关闭，先通过 COMPAT-1..10，再评估新能力。无法满足兼容时调整新增方案；例外需用户批准。
用户已授权完整实施本计划；未授权提交、推送或合并代码。

每阶段证据记录基线与变更 SHA、配置、工具链、硬件、输入种子、规则/核版本、误差目标、命令和原始结果。
实施时将证据放在 `docs/dev/validation/` 的阶段专属文档，较大原始数据作为关联 artifact；本次不造空报告。
不把 queued CI 写成通过，不把单帧截图写成完整运行证明，不把 include 图写成裁剪证明。

## 2. 阶段零：兼容基线与接口设计冻结

交付：复核当前依赖图、公开扩展点、物理与渲染调度；确定职责的 host、模块层级和最小适配边界。
核实源码/脚本/插件 ABI 兼容要求。整理旧接口、存档和典型场景的可复现基线。

冻结性能验收配置：目标 CPU/GPU、线程数、分辨率、目标帧时间 B、固定 dt、核、误差范围、内存上限。
用户已确认目标为 60 FPS（整帧 16.67 ms），1080p、固定模拟步长约 1/60 秒；
不能以场核心计时代替整帧验收。硬件和当前未通过结果见上述性能基线。
目标百万规模为 Ns=Nt=1,000,000 个独立点源/目标；扩展物体采样和复杂刚体另列成本。
如果尚未指定硬件，不允许给出“百万对象已保证一帧”的结论。

验收：

- 现有 Scene、Camera、Physics、Procgen、Spatial 的调用与返回语义均有针对性的兼容用例。
- 新模块关闭、不编译和 provider 缺席三种状态的预期可观察行为明确。
- 每个边界完成机制四轴分析、六面说明、生命周期和成本契约，不新增中央登记表。
- 量化旧路径性能噪声及判定方法；未经批准不以一个宽松百分比允许回归。

退出条件：基线可复跑、预算可度量、接口接入不改变默认路径。此阶段允许仅设计和基线测试。

## 3. 阶段一：多尺度值类型与局部投影

交付：新增参考系/地址/局部偏移、量纲与范围处理，独立于现有 TRS；新增显式局部投影适配。
确定地址宽度、最大活跃层级、规范化及溢出诊断。旧对象不创建新坐标组件。

验收：

- 跨巨大尺度的方向/距离与局部微小位移均对高精度离线参考验证。
- 平移参考系变更不改变物理关系；旋转参考系不被误用为无额外项的惯性系。
- 局部坐标→多尺度→局部坐标满足预算；边界、负地址、深层路径、溢出都显式测试。
- 旧 TransformSystem、相机和拾取基线不变；未启用路径无逐对象新增工作。
- 持久值与运行 handle 分离，销毁/恢复 stale 检查正确。

退出条件：坐标能力可单独使用且不触及旧矩阵默认语义。

## 4. 阶段二：纯数学两阶段场求解

交付：一种核、源/目标批次、压缩树、FMM 构场、批量求值、误差与成本报告。
先建立 CPU 正确性基准；GPU 并行作为后续优化，不能跳过参考结果。

验收：

- 小 N 直接 O(N²) 求和验证势、梯度和自作用排除；有限体积/软化的模型差异单独记录。
- 大质量远源、对称抵消、共点、团簇、薄片、巨大尺度差、全体移动和瞬移都有输入与诊断。
- 输出逐项绝对/相对误差，并区分保守上界、估计值和实测值。
- Ns、Nt、M、I、P、展开阶数及内存可观测；构树、排序和重建时间计入完整阶段 A。
- 无 graphics/局部刚体后端的配置完成 L1/L2/L3/L4 证据。
- 独立 batch 使用固定 tick；混用不同 Revision 的请求被拒绝。

退出条件：可控误差成立，交互规模无隐藏 N² 结构；未达性能目标不阻碍诚实报告算法状态，但不能标记最终完成。

### 百万规模的 GPU 常驻实现路径（阶段二、三、五共同验收）

当前百万全量移动测量已证明 CPU 每帧重建快照并上传不可满足 16.67 ms，
因此规模路径必须让源、目标、层级摘要和可见实例常驻设备；CPU 只提交
增量编辑、帧参数和预算诊断。下列步骤按依赖顺序完成，不用“单次 draw”
代替整帧证明：

1. 建立版本化的 GPU 状态缓冲与增量上传，记录每帧上传字节、等待和所有权；
   保留 CPU 参考路径和默认关闭的入口，热重载/设备丢失必须可重建。
2. 在设备上按固定 tick 构建/更新空间层级与多极摘要；分离 A 阶段源构场、
   B 阶段目标求值、状态积分，避免为每个目标遍历全部源。分层工作队列
   必须有容量和溢出诊断，不能以固定邻域截断长程影响。
   [GPU Morton 键前置阶段](../../validation/2026-10-30-gpu-morton-key-stage.md)
   已能从常驻源线性生成空间键、原子发布并在 GPU 上稳定排序；压缩树、摘要与
   一般分布场求值仍未实现，因此本项尚未验收。
3. 为同一核建立 CPU 直接求和、CPU 分层和 GPU 分层的误差对照，记录
   绝对/相对误差、守恒漂移、拒绝条件、确定性或容差范围。GPU 并行降低
   实际时间，不改变算法复杂度的证明义务；如果源/目标分布导致工作队列
   超预算，就明确报告该帧无法按目标误差完成。

已完成的[共点源 GPU 两阶段验证](../../validation/2026-10-30-gpu-field-probe.md)
证明该特殊输入可在设备端归约百万源并更新百万目标；它没有多簇树、近场或
一般分布的误差证据，不能视作本阶段退出条件。
后续[八簇质量与一阶矩验证](../../validation/2026-10-30-gpu-field-clusters.md)
已加入设备端源分桶、保守误差准入和近场拒绝；固定八簇仍不能代表自适应树。
[候选状态整批发布](../../validation/2026-10-30-gpu-field-atomic.md)
验证了 GPU 求值失败不会发布部分目标状态，尚需并入真实模拟 owner。
[源与目标设备常驻候选](../../validation/2026-10-30-gpu-field-source-residency.md)
进一步验证两种状态共同发布及拒绝回滚；仍只有固定八簇，尚未接入引擎。
[引擎 GPGPU 场组合验证](../../validation/2026-10-30-engine-gpgpu-field-sequence.md)
在真实引擎设备上运行了同一阶段关系的计算 shader，验证现有 GPGPU
命令序列和重绑定可用；正式模拟 owner 与自适应层次仍未完成。
`physics_field_gpu` 可选卫星现已提供会话所有权、受检 tick/revision 和
候选 prepare/commit；它仍仅支持固定八簇与有界源运动，不能替代
任意分布的 GPU 自适应层次或整帧规模验收。生产会话在 R9700 上
百万源加百万目标的 120 步计时与明确限制见
[GPU 场会话验证](../../validation/2026-10-30-gpu-field-session.md)。
4. GPU 积分后直接供给可见性与实例绘制；只读回诊断和必要的观察窗口。
   远景通量也在设备端生成/更新，曝光保持独立的显示常量。
   已完成的[球体常驻记录桥接](../../validation/2026-10-30-gpu-resident-sphere-view.md)
   验证同设备 buffer 到既有图像与批量绘制。生产场会话现在能把已发布目标
   直接投影为 GPU 球体包，百万源和百万目标的模拟/投影/绘制/呈现合成基准见
   [场到渲染验证](../../validation/2026-10-30-gpu-field-render-composition.md)。
   GPU 可见性、通用坐标转换和完整游戏帧组合仍未完成。
5. 在固定硬件、1080p、1/60 秒下同时量测 A、B、积分、生成、可见性、
   绘制、同步与整帧 P50/P95/P99；百万独立源和目标、全量移动及突发编辑
   都必须计入。不能把 CPU/GPU 重叠时间相加充当整帧，也不能遗漏等待。

## 5. 阶段三：模拟与局部物理适配

交付：固定 tick 调度、力缓冲、轨道积分、新场与现有刚体的显式绑定、参考系迁移。
System 的 View/读写/结构变更/服务/phase 在实现前记录。

验收：

- 场求值全部完成后再更新状态；初始加速度和积分器所需额外构场计入成本。
- 同一对象只有一个推进 owner；进入/退出局部物理域没有双积分或速度跳变。
- 叠加、替代指定重力贡献、只查询三种模式正确；后端不支持时明确拒绝。
- 旧重力、碰撞、约束、事件顺序及未绑定对象行为保持不变。
- 长时轨道能量/动量漂移、外力与碰撞组合、巨型物体潮汐/力矩均有证据。
- 对象先销毁、服务先销毁、恢复、过期任务完成与事务失败注入不泄漏或部分发布。

退出条件：新场可驱动显式绑定对象，旧物理仍完整可用；不同后端共享同一份适配契约测试。

## 6. 阶段四：递归生成与守恒摘要

交付：新增版本化递归定义、稳定节点键、惰性展开、摘要与稀疏编辑；旧生成器作为可选叶实现。
生成 prepare/build/publish 有预算和取消语义，不改旧种子与缓存行为。

验收：

- 普通/太阳尺度战舰分别验证尺寸参数；村落/王城验证容量增长而非统一放大。
- 调换展开顺序和任务调度后，固定节点的生成结果保持规定的确定性。
- 未展开摘要无需枚举全部后代；质量、一阶矩、动量及误差在细化/合并前后满足契约。
- 父子源无重复覆盖；局部细化的残余源正确，渲染淡化不改变质量。
- 玩家损伤/建筑修改跨合并、保存、恢复保留；不可表达合并明确拒绝。
- 循环规则、无进展规则、任务取消与旧版本完成通知受到控制。
- 旧 Procgen 输入、种子、缓存键及输出的基线不变。

退出条件：物理表示与视觉表示可独立细化，模型定义不依赖已加载细节。

## 7. 阶段五：可选多尺度视图

交付：新增视图接口、保守可见性层级、角尺寸 LOD、亮度摘要、相机相对渲染和远景深度策略。
reverse-Z/无限远投影仅属于显式新路径；兼容能力逐项列出。

验收：

- 近处小物与远处大物具有相同角尺寸时保持一致的投影尺寸和细节误差。
- 恒星亚像素通量、多个微弱源聚合、曝光变化均有数值与画面证据。
- 玩家在远方新建/拆除奇观，不加载完整网格也能更新可见粗表示。
- 前景遮挡、巨物跨尺度、透明、阴影、拾取、深度重建、运动向量和时间历史逐项验证。
- 相机进入巨物、连续跨尺度移动不抖动、不突然漏物；不支持组合显式诊断。
- 旧相机和旧后处理的基线保持；不能依靠全局切换深度约定完成新模式。
- 使用 engine-owned screenshot/连续状态证据，不能用日志、首帧或 Xvfb 截图代替视觉验收。

退出条件：新模式完整跑通，旧视图独立可用。未支持效果必须写明，不能宣称任意旧效果已兼容新模式。

## 8. 阶段六：组合、规模与发布门禁

交付：集成示例、版本化保存/恢复、可观察预算状态、完整性能报告与用户文档。
以可运行原生引擎示例展示跨尺度移动、远方奇观、生成细化及长程相互作用。

性能测量至少包括 10k、100k、500k、1M 独立源/目标；小规模测直接求和误差，大规模用分层抽样参考
和可验证界，不能为大 N 做不可承受的全量参考后误报实时成本。
每个规模包括均匀、团簇、薄片、尺度/质量差异、全体移动、瞬移和生成突发。

完整记录构树、场阶段 A/B、积分、碰撞、生成、可见性、GPU、上传同步、内存、S、p、M/N、I/N、P/N。
区分预热、冷启动、稳态与重建帧；报告 P50/P95/P99 和最大观测值。
观察到的最大值不是任意场景的最坏时间证明，不能以平均场时间代替整帧承诺。

退出条件：

- 在阶段零冻结的配置下，指定场景及百分位整帧满足 B，误差满足目标，百万独立状态全部更新。
- 超预算场景按策略明确报告，不静默移除远源、跳过目标或丢弃模拟时间。
- 所有兼容、生命周期、失败注入和 provider-present/absent 用例通过。
- 源质量、所需平台 CI、裁剪构建和示例 smoke 均取得终态证据。
- 尚未支持或未达标的组合明确列为未完成，不能靠缩小验收输入后保留原宣称。

## 9. 各阶段共有门禁

实现阶段每个 PR 运行 `make check`，记录 CI_BASE/PR 基线；按变化运行宿主构建与必要的聚焦域测试。
Windows 遵循根 AGENTS.md：确认 SHARED 导出与 OBJECT 所需链接，头改动确保相关 TU 真正重编译；
