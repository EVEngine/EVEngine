状态：六批候选均已实施或给出保留结论；固定基线的完整 Vulkan 主套件已运行，WebGPU 与跨平台验收未关闭。当前证据见第 9 节。

## 1. 目标与判断标准

减少重复代码、重复执行和没有验证行为的工作量，同时保留有意义的失败检测能力。
不以“删除多少测试”作为目标，不根据代码相似度、文件长度、断言数量或运行慢单独判定冗余。

每项精简必须回答四个问题：

1. 原用例验证什么行为，正常、边界、失败、生命周期、后端或资产差异分别在哪里？
2. 替代用例如何覆盖这些行为，哪些断言、输入类别和历史回归必须留下？
3. 省下的是重复源码、进程启动、设备初始化、等待、渲染帧，还是算法计算？
4. 用什么实际故障证明新用例仍会失败，用什么同环境计时证明它更快？

用例只有在被保留用例覆盖且没有独有回归价值时，才进入删除清单。尚未证明的项保持候选状态。

## 3. 确认的首批候选与覆盖保留表

### 3.1 优先批次一：流体重复注册

涉及 `test/fluids.cpp:131–297`、`test/fluids_surface.cpp:17–181`、

## 5. 反例与禁止机械精简项

- `common.result.*` 的 Debug/Release 条件断言：配置契约，不能按 CHECK(true) 删除。
- `editor.session_destructor_contains_throwing_tool_callbacks`：析构含异常而进程不终止就是合约，
  可加强回调计数，但不能只因末尾 CHECK(true) 删除。
- `sound.invalidData`：try/catch 检查异常路径，可以换为类型准确的异常断言来减少样板；这不是删除错误覆盖。
- `grid.*.roundtrip`、`ClassicScenes.*`、`tensor.gpu.stageBisect`：断言位于 helper，非空测试。
- `rpg.attribute.pureCompute.overridePriorityWins` 与 `clamp`：结构相似但操作类型不同，保留两个行为。
- Script API 与 C++ API、headless 与窗口、Vulkan 与 WebGPU、provider-present 与 provider-absent：
  即使调用看起来相同，也分别验证不同契约。
- 不全局改为 bundle；现有 GPU/窗口用例需要进程隔离。局部表驱动也必须先验证没有状态污染和性能退化。

## 6. 实施方式与验收

1. 审阅本计划后先做批次一，每批独立 diff，禁止混入生产功能修复。
2. 实施前固定同一 HEAD、编译器、构建类型、后端、显示方式、资产集、并发数；从二进制列表和
   `ctest --show-only=json-v1` 交叉核对实际注册。全量基线至少记录首轮与重试；热点独立跑至少 3 次。
3. 对每个删除/合并项记录原名、替代名、输入类别、断言并集、允许失去的重复工作。重命名同步修正
   CTest filter/文档引用，避免筛选 0 条仍显示成功。
4. 对关键替代用例做最小故障注入：UV 错位、深度失效、生成器空输出、播放不前进等；新旧用例应
   都能捕获应捕获的问题。故障注入在隔离工作区进行，不能混入提交。
5. 先跑受影响用例，再跑模块级、相关后端/平台和完整主套件。统计 pass/fail/skip/未执行/重试，
   缺设备或缺资产的提前返回单独记账。失败先归因，不通过增加重试或放宽断言来获得绿色。
6. 报告代码净变化、重复定义数、进程数、设备初始化次数、代表帧数、热点耗时中位数和主套件墙钟；
   不用源码行数或用例数量推算全套加速百分比。无收益的组合退回，保留有价值的断言改进。
7. 每批执行相关测试发现 fixture、`git diff --check`、变更行 clang-format、适用模块门禁；测试结构
   重构交付前执行 `ARCHITECTURE_BASE=HEAD make check/architecture-contracts`。
8. 若需要改公共 API、跨域生命周期、模块边界或持久化格式，先读仓库四份强制架构规范，另列设计与
   验证范围；本计划不预授权此类引擎改动，也不豁免 Result、所有权或 backend contract 要求。

完成条件是：明确重复已消除，代表性用例能检测目标故障，独有覆盖没有未经说明地减少，标准化
