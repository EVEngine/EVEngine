## 1. 一句话目标

把已经入库的 **action / combat / settlement / rpg / inventory** 积木，收成一条**可重复验收的单机动作 RPG 宿主路径**：从移动与技能命中，到成长、装备、任务、安全点存档，都能用固定输入序列与原生组合测试证明，而不是再造一套「ARPG 总管」模块。

## 2. 产品定义（本计划承诺什么）

### 2.1 成功标准（Must）

玩家（或 `eve_play` 代理）在官方示例中能完成：

1. **实时动作战斗**：移动、轻/重攻击（或技能）、闪避 i-frame、敌人预警/命中。
2. **权威扣血一次**：命中经 action notify → settlement → **唯一**资源所有者（默认 RPG Vitals `hp`）。
3. **成长闭环**：击杀 → 经验/金币/任务进度 →（可选）掉落入包 → 装备 → 属性同步。
4. **安全点存读档**：无活动敌人、无待发奖回执时保存；读档后不重复发奖、不恢复半途战斗瞬时态。
5. **可测**：原生组合测试 + `agent_check.py`（真实输入，禁止 `eve_eval` 改 HP）+ `make check`。

### 2.2 非目标（本计划明确不做）

| 不做 | 原因 |
| --- | --- |
| 新建 `arpg` CMake 模块或万能 CombatActor / GameplayObject 根 | 违反短根与领域所有权；框架设计已否决 |
| 联机权威 / 客户端预测 / 跨平台逐位回放 | 列为可选扩展；0.6/0.7 路线图也不承诺 |
| Diablo 级词缀经济、唯一掉落、完整 Boss 阶段机 | Phase E 扩展项，不阻塞 Must |
| 完整 3D NavMesh、云存档、内置 ARPG 编辑器 App | 工具差距与路线图已划出边界 |
| 用第二次 `rpg.update(0)`「刷新一切事件」 | 明确禁止；事件消费须有所有者 |

### 2.3 目标用户故事

| ID | 故事 | 验收入口 |
| --- | --- | --- |
| US1 | 独立团队用现有模块搭出可玩 ARPG 竖切，无需改引擎内核 | `examples/arpg-loop` 或其后继 |
| US2 | 宿主能把场景实体、战斗主体、RPGActor 绑成 generation-safe 映射 | 原生组合测试 + 读档重建 |
| US3 | 内容作者用 JSON 定义技能/效果/掉落/任务，热重载后行为可预期 | 示例 data/ + 热重载烟测 |
| US4 | QA / Agent 用固定操作复现「三杀升级装备存档」 | `agent_check.py` + 引擎截图 |

下列项在 [ARPG框架设计.md](../../ARPG框架设计.md) 已有实现与验证记录；本计划**继承并加固**，不重写：

| Action → RPG 扣血 | `rpg::RPGActionDamageSink` + `RPGSettlementAdapter`；集成测「RPG action damage」 |

## 4. 架构约束（实施红线）

1. **一事实一所有者**：HP 只归 Vitals（或明确选定的 CombatState），禁止双写后互相同步。
2. **跨域只走已声明接口**：action damage-sink / settlement / inventory prepare-commit；不向上 `#include` combat 实现进 rpg（裁剪证据继续有效）。
3. **身份用 generation Handle + SubjectRef**：销毁、读档、槽复用后旧映射必须失败，不得静默扣血。
4. **命中与表现解耦**：hitstop / 飘字 / 音效失败不回滚已提交结算。
5. **存档只含永久态**：检查点不存冷却、攻击窗口、敌人半残血量；读档回营地并 `resetTransient`。
6. **Result / nodiscard / 无架构豁免**：新公开 API 遵守仓库重构规范；新 TODO 须带 owner/issue/expiry。
7. **不扩 `getModInst` 到 runtime 热路径**；热路径文件声明 `// eve-hot-path`。

模块数据流（宿主焊接，非自动连通）：

```text
Input / AI intent
  → action (ability + timeline + notify)
  → combat windows (hit / guard / dodge)   [可选：CombatLoop 排序]
  → settlement commit
  → RPG Vitals / GameState / Tracker
  → inventory (loot / equip) → attributes modifiers
  → presentation (feel / VFX / UI)   [只读消费结果]
```

把 `arpg-loop` 里已验证的接线，收成**可复用、可测的宿主面**，避免每个游戏复制一份脆弱脚本。

| ID | 工作项 | 产出 | 完成条件 |
| --- | --- | --- | --- |
| A1 | 文档化「ARPG Host Checklist」：身份映射、固定步时序、唯一 damage provider、安全点谓词 | 用户手册章节或本计划附录落地到 `docs/usr/` | 清单可对照示例与测试逐条勾选 （已完成：2026-11-06 `docs/usr/modules/arpg-host.md`） |
| A2 | 提炼/加固 `ActionEncounter`（或等价）为稳定脚本/原生 API：bind / hit / claim / close / hasPendingReward | 公共 API + Doxygen `@cost` | 多遭遇误绑同一目标返回 Conflict；互不重叠可并存 （已完成：2026-11-06 增补 `isClosed`/`isBound`/`lastTick` + usr 文档） |
| A3 | 统一「余下宿主工作」1–8 的失败语义表（旧 generation、满包、重复击杀、provider 缺席） | 组合测试矩阵 | 每种失败有 Result 状态且不污染权威状态 （已完成：2026-11-06 矩阵入手册 + `kill_reward` 失败边用例） |

## 6. 模块责任矩阵（谁改什么）

| 模块 | 本计划允许的改动 | 禁止 |
| --- | --- | --- |
| `action` | notify / damage-sink 契约测试；多段技去重文档 | 持有 HP / 背包 |
| `combat` | Loop/窗口/闪避与示例对齐；导航卫星可选 | 直接改 RPG Vitals |
| `settlement` | 规则阶段文档与失败回滚测试 | 游戏公式硬编码进通用入口 |
| `rpg` | Encounter / KillReward / Save 加固；手册 | `#include` combat 实现；第二套动作状态机 |
| `inventory` | 满包/事务边界；装备 sync 钩子文档 | 反向依赖 rpg 实现细节 |
| `sensing` / `npc_ai` | 查询 preset、意图源示例 | 扣血 |
| 示例 / 文档 | 宿主模板、agent 验收、usr 入口 | 在示例里复制权威 HP |

跨模块机械改动（导出宏、全库 rename）**单独 PR**，不塞进功能阶段。

## 7. 验收与质量门禁

### 7.1 每阶段退出标准

1. `make check`（含 architecture-contracts，相对 `CI_BASE`）通过。  
2. 相关 `FILTER=` 领域/集成测试全绿；新增失败注入至少覆盖「旧 identity / 满包 / 重复发奖」三类之一。  
3. 可玩路径：`MIN_RUN_SECONDS=2 bash scripts/smoke_examples.sh <example>`。  
4. 行为路径：`python3 examples/<name>/agent_check.py …`（有则必跑）；证据目录含 observe 与引擎 readback。  
5. 手册与绑定：公开 API 有 `@brief`/`@param`/`@return`；昂贵 API 有 `@cost`。  
6. 最终交接按仓库规范报告：适用架构规则、验证了什么、有无例外（例外须用户批准）。

### 7.2 建议的自动化资产

| 资产 | 用途 |
| --- | --- |
| `test/integration/rpg-action/*` | 扣血 / 发奖 / provider 冲突 |
| `examples/arpg-loop/agent_check.py` | 端到端玩法 |
| 新增 `examples/arpg-host` 或手册夹具（若 A2 提炼成功） | 最小宿主模板，减少复制 |
| `make check/examples` | 示例布局契约 |

### 7.3 发版叙事建议

- **可宣布「动作 RPG 竖切可用」**：Phase A + B 完成，且 `arpg-loop`（或后继）进发版 checklist。  
- **可宣布「最小世界环」**：再加 Phase C。  
- **词缀 / Boss / 联机**：不得写入该宣布，除非对应 Phase E/F 项关闭。

## 附录 A — 宿主检查清单（实施 A1 时落手册）

复制到 `docs/usr` 前可先用此草案评审：

1. [ ] 每个生命有不可复用 SubjectRef；ECS Handle 带 generation。  
2. [ ] 每目标至多一个 accepting damage provider，且属于当前遭遇。  
3. [ ] 固定仿真步（如 60 Hz）拥有判定；渲染帧率不参与伤害。  
4. [ ] 每步顺序固定：意图 → ability/timeline → hit windows → settlement → 奖励/事件 poll → 表现。  
5. [ ] 死亡 receipt 认领失败可重试；成功后身份消费不可逆。  
6. [ ] 掉落缓存与击杀奖励分事务；满包不吞缓存。  
7. [ ] 换装后 `syncEquipModifiers`；生命上限下降有明确夹取规则。  
8. [ ] 存档前：无敌人、无 pending reward、玩家存活；存档后读档 `resetTransient`。  
9. [ ] 热重载 / 读档重建映射与 sink，不保存裸指针。  
10. [ ] 观察面只读；Agent 验证不走 `eve_eval` 改权威状态。
