# 多尺度生成世界、分层场与无固定远裁剪视图

日期：2026-10-26  
状态：架构设计；已实现独立坐标、CPU 场核心与事务积分切片，整体尚未完成验收。本文不是已有能力或性能证明。  
首要约束：只扩展接口和进行保持行为的抽象，不改变 EVEngine 已有功能。  
实施与验收：[分阶段计划](../plans/2026-10-26-multiscale-generated-world-plan.md)。

## 1. 目标与保证范围

本设计统一以下需求：

1. 用数学定义和局部参考系表达跨尺度模型，不预设固定世界边界或统一最小几何单位。
2. 对支持的长程场，不以距离截断源；先批量构造场，再批量求值和更新物体。
3. 在固定精度、固定地址处理成本和受控交互规模下，两阶段分别达到 O(N)。
4. 支持尺寸缩放与结构增长：普通战舰可具有太阳尺度，村落可通过增加结构成长为王城。
5. 相机按角尺寸、接收亮度与遮挡决定显示，不因固定最远距离丢弃恒星或玩家奇观。
6. 百万独立源与目标是指定硬件、精度和时间步下的性能验收目标，不能由渐进复杂度直接推导。

“无限”指规则和地址可扩展、作用公式无硬距离阈值，不指有限机器处理无限数据或无限精度。
每次运行的精度、地址宽度、活跃规模和资源都有显式上限。超出范围必须诊断，禁止溢出、
回绕或静默删除贡献。扩大精度或地址宽度的成本必须重新计入复杂度。

第一种场为有限源或总量与远场积分收敛的自由空间牛顿引力；不默认支持无限均匀质量分布、
相对论、光行时或任意非线性交互。无限周期世界必须另行声明边界条件和专用求解器。
默认模拟与视觉使用当前 tick；光行时属于后续独立能力。

## 2. 不改变已有功能：强制兼容契约

以下规则优先于便利性、性能优化和新功能接入方案。

- **COMPAT-1 默认关闭**：旧项目不修改配置即可保持原行为；不得自动迁移到新坐标、场或相机。
- **COMPAT-2 接口语义稳定**：已有入口、默认值、返回值、错误、事件顺序及可观察排序保持一致。
  不给已有扩展接口新增强制纯虚方法，不要求第三方旧实现被动实现新能力。
- **COMPAT-3 坐标稳定**：保留已有 TRS、矩阵、单位和局部空间 API。新坐标通过显式适配投影到旧接口。
- **COMPAT-4 物理稳定**：不改变旧重力、碰撞、约束和积分流程。新场只影响显式绑定对象。
- **COMPAT-5 渲染稳定**：旧相机的裁剪、深度、阴影、拾取及后处理不全局切换。
  新视图使用独立模式；不兼容的效果报告 Unsupported，不静默改写旧路径。
- **COMPAT-6 生成稳定**：相同旧参数、种子及规则版本维持旧结果与缓存键语义。
- **COMPAT-7 数据稳定**：旧存档不强制迁移，不改变已有字段含义；新数据使用独立版本化载荷。
- **COMPAT-8 依赖稳定**：新能力关闭时，不增加旧功能必须依赖的模块、启动服务或外部资源。
- **COMPAT-9 成本隔离**：旧路径不增加新体系的逐对象/逐帧遍历、场求解和后台生成。
  固定调度开销也须测量，不接受未经批准的性能退化。
- **COMPAT-10 抽象有边界**：只抽取接入所需接口和机制，不顺带重写旧模块。接口变更必须在同一
  可构建提交/PR 中覆盖所有后端与消费者；机械跨模块清理另立 PR。

兼容保证包括源码、脚本和公开扩展协议；当前发布约定是否要求二进制 ABI 在实施阶段零核实。
在核实前不更改已有公开对象布局或 vtable。不能以“结果大致相同”替代离散行为兼容；仅既有
浮点容差或预先批准的数值容差可以用于浮点比较。

若新增能力与这些要求冲突，应调整新增能力方案。任何例外必须先取得用户明确批准并记录，
不能以 fallback、兼容分支或默认参数暗中豁免。本设计没有申请或授权例外。

## 4. 数学定义与坐标

模型定义为 M = (Identity, Rule, Parameters, Scale, Capacity, Seed, SourceDefinition, VisualDefinition)。
运动、损伤和玩家编辑是独立运行状态；网格、树和场系数是派生表示。

局部参考系变换为 x_parent = t + 2^e R u，其中 u 为有界局部坐标，e 为尺度指数。
位置保存 FrameHandle、CellAddress、LocalOffset；相对运算在共同参考系中完成，不先拼成巨大
绝对浮点数再相减。物理求解参考系优先使用惯性或明确的平移参考系；若使用旋转/加速参考系，
必须同时定义非惯性力，不能把纯坐标变换当作动力学变换。

尺度及数量使用明确量纲和规范化表示。质量也可能溢出，必须与长度一起做数值范围设计。
GPU 只接收适合当前视图的有限相对数据。扩展地址与任意精度不享有免费 O(1) 运算假设。

几何可以用隐式域 f(u) <= 0、参数曲面、体生成器或模块规则表示，不强制统一为 SDF。
规则 G(type, parameters, scale, capacity, seed, nodeKey) 产生子定义。
尺寸 scale 与容量 capacity 独立：增大城市容量增加街区，而非放大所有门和人物。
同密度相似缩放满足质量随 scale^3 变化；材料、密度和动力策略均须显式配置。

种子来自根种子、稳定节点键、规则版本、命名 RNG 流；不得依赖线程执行顺序、加载顺序或 wall clock。
规则必须有展开预算及循环/无进展检测。无限递归只允许作为潜在定义，不允许一次任务无界展开。

## 5. 三种层级和核心数据

生成层级描述组成，场树描述空间交互，视觉层级描述可见贡献。三者可以共享不可变边界数据，
不能强制同构，也不能共享含糊的可变状态 owner。

### 5.1 数据职责

- **ModelDefinition**：不可变规则、版本、参数、尺度和源策略，由定义资源 owner 管理。
- **ModelInstance**：持久身份、定义引用、运动与玩家修改，由所属领域 owner 管理；不创建万能 GameObject 根。
- **GenerationNode**：稳定路径键、子规则、总量预算、保守边界及摘要 Revision。未展开节点也有有效摘要。
- **FieldSourceBatch / FieldTargetBatch**：连续 SoA 数组，保存位置、源强度、支持域、采样规则及句柄映射。
- **FieldTree**：拓扑、叶区间、归一化尺度、多极/局部系数、交互列表与误差；由求解器拥有。
- **FieldSnapshot**：不可变 tick、源 Revision、核版本、系数和精度报告，拥有独立生命周期。
- **VisualSummary**：保守边界、几何近似误差、粗外观、发光上界及资源版本。
- **RepresentationLink**：以 generation-qualified Handle 关联 Scene、刚体和渲染表示，不持久保存裸指针。
- **BudgetPolicy / AccuracyReport**：资源上限、误差目标、实际质量状态及超预算原因。

以上为设计说明，不建立第二套手工 JSON 类型、模块或 System 注册表。

### 5.2 细化、合并与源覆盖

父摘要与子表示满足质量与一阶矩一致：M_parent = sum(M_child)，
M_parent * center_parent = sum(M_child * center_child)。运动表示切换还须保持线动量和角动量。
不可丢弃的内部运动、损伤或玩家修改保留为粗状态/稀疏覆盖；不能表示时拒绝合并。

每次场求解使用无重复的源覆盖：同一质量不能同时从父摘要和子节点进入求和。
部分细化必须把残余源与已展开源明确分区。摘要需直接可计算或增量维护，不能要求遍历所有潜在后代。
未展开区域只有在摘要及误差满足目标时才可参与；“尚未生成”不是零质量或零亮度。

新增对象的质量、包围体与亮度摘要随发布事务同时传播。完整视觉资源晚到时继续使用有效粗表示，
不能让已存在的奇观因网格未加载而从远景消失。

## 6. 两阶段场求解

首个核为 Phi(x) = -G integral(dmu(y) / |x-y|)，a(x) = -grad(Phi(x))。
点源自作用排除；重合点、有限体积及软化规则由物理定义明确处理。软化改变模型，不是纯数值误差；
更换核后必须重新验证展开、导数和误差界。

### 阶段 A：构造场

准备源和空间树后，执行 source-to-multipole、multipole-to-multipole、multipole-to-local、
local-to-local。空间单元 B 中使用局部归一化展开：

Phi_B(x) ~= sum[L_(B,alpha) * ((x-center_B)/size_B)^alpha] + Phi_near,B(x)。

远场按节点对共享计算，不能为每个目标重新遍历全部源。求梯度时应用 1/size_B 链式因子。
初始实现使用一种有明确误差契约的展开；不同核不承诺共用同一组系数。

### 阶段 B：批量求值与更新

目标读取所属单元局部展开与近邻直接项，得到加速度和必要的梯度/力矩。
扩展物体的合力为 integral(g(x) dmu)，力矩为 integral((x-center) cross g(x) dmu)。
质心单采样只有在梯度误差允许时才成立；太阳尺度战舰需按潮汐/力矩误差细化或增加有限采样。
新增采样数量计入目标数量，不能隐藏成本。

所有目标使用同一状态快照构造的场。求值写输出缓冲，不能一边改位置一边污染其余物体的本步输入。

## 7. 执行阶段、ECS 与时间

渲染帧与固定模拟 tick 分开；一帧执行 S 个 tick 时必须乘上 S 的模拟成本。
以下是新增调度职责，不改写旧场景或旧 World3D 的更新顺序。

1. **Commit**：对带新能力的实例提交命令及生成结果；校验版本、守恒和预算后原子发布。
2. **Snapshot**：读取权威位置、质量、速度；形成稳定 View 的拥有型批次。
3. **Representation**：按受力、碰撞、交互要求选择物理表示，与相机无关。
4. **Prepare/BuildField**：构树、聚合、转换、向下传播；发布只读 FieldSnapshot。
5. **Evaluate**：读场和目标批次，写独立力缓冲，无实体结构变更。
6. **Integrate/PhysicsBridge**：由唯一运动 owner 写下一状态。全局轨道积分与局部刚体推进不能重复执行。
7. **Publish**：提交状态与事件，递延销毁及表示变化，更新摘要 Revision。
8. **ViewPrepare/Render**：读已发布状态，选择视觉表示并生成相机相对渲染包；调度后续生成任务。

实施每个 System 前在所属源码/设计局部记录实体类型与 View、读写组件、结构变更、事件、服务、phase。
循环内只处理批量数据，不做脚本回调、按名字查模块或 per-element capability 查询。
结构变更通过 deferred mutation；工作线程只读拥有型快照，owner 线程发布，不持锁调用外部代码。

局部物理接入显式选择叠加、替代指定重力贡献或只查询；默认不接入。
无法在后端保持其它力语义的替代模式返回 Unsupported，不全局关闭旧重力来模拟局部替代。
进出局部物理域时事务性转移运动写权限，确保状态连续；不同时存在两个权威位置。

## 8. 复杂度契约

记 Ns 为源数，Nt 为目标采样数，M 为树节点数，I 为远场交互数，P 为近邻直接对数。

T_field = O(Ns + M*C_up(p) + I*C_translate(p) + Nt*C_eval(p) + P)。

线性要求 M=O(Ns+Nt)、I=O(M)、P=O(Ns+Nt)，且展开阶数 p、核种类数、地址/精度处理成本受控。
实际成本分阶段记录；不能把构树、排序、平衡、源细化或力矩采样排除后称整步线性。

- 使用压缩自适应树避免空尺度链，约束叶容量和跨层交互；实现需证明/测量交互规模。
- 固定位宽基数排序可作为线性构建路径；比较排序必须报告 O(N log N)。
- 增量维护不是天然 O(1)，全体移动/瞬移需要重建路径及成本证据。
- 极端聚集或共点不能通过无限细分解决；按核支持与精度显式拒绝、合并等价源或选择已验证处理。
- 场系数和交互列表内存为 O(M*C_coeff(p)+I+Ns+Nt)，禁止生成全量源目标矩阵。

全帧成本还包括 O(K+Q+V)、局部碰撞、GPU 光栅化及 S 次模拟；K 是新增/修改节点，Q 是视觉访问节点，
V 是输出细节。任意接触关系、透明排序、像素过绘、任意脚本两两逻辑都不享有 FMM 的线性保证。

“百万独立对象”验收中必须有百万独立目标被更新；聚合远场系数不能替换这些独立状态。
仅当游戏模型明确允许群体状态时才可降为粗模拟，并单列结果，不能混入同一性能数字。

## 9. 误差和预算

### 9.1 数值场

目标为 |a_approx-a_reference| <= eps_abs + eps_rel*|a_reference|。
运行期使用核相关的保守界或已验证估计器，测试用直接求和参考。每个节点分配误差预算并累计，
不能让每个节点独立消耗全部预算。巨大远源使用源强度加权判据；净场抵消附近保留绝对容差。
表示误差、展开误差、坐标误差与舍入误差分别记录；不得把经验采样误差称为严格误差界。

### 9.2 表示与积分

摘要有误差上界和有效 Revision；失效结果不发布。固定模拟时间、命名 RNG、稳定归约顺序用于复现。
默认跨 CPU/GPU、跨物理后端承诺容差有界，不承诺 bit-exact；同后端的确定性范围也需测试。
初期无接触轨道使用明确的 leapfrog/Verlet 时序，预热和首次加速度计算计入成本；局部后端沿用旧积分。
监控能量、线动量、角动量漂移。一般 FMM 不自动保证精确成对反作用，必要的对称方案必须单独验证。

### 9.3 预算状态

精度优先模式允许超时但不暗改容差。实时优先模式仅在显式允许范围内调整细节/精度，优先推迟生成。
仍无法满足时返回结构化 BudgetExceeded/AccuracyUnmet 等状态；可由宿主选择降低模拟推进速度，
保留未推进的模拟时间，不能静默丢弃 tick 或假装旧场满足当前 tick 精度。
场景编辑失败保留上一已发布状态；昂贵生成/构场采用 prepare/build/publish 或 token，公开 @cost。

## 10. 无固定距离裁剪的视觉路径

角尺寸近似 theta=D/r，投影几何误差 e_px ~= H*delta/(2*tan(FOV_y/2)*r)。
按屏幕误差细化，使用迟滞与稳定节点身份减少跳变；近距离/包围相机情况使用保守投影而非远场近似。
亚像素发光源按接收通量与成像滤波显示；许多微弱源合计可能可见，剔除需约束累计亮度误差。
普通不发光物体保持正确照明与角尺寸，不因“无限可见”人为保证永远可辨认。

新视图可以采用独立的浮点 reverse-Z 与无限远投影，但仍有有限精度。
超远方向/尺度表示需要与近景一致的遮挡比较；不能仅把两个色彩图层叠加。
巨物跨尺度、透明、阴影、拾取、深度重建、运动向量和时间历史逐项验证。
旧相机和旧后处理保持原路径；新增模式中的不支持组合明确诊断。

视觉树从保守粗节点遍历，以贡献及误差预算决定是否展开；Q 在病态场景可能增长，分辨率有限
不意味着任意场景遍历必然 O(像素数)。新建奇观在发布时更新祖先摘要，不能只更新已加载网格。

## 11. 模块边界、接口与生命周期

空间地址/索引职责归 spatial 宿主，世界表示关联归 scene 的可选扩展，生成规则归 procgen，
场核与求解归 physics 宿主下独立可选卫星，视图投影与显示归 graphics。
这是职责划分；具体模块名、层级和拆分数由阶段零依赖审计确定，不在本文假造已有模块。
纯数学核心不依赖 graphics、editor、脚本执行器或局部刚体后端。

连接机制按 cardinality、frequency、observer knowability、atomicity 选择：

- 已知单服务的热路径：注入已解析接口/批量视图，不进行每元素查找。
- 可选 provider：在组合/准备阶段通过现有 capability 机制接线；定义缺席、撤销和重绑定语义。
- 跨域身份：typed Link/Handle，解析检查 generation；不把强类型退化为任意整数或长期裸指针。
- 多订阅通知：发布后发事件；事务写入：先 staging，再 owner 原子提交。

公共接口以消费方本地契约为优先，common 只容纳确需共享的机制/值类型，不把所有领域接口堆入 common。
每个新增边界描述 capability in/out、ECS+Link、events、script、tool 六个面；不使用的面明确不新增。
文档与源码注释表达契约，不恢复废弃 JSON catalogue。清单仅使用现有 host manifest 组合。

owner 负责取消任务、撤销 provider、使句柄失效。任务持有值快照及版本凭据；对象先销毁或服务先撤销
两种顺序均不允许访问失效资源。恢复/热重载重建 Link、树与 GPU 资源；过期完成通知不写回新实例。
接口使用 Result、强状态、[[nodiscard]]，遵循 Doxygen 生命周期、线程、重入和成本契约。

## 12. 持久化与可裁剪性

新载荷具有 schema ID/version；保存规则版本、种子、节点键、玩家覆盖、运动状态、核与精度策略。
未知必需字段/版本拒绝；明确标记为可忽略的扩展字段才允许忽略。旧格式读写语义不变。
解析/迁移在独立 staging 完成，整体校验后发布，失败不留部分可见世界。
派生场树、GPU 缓存和运行时 handle 默认重建，不能把旧进程句柄持久化后复用。

裁剪需区分 L1 编译、L2 链接、L3 运行、L4 可观察行为，不能仅凭 include 图声称可裁剪。
必须验证纯数学无渲染、生成 provider 缺席、物理后端缺席、graphics 缺席及旧默认配置。
不支持的组合返回明确状态；不新增静默 fallback。
