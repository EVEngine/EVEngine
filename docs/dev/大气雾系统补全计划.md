# EVEngine 大气雾系统补全计划

> 日期：2026-08-24  
> 状态：提案  
> 范围：`graphics`、`daynight`、`weather` 的天空大气、远景雾、体积雾和局部雾体积  
> 基线：现有 `Volumetric::setMode("fog")` 高度/距离全屏 ray march

## 1. 结论

EVEngine 当前的雾已经能承担风格化场景的远景层次，但它只在最终画面上沿深度积分一个全局介质：没有可复用的相机视锥体体积缓存，没有光源/阴影注入，没有局部密度体积，也没有与 `daynight` 天空大气共享透射率和散射结果。

建议把目标拆成两条可组合、可独立降级的路径：

1. **廉价大气路径**：解析高度雾 + 天空颜色/透射率 LUT，覆盖 WebGPU、低端设备和远距离 aerial perspective。
2. **高质量体积路径**：相机对齐 froxel 网格，注入介质、方向光/局部光和阴影，再沿视线积分并做时域重投影。

不要立即替换当前 `applyFog()`。它应保留为兼容和低质量后端，在新系统达到功能与图像基线后再转成 fallback。

## 2. 主流引擎与公开算法调研

### 2.1 Unreal Engine

Unreal 将相关能力分成互相组合的层级，而不是用单一“雾 shader”解决所有问题：

- **Sky Atmosphere**：Rayleigh、Mie 和吸收介质；用 `TransmittanceLUT`、`MultipleScatteringLUT`、`FastSkyViewLUT`、`AerialPerspectiveLUT` 加速天空与远景透视。`AerialPerspectiveLUT` 本身就是相机视锥体 froxel 数据，可用于不透明和透明物体。
- **Exponential Height Fog**：廉价的全局高度雾，适合作为体积雾关闭时的基础效果。
- **Volumetric Fog**：相机视锥体低分辨率体积纹理，支持方向光、点光、聚光灯、阴影和局部参与介质；通过逐帧子体素 jitter 与强时域重投影消除低分辨率采样噪声。
- **Local Fog Volumes**：廉价球形局部雾可按屏幕 tile 剔除；启用体积雾时也可体素化进入体积系统。

对 EVEngine 最有价值的不是完整复制功能，而是其**分层策略**：解析高度雾保证覆盖面，froxel 只负责需要真实光照的近中景，天空大气 LUT 单独负责行星尺度透射率和远景颜色。

### 2.2 Unity HDRP

HDRP 同样采用视锥体 3D 体积光照缓冲，并公开了横向分辨率比例、Z slice 数、深度范围和 slice 分布参数。它把以下参数视为核心物理/艺术控制：

- mean free path / extinction；
- single-scattering albedo；
- anisotropy；
- base/max height；
- sky color 或 constant color；
- directional-lights-only 等性能开关；
- Gaussian、reprojection 或组合降噪策略。

HDRP 的局部密度体积可以使用 3D density mask，代价与体积覆盖范围和材质复杂度相关。其经验说明，EVEngine 需要把“质量档”定义为资源分辨率、slice 数、光源集合和降噪模式的组合，而不能只改变每像素 sample count。

### 2.3 Godot 4

Godot 的 `Environment` 提供全局体积雾，`FogVolume` 向其中添加或以负密度移除局部介质，支持椭球、圆锥、圆柱、盒和全世界形状。官方文档明确指出薄体积在有限 Z slice 下会闪烁，解决办法是在体积厚度、可视距离和 volume depth 之间取舍。

Godot 的设计对 EVEngine 的启发是：第一版局部体积不需要材质图系统，但应从一开始支持**加法和减法密度**、多种解析形状和清楚的 Z 分辨率限制。

### 2.4 Frostbite / Assassin's Creed IV 公开方案

Wronski 的 SIGGRAPH 2014 方案奠定了现代游戏体积雾的常见结构：

1. 在相机视锥体的 3D 网格中写入密度/散射系数；
2. 注入太阳、环境光和影响大气的局部光，主光使用阴影图；
3. 沿 Z 对散射方程做前向积分，累计 in-scattering 与 Beer–Lambert transmittance；
4. 不透明或透明着色阶段按像素深度查询积分后的 3D 纹理。

这条路线比 EVEngine 当前“每个像素独立走 8–48 步”更容易复用结果，也能让多个透明层在各自深度获得正确雾化。

## 3. 当前实现与目标差距

### 3.1 已有可复用资产

- `Volumetric` 的相机重建、全屏合成、密度/高度/距离参数和质量档 API。
- Vulkan GBuffer 深度与世界法线，以及已有的渲染控制/帧图结构。
- 方向光、clustered point lights 和 shadow map 基础设施。
- `daynight` 的太阳方向、天空颜色、Rayleigh/Mie 风格参数与 IBL 更新。
- Vulkan compute pass 和 SPIR-V 编译/嵌入流程。
- `Volumetric.cpp` GPU 像素测试、RenderImageAudit 和 weather/daynight 场景。

### 3.2 必须补齐的基础设施

- 可采样、可作为 storage image 写入的 3D 纹理；格式至少覆盖 `RGBA16F` 和 `R16F`。
- 3D image 的创建、view、布局转换、frame lifetime 和显存统计。
- graphics 内部 compute dispatch 对 3D storage image、采样纹理、SSBO 和 push constants 的组合绑定。
- 每相机历史体积、上一帧矩阵、相机 cut/resize/质量变化后的 history invalidation。
- Vulkan 高质量路径和 WebGPU/不支持 compute/3D texture 后端的明确 fallback。

### 3.3 功能差距

- 雾色目前由脚本手传，未从天空散射/环境光自动获取。
- HG 各向异性固定，albedo、extinction、emissive 没有清晰区分。
- 只有单个全局高度介质，没有局部体积、纹理密度或负密度。
- 光照只提供固定方向相函数 tint，没有阴影和局部光注入。
- 静态 hash 噪声没有风场、时间连续性和时域稳定性。
- 全屏结果只在不透明场景之后叠加；透明物体不能按自身深度正确雾化。
- `resolutionFor()` 只是建议值，质量档没有自动管理内部资源。

## 4. 目标架构

### 4.1 模块边界

第一阶段保持实现位于 `graphics`，避免新模块向上依赖 `daynight` 或 `weather`：

- `graphics` 声明 `AtmosphereSettings`、`FogSettings` 和 `AtmosphereLighting` 数据结构。
- `daynight` 作为 provider，把太阳方向/辐照度和天空散射参数转换成上述纯数据结构。
- `weather` 只修改 preset/override，不直接调用后端 shader。
- `RenderControl` 根据特性和后端能力编译 pass 列表。

如果跨模块自动连接需要 capability，则接口放在 `common/`，provider/consumer 通过 `eve::cap::provide/query` 连接，不能由 `graphics` include `daynight`。

### 4.2 渲染数据流

推荐帧内顺序：

1. 更新天空大气 LUT（仅在大气/太阳参数显著变化时）。
2. GBuffer 和阴影图。
3. 清空并注入全局高度介质与局部 FogVolume。
4. 注入方向光、天空环境光和选定的 clustered lights；采样阴影。
5. 时域重投影并进行邻域 clamp。
6. 沿 froxel Z 方向积分散射与透射率。
7. 按场景深度合成不透明表面。
8. 透明物体在材质阶段或独立 transparent fog pass 查询相同积分体积。
9. 云层使用统一的大气透射率，并在需要时向雾提供云影。

### 4.3 资源建议

首版建议使用相机对齐网格，而非世界 clipmap：

- low：屏幕 1/12 × 1/12，32 slices，仅方向光，无 history 或轻量 Gaussian；
- medium：屏幕 1/8 × 1/8，48 slices，方向光阴影 + 8 个局部光，时域重投影；
- high：屏幕 1/6 × 1/6，64 slices，方向光阴影 + 32 个局部光，时域 + 空间滤波。

Z slice 使用指数或对数分布，并允许在相机 near 与 `fogViewDistance` 间配置。具体默认值必须通过 GPU 计时和图像误差测试确定，不能视为最终预算。

体积至少需要两个逻辑缓冲：

- `media`: extinction、scattering albedo/emissive 或预乘散射系数；
- `integrated`: RGB in-scattering + A transmittance/optical depth。

可先合并 lighting 与 media 以减少显存，等局部材质和多光源复杂度上升后再拆分。

## 5. 分阶段实施计划

### Phase 0：定义语义和图像基线（1 个 PR）

目标：消除现有 API 中物理量混用，为后续实现建立可比较基线。

- 新增 `FogSettings`：`extinction`/`meanFreePath` 二选一主控、`albedo`、`emissive`、`anisotropy`、base height、height falloff、start/end distance。
- 保留 `setDensity`、`setFogColor`，标记为兼容映射，不立即删除。
- 修复 `setTime()` 对 fog 无效的问题：要么加入连续风噪声，要么从 fog API 文档中移除这一承诺。
- 固化 clear/cloudy/rain/storm/night 五组图像基线和相机路径。
- 加 CPU 参考积分器，用小尺寸射线验证 Beer–Lambert 和高度积分。

验收：旧示例视觉可接受；同输入下 CPU/GPU 透射率误差在约定阈值内；兼容 API 测试通过。

### Phase 1：统一天空、远景雾和合成（2–3 个 PR）

目标：先补最显眼的 atmospheric fog 缺口，不依赖 froxel。

- 将 `daynight` 当前 CPU 大气模型参数化为共享 `AtmosphereSettings`。
- 生成最小 LUT 集：transmittance LUT + sky-view LUT；多次散射先用近似或低分辨率 LUT。
- 新增廉价 aerial perspective pass，雾色来自天空而不是常量颜色。
- 明确定义合成顺序，避免天空、云、height fog 重复叠加。
- 支持 camera resize、FOV/near/far 更新和 WebGPU fallback。

验收：日出/正午/日落时地平线与远处物体颜色连续；禁用体积路径时仍有稳定远景雾；云和天空无双重雾化。

### Phase 2：3D 纹理与 froxel 最小闭环（3–4 个 PR）

目标：只实现全局高度介质 + 方向光，先打通资源和 pass。

- 扩展 graphics 内部 3D texture/storage image 抽象；Vulkan 实现与能力查询。
- 添加 `AtmosphereVolume`/`VolumetricFogRenderer` 内部对象，自动管理质量档资源。
- compute 注入全局高度介质和太阳单次散射。
- 沿 Z 积分输出累计 radiance/transmittance。
- 按 GBuffer depth 合成，保留现有 `applyFog()` fallback。

验收：方向光无阴影时结果与 CPU 参考和旧路径趋势一致；resize、质量切换、创建销毁无验证层错误或资源泄漏。

### Phase 3：阴影、时域稳定和性能闭环（3–4 个 PR）

目标：达到实际游戏场景可默认启用的质量和成本。

- 将主方向光 CSM/现有 shadow map 注入体积光照。
- 每帧子 froxel jitter；用上一帧 view-projection 重投影 history。
- 深度/光照/密度邻域 clamp；camera cut、瞬时闪电和快速光源提供 history rejection。
- 提供 Gaussian、reprojection、combined 三种降噪策略或等价质量档。
- 加 GPU timestamp，分别记录 media、lighting、integration、filter、composite。

验收：静态相机无明显 banding；移动相机无不可接受拖影；闪电/枪口闪光在 history rejection 后不留下长尾；目标硬件 medium 档预算暂定 1080p ≤ 2 ms，最终以实测校准。

### Phase 4：局部 FogVolume（2–3 个 PR）

目标：提供关卡可用的局部雾和清雾空间。

- 新增球/椭球、盒、圆柱三种解析形状，支持 transform、边缘 falloff、priority/debug name。
- 参数支持 signed extinction、albedo、emissive、anisotropy；负密度用于室内清雾。
- CPU frustum culling；随后按需求增加 clustered/tiled volume list。
- 可选 3D density mask 放到后续小 PR，避免首版被资源格式阻塞。
- Squirrel API 和序列化格式；weather preset 可引用 volume group，但不持有 renderer。

验收：重叠体积按介质系数稳定相加；负密度不会产生负总 extinction；镜头跨越边界无跳变；压力场景有 volume count/overlap debug view。

### Phase 5：多光源、透明物体与云耦合（3–5 个 PR）

目标：补齐主流高端引擎的核心生产能力。

- 从 clustered lights 选取影响 froxel 的点光/聚光灯，支持 per-light volumetric intensity。
- 局部光阴影按质量档限制数量；无阴影灯与有阴影灯分别预算。
- 透明材质按片元世界深度采样 integrated volume；低端路径允许顶点雾。
- 云使用 atmosphere transmittance；太阳云影可调制雾的方向光注入。
- 水、粒子、瀑布等现有透明路径建立专项回归。

验收：室内不会被 sky ambient 过度照亮；透明层在不同深度获得不同雾量；局部光数量达到预算上限时稳定降级而非抖动。

### Phase 6：高级能力（按产品需求启用）

- 世界空间 clipmap，用于超远距离或大范围稳定介质。
- 体积材质/程序化 density graph。
- 预烘焙或稀疏体积纹理。
- 多次散射改进、地表反照率与行星尺度观察。
- VR 双眼 froxel 共享策略、动态分辨率、异步 compute。

这些能力不应阻塞 Phase 1–5 的生产化。

## 6. API 草案

推荐让常规游戏只操作一个高层对象，手工 pass API 保留给高级用户：

```squirrel
local atmosphere = gfx.getAtmosphere();
atmosphere.setEnabled(true);
atmosphere.setQuality("medium");
atmosphere.setFogMode("volumetric"); // off | analytic | volumetric
atmosphere.setMeanFreePath(80.0);
atmosphere.setAlbedo(0.86, 0.90, 0.96);
atmosphere.setAnisotropy(0.35);
atmosphere.setHeightLayer(1.2, 0.18);
atmosphere.setViewDistance(120.0);

local volume = atmosphere.newFogVolume("box");
volume.setPosition(0.0, 1.5, -8.0);
volume.setSize(8.0, 3.0, 12.0);
volume.setExtinction(0.04);
volume.setEdgeFalloff(1.5);
```

`RenderControl` 建议增加 `atmosphere`、`volumetricFog`、`fogLocalVolumes`、`fogTemporal` 特性，并让依赖关系由 compile 自动推导；脚本不应每帧手动取得 depth 后调用 `applyFog()`。

## 7. 测试与验证计划

### 7.1 数学测试

- 均匀介质解析解：`T = exp(-sigma_t * distance)`。
- 高度指数密度积分与 CPU 数值积分对照。
- HG phase 在 `g = 0`、正/负 anisotropy 下的归一性和方向趋势。
- 多体积 extinction/scattering 混合和负密度 clamp。
- 对数 Z slice 映射及其逆映射。

### 7.2 GPU 功能测试

- 3D storage image 写入、采样、布局转换和跨帧 history。
- 方向光开/关、阴影内外的 froxel radiance 差异。
- near/far 深度取样、天空像素和反向 Z/空深度约定。
- resize、MSAA、quality hot switch、camera cut。
- Vulkan validation 下短测试零 VUID。

### 7.3 图像测试

- Cornell/山谷/室内门洞三种几何；正午、日落、夜间三种光照。
- 无雾、解析雾、froxel 雾对照。
- 静止、平移、快速旋转、瞬时闪电的连续帧审计。
- 局部盒雾、重叠球雾、负密度室内体积。
- 不透明、alpha-cutout、水面、粒子四类材质。

图像审计不仅检查“有像素变化”，还要记录 luminance 区间、阴影/非阴影区域对比、近远透射率单调性和连续帧差分。

### 7.4 性能与内存

- 每个 pass 使用 GPU timestamp；CI 至少保存趋势，不以虚拟机绝对耗时作为硬门槛。
- 本地目标 GPU 建立 1080p/1440p 的 low/medium/high 基线。
- 记录 3D texture 总字节、history 双缓冲和 resize 峰值。
- 压力用例覆盖 0/8/32/128 局部体积和 0/8/32 局部光。

## 8. 风险与规避

- **Vulkan-only 漂移**：先定义能力查询和 analytic fallback；WebGPU 不宣称支持未实现的 froxel 特性。
- **3D 纹理抽象扩大改动面**：资源基础设施单独 PR，并用小型 compute probe 验证后再接雾。
- **时域拖影**：动态光/高密度区域提供 rejection mask；质量档允许改用 Gaussian。
- **透明渲染循环依赖**：integrated volume 作为只读渲染资源，不让透明模块反向依赖 atmosphere 高层对象。
- **天空与雾重复散射**：先写合成规范和背景像素约定，再实现 pass。
- **API 过早固化**：Phase 0–2 将高级对象标记 experimental，旧 `Volumetric` API 保持兼容。
- **宽头文件重编译**：公开结构用小型 POD/接口，后端资源隐藏在 Pimpl；遵守 public header 无跨模块 include 规则。

## 9. PR 切分原则与完成定义

每个 PR 必须在 Vulkan 和 fallback 路径上可构建，接口变化同时更新所有后端、消费者、绑定、文档和测试。不要提交“先破坏旧 API、后续 PR 再修复”的中间状态。

系统达到“补全”需同时满足：

- 默认 3D 管线无需脚本手工编排即可产生正确 fog；
- 天空、雾、云共享太阳和大气透射率语义；
- 高端路径具有 froxel、方向光阴影、时域稳定和局部体积；
- 透明物体至少有明确且可用的雾化路径；
- 低端/WebGPU 有解析 fallback；
- 质量档拥有经实测的 GPU/显存预算；
- 数学、GPU、图像和生命周期测试完整；
- 原有 `weather-daynight` 示例迁移到高层 API，兼容路径仍有测试。

## 10. 推荐优先级

近期应依次执行 Phase 0、Phase 1、Phase 2。Phase 1 的“天空与远景雾统一”通常比立刻增加局部光更能改善 atmospheric fog 的观感；Phase 2 则验证 EVEngine 是否具备承载现代体积渲染的资源架构。只有二者稳定后，才投入时域、局部体积和多光源。
