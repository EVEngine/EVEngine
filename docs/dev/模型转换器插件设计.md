# 模型转换器插件设计 — `modelconverter`

日期：2026-08-16
状态：设计与实现中（`modelconverter/`）
存放：`docs/dev/`

## 一句话

一个 **EVEngine 原生插件（`eve.plugins.load` 加载的共享库）**，通过调用 **Blender 的
Python 包（`bpy`）** 来完成模型转换：玩家在 Blender 里只做一个**简单原始体**（盒/球/柱），
插件运行一个**转换器**（一段 Python 脚本或一个 Geometry Node 节点组），自动把它变成
**石头、墙体、栅栏**等复杂网格，再把结果导回 EVEngine 渲染。

> 用户原话：“玩家只需要制作原始的模型（非常简单的盒子等），blender 就能应用节点，
> 自动把其转换成对应的石头、墙体等等。”

## 核心思路与分工

| 侧 | 职责 |
|----|------|
| EVEngine 原生插件（C++，本仓库 `modelconverter/plugin`） | 给 Squirrel 暴露 `ModelConverter` 模块；序列化任务；spawn 一个 Python 子进程；读回结果 |
| Blender Python 包（`bpy`） | 真正的网格变换引擎：导入原始体 → 执行转换器 → 烘焙 modifier → 导出 |
| 转换器目录（`modelconverter/converters`） | 玩家/美术可编辑的“配方”：一个转换器 = 一段 `.py` 脚本 **或** 一个 `.blend` 几何节点组 |
| Python 运行时（`modelconverter/python/eve_blender_converter`） | 把 job 分发给正确转换器，提供通用 `bpy` 辅助函数与烘焙/导出管线 |

要点：**插件不内嵌 Python/bpy，而是以子进程方式调用**。这样不需要把整个 Blender 链接进
EVEngine 进程，跨平台、崩溃隔离、bpy 版本升级互不影响，也符合“插件调用 blender 的 python
包来完成任务”。

## 架构图

```text
Squirrel 脚本 (main.nut)
    │  mc <- eve.ModelConverter()
    │  mc.configure(converterDir, pythonExe)
    │  mc.convert("stone", inBox.obj, outStone.glb, p)
    ▼
EVEngine 原生插件  ModelConverter (C++, shared lib)
    ├─ 序列化 job.txt（converter / input / output / format / params_json）
    ├─ spawn:  python -m eve_blender_converter convert job.txt
    │         （环境变量 PYTHONPATH 指向 python/eve_blender_converter 所在目录）
    └─ 读回 result.txt（ok / error / outputModel / stats）
    ▼
Blender Python (bpy)   eve_blender_converter
    ├─ 按 converter=xxx 找到转换器定义（manifest.json）
    ├─ import 原始体（obj / stl / glb / fbx）
    ├─ 执行转换器：
    │    ├─ kind=script     → run convert(ctx)，脚本可调用 mesh_ops 辅助
    │    └─ kind=nodegroup  → append .blend 里的几何节点组，挂到 modifier 并应用
    ├─ 统一 bake：应用 modifier / solidify / 三角化 / 计算法线与 UV / 可选去重
    └─ export 结果（gltf / obj / fbx）→ outputModel，写 result.txt + result.json
    ▼
EVEngine 用 model3d 载入结果并渲染（ModelData → GPU Mesh）
```

## 通讯协议（进程边界）

任务与结果都用**简单文本行**传输，C++ 侧不需要依赖 JSON 库；Python 侧用标准库 `json`
解析参数。

`job.txt`（C++ → Python）：

```text
converter=stone
input=C:/models/box.obj
output=C:/out/stone.glb
format=glb
params={"seed":"1847","size":"1.0","detail":"0.6"}
converter_dir=C:/eve/modelconverter/converters
```

`result.txt`（Python → C++，行式，逐行 `key=value`）：

```text
ok=1
output=C:/out/stone.glb
vertices=428
triangles=856
```

失败时：`ok=0`、`error=<UTF-8 错误信息>`。同时写一份 `result.json` 供日志/调试。

## 转换器目录与两种形态

转换器是**用户可编辑的资产**，放在 `converters/<id>/`。每个转换器一个 `manifest.json`：

```json
{
  "id": "stone",
  "name": "Low-poly Stone",
  "kind": "script",            // script | nodegroup
  "entry": "convert.py",       // kind=script 时的入口（提供 convert(ctx)）
  "blend": "gn_displace.blend",// kind=nodegroup 时的 .blend 文件
  "group": "EVE_Displace",     // kind=nodegroup 时的节点组名
  "description": "Box → low-poly stone via seeded displacement.",
  "params": [
    {"key": "seed",   "type": "int",   "default": "1"},
    {"key": "size",   "type": "float", "default": "1.0"},
    {"key": "detail", "type": "float", "default": "0.6"}
  ]
}
```

### `kind=script`

`convert.py` 导出 `def convert(ctx)`。`ctx` 提供：

- `ctx.obj` — 当前 Blender mesh 对象（可直接操作 `ctx.obj.data`）
- `ctx.mesh_ops` — 通用辅助（见下）
- `ctx.params` — 解析后的参数 dict
- `ctx.run_py(source)` / `ctx.apply_nodegroup(blend, group)` — 可混合调用节点
- 常用 `bpy` 已导入为全局

### `kind=nodegroup`

运行时从转换器目录加载 `.blend`，`append` 命名节点组，为 `ctx.obj` 新建 Geometry Nodes
modifier 并挂上该组，然后应用。**.blend 由脚本生成**（见
`modelconverter/scripts/build_nodegroup_blend.py`，在 Blender 里
`blender --background --python ...` 运行一次即可），这样仓库里不维护二进制。

### 通用网格辅助 `mesh_ops`

为脚本转换器提供封装，保证确定性（可复现）与结果整洁：

- `remesh_quads(obj, subdivisions)` — 细分
- `displace_vertex_weights(obj, seed, strength, vertex_group_name)` — 按顶点组做种子位移
- `weighted_random_group(obj, seed, group_name, min/max)` — 给顶点打随机权重（成片区域）
- `apply_modifiers(obj)` / `triangulate(obj)` / `recalc_normals(obj)` / `unwrap_lite(obj)`
- `deselect_all()` / `select_obj(obj)` 等杂项

## EVEngine 插件 API（Squirrel）

```squirrel
mc <- eve.ModelConverter()
mc.configure(converterDir, pythonExe, tempDir?)   // tempDir 默认系统临时目录
mc.check()                                        // 校验 python/bpy 可用，返回 bool
mc.listConverters()  -> [ "stone", "stone_wall", ... ]
mc.hasConverter(id)  -> bool
mc.convert(id, inputModel, outputModel, params)   // 成功返回 true，失败取 lastError()
mc.lastError() -> string
```

`params` 是一个 `ModelConverterParams` 对象（`mc.newParams()`），提供
`setInt / setFloat / setString / has / getInt / getFloat / getString`，风格与
`ProcgenParams` 一致。

### 示例

```squirrel
local p = mc.newParams();
p.setInt("seed", 1847);
p.setFloat("size", 1.2);
p.setFloat("detail", 0.6);
if (mc.convert("stone", "models/box.obj", "models/stone.glb", p)) {
    local md = model3d.newModelDataFromFile("models/stone.glb");
    // …上传到 GPU / 绑定 Renderable3D
}
```

## 环境与前提

1. 安装 Blender 的 Python 包：`pip install bpy`（Blender 官方发布的可导入模块，含几何节点引擎）。
   注意：新版 `bpy`（≥5.x）只针对单一 CPython 版本发布 wheel，**bpy 5.2 需要 CPython 3.13**，
   例如 `py -3.13 -m pip install bpy`。配置插件时把 Python 指向装有 bpy 的解释器。
2. 首次使用（可选）生成节点组演示：`py -3.13 modelconverter/scripts/build_nodegroup_blend.py`
   （或在 Blender 里 `blender --background --python ...` 运行）。
3. 在 Squirrel 里加载插件：`plugins.load("modelconverter.dll")` 后 `mc <- eve.ModelConverter()`。

> 若环境里没有 `bpy`，`mc.check()` 返回 false，`convert` 返回 false 并给出清晰错误，不影响
> 其它功能。`python -m eve_blender_converter check` 可单独自检。

## 设计要点 / 决策记录

| 决策 | 理由 |
|------|------|
| 用子进程调用 bpy，而非内嵌 | 不把 Blender 链接进 EVEngine 进程；崩溃隔离、跨版本稳定 |
| 转换器 = 脚本或节点组，两者都支持 | 脚本灵活跨版本；节点组让美术可视化编辑，满足“应用节点” |
| 行式文本协议（C++ 无 JSON 依赖） | 插件只依赖 engine 公共头，不引入 Poco/第三方链接 |
| 确定性优先（种子 + 顶点组权重） | 与 procgen 的“同 seed 可复现”哲学一致 |
| 转换器目录可插拔 | 玩家/美术不改代码即可新增/调整配方 |
