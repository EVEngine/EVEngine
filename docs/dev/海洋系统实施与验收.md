# 海洋系统实施与验收

## 目标与完成边界

实现广阔海洋、自然波涛、可驾驶船舶、浮力和水动力、船首推水与尾浪反馈。
完整交付包含多级频谱、海面 LOD、泡沫与飞沫、水下过渡、脚本示例、测试和实际画面证据。
解析波和浮力数学只是基础阶段，不代表完整系统已交付。
高度场不支持翻卷浪管；本轮采用浪尖白沫与飞沫表现破碎浪，体积翻卷不在已选方案中。

## 权威状态和数据流

- fluids 域拥有海况、频谱和交互波场。图形资源是这些状态的只读投影。
- physics::World3D 拥有船体姿态、速度和质量。浮力系统输出力，在物理固定步前提交。
- 应用注入仿真时间和随机种子。禁止材质和浮力各自累计一个独立时钟。
- 船体连接采用领域 Handle；跨帧不保留临时指针。图形资源借用由 provider weak lifetime 保护。
- 暂无新 ECS System。引入 System 前补齐类型范围、View、读写集、结构变化、事件、服务和 phase。
- 不建立新顶层 ocean_* 包；后续图形/物理桥接置于 fluids 宿主的卫星目录，清单为唯一装配入口。

## 解析波基础契约

`OceanSurface` 是不可变 owning value。创建时复制并规范化波向，拒绝非有限输入及
总水平陡度超过 0.75 的波组；这使水平映射单值，并为反求提供收敛界。
`position(q,t)` 给网格使用，`sample(worldXZ,t)` 反求位移前坐标后返回相同波面。
不能以位移前坐标直接查询船所在世界坐标，否则浪尖与浮力错位。

单位是米、秒、千克，Y 向上。海流平移波相位；返回速度为 Gerstner 表面粒子速度
加均匀海流，是水速度近似，不是任意流场的精确解。法线来自解析切向量。
时间与世界坐标采用 double；跨平台数值容差而非逐位相同。所有调用不保留引用、不执行回调。
目前没有持久化协议；后续配置和恢复必须带 schema/version，并事务式验证和发布。

`OceanBuoyancyCell` 用球冠浸没比例乘分配的排水体积。各 cell 体积之和由船体配置决定，
不能因增加采样点就增加排水量。浮力竖直向上，阻力使用相对水速，初始核心为各向同性二次阻力。
OceanBoat 已补齐方向性阻力、推进与舵力；拍浪冲击仍待补齐。

## 模块边界六面与成本

这不代表整个 fluids 模块可无图形链接；其既有清单仍依赖 graphics/gpgpu/physics。

## 频谱核心

`OceanSpectrumBuilder` 验证海况和不重叠波长区间，生成带方向的 JONSWAP 频谱。
总能量归一化为有效波高平方 / 16。相位随机流由注入 seed 独占，使用显式 SplitMix64，
不依赖全局 RNG 或平台随机分布实现。零浪高产生平静海面。

`OceanSpectrum::frameBuilder(time)` 是廉价准备步骤，builder 持有不可变频谱的共享租约；
销毁原 spectrum 后仍可 build。`build()` 执行六个场的二维逆 FFT：三维位移和粒子速度。
代价按每个频段 N² log N 增长；每个物理 tick 生成一次，所有消费者共享同一帧。
帧拥有网格数组，公开只读 span 不能跨帧对象销毁/移动保存。

FFT 使用不归一化的逆变换，频谱系数已是物理振幅，避免分辨率改变浪高。
移除 Nyquist 轴上的模式以保持水平位移场的 Hermitian 对称性。
速度是随均匀海流平移的粒子速度近似；不是观察者固定坐标处的高度时间导数。
周期 Catmull-Rom 插值使法线跨网格边界连续。世界坐标查询反求水平位移，失败显式返回
Unsupported，不把折叠或不收敛结果当作有效浮力高度。

默认三个 64² 频段作为 CPU 参考起点；GPU 256² FFT、局部尾浪合成及驻留位移已验证。
按船体尺度过滤、海况过渡和序列化尚未完成；Vulkan 两种投影路径已验证实际绘制，
可驾驶示例与海洋场景视觉验收尚未完成。

数值证据：7 个测试、1000 条断言通过，Debug 和 ASan/UBSan 独立构建均通过。
独立 DFT 对照验证 FFT 演化；另测能量、seed、周期、海流平移、速度有限差分、
默认多级海况的位移反求与法线、builder 源对象销毁、零浪高及非法输入。
多级测试曾发现双线性边界斜率跳变，改为三次插值后在原误差断言下通过。

## 真实船体适配

`OceanBoat` 拷贝最多 64 个船体局部浮力单元，以 PhysicsLink 记录世界/刚体身份。
每次固定步解析 World3D 注册表与 body generation，不保留跨帧指针。adapter 先销毁不影响
刚体；刚体先销毁或世界先销毁返回 StaleHandle。恢复后从新刚体重新创建 adapter。
World3D 是船体姿态与速度的唯一所有者，OceanBoat 不复制保存这些状态。

apply 接收同一时刻的频谱帧，输出排水量和水接触 receipt，并向真实刚体施力。
所有查询与校验在第一个 applyForceAt 之前完成；非法输入不提交部分力，也不消耗时间戳。
同一时间戳重复提交被拒绝。支持最大 1/30 秒固定步。方向性二次阻力在船体局部坐标计算，
按单元分配的质量约束耗散冲量；推进器离水失效，舵力随纵向相对水速变化。
receipt 带同一物理时间戳，已作为局部波场输入；采用有界游戏近似耦合，不声称严格守恒 CFD。

核心裁剪测试真实编译链接了 World3D/Body3D，而不链接 fluids facade、graphics 或 gpgpu。
这揭示并修复了两项原有配置问题：physics-core-only 的旧 event 模块名改为 platform_event；
将世界查询注册/实现从 PhysicsCapabilities.cpp 纯移动到 PhysicsWorldQueries.cpp，避免构造
World3D 必须链接带 Physics facade 的整个 TU。相机、地形和 LOS 注册行为保持原样。

真实刚体测试已通过静水浮力平衡、前进、转向、随浪升沉/倾斜、离水推进失效、重复步骤拒绝、
两种销毁次序。查询纯移动另加相机/地形命中与世界销毁后失效回归。
当前 5 个独立 CTest 全部通过，直接运行同一二进制为 2383 条断言、零警告/失败。
配置还修正了 profile checks 在 BUILD_TESTING=OFF 下未生成根 CTest 注册的问题；
现在真实运行 5 个 case，而非零测试退出成功。
主机图形构建已通过，这些证据不代表渲染验收。

## 尾浪与统一水面组合

`OceanWake` 独占局部高度、垂直速度和泡沫状态。每个频域模式按
`omega² = g*k*tanh(k*depth)` 演化，复用与基础海洋相同的二维 Fourier 实现。
均值模式清零，防止重复船体注入把整个局部海平面抬高；这是显式的游戏近似。
速度/高度有界，边缘采用耗散区，并在查询输出上平滑归零。
零尾浪区域即基础海洋，不依赖相机朝向。

`injectOceanBoatWake` 将同一步 receipt 转成船首/船尾方向双极扰动与垂直入水扰动，
验证整批后再注入。半径不小于单元宽度以避免欠采样，泡沫随接触生成并按时间衰减。
当前泡沫已进入 CPU/GPU 图形输出，并随步首谱帧的水平水速输运；三维飞沫的最新进展见文末。
`recenter` 只按整数格移动，保留重叠区域的世界坐标历史；远距离跳转清空新区域。

`OceanWaterView` 是一次同步调用期间的 borrowed view。基础帧和波场必须存活且不可变，
view 不得跨 owner mutation/销毁保留。两者时间戳不匹配时查询拒绝，避免旧尾浪与新频谱混合。
几何位移和刚体水面采样使用同一组合；尾浪在基础海浪位移后的世界 XZ 采样。
法线使用两个世界梯度之和，速度包含尾浪垂直项及基础水平速度的梯度项。

固定步顺序：生成当前频谱帧 → 所有船读取统一 view 并施力 → 汇集 receipt 注入尾浪 →
World3D 固定步 → 尾浪推进到下一个时间戳。不得在某船注入之后才为同一步另一船查询水面。
所有船完成查询后才注入，从而不让船遍历顺序决定同一帧受力。

当前数值核心 10 个测试、1541 条断言通过；真实物理组合 6 个测试、3476 条断言通过。
尾浪测试独立 DFT 验证有限水深色散、传播、无效批次原子拒绝、边缘高度/梯度、
整数格移动历史、组合几何/采样/法线、过期 timestamp。双船测试比较同位置无尾浪对照，
证实第一艘船产生的扰动改变第二艘真实刚体的垂直受力和位置。

## 分级网格与大坐标

`OceanMeshBuilder` 建立共用边界顶点的同心方环；径向格宽逐级增长，外边界精确落在
配置半径上。默认 256 个周向顶点、128 环、首圈半径 0.5 米、外圈半径 20 公里，
合计 32769 顶点和 65280 三角形。覆盖 40 公里见方的平面海域，不声称球形地平线。
拓扑仅在质量配置变化时重建，镜头中心连续移动；没有重叠 patch、裙边或 T 形裂缝。
径向与周向近景采样密度仍须结合实际画面调整，不能以拓扑测试替代视觉质量验收。

`OceanMeshFrameBuilder` 是 CPU 参考投影。世界参数坐标和原点相减使用 double，最后
才转换为 GPU float。世界波相位不随相机或浮动原点平移。它借用当次同步 mesh/water，
不得跨步或异步保留；结果拥有独立数组。geometry 直接返回插值位置和切向量，不做
逐顶点反求；尾浪梯度通过链式求导与基础浪切向量组合，与物理 sample 的法线一致。
GPU 驻留路径见后文；CPU 上传保留为一致性参考，不作为最终高质量性能承诺。

新增三例测试验证内部边双邻接且方向相反、外圈单边界、总面积、Euler 特征、
默认预算和非法配置，以及正负一亿米世界坐标下显示点与物理水面相差小于 0.02 毫米。
尾浪组合测试另外用有限差分核对直接几何法线，并验证过期视图被拒绝。
本阶段数值核心 13 个测试、9335 条断言全部通过；同一 13 例 ASan/UBSan 全部通过。
真实物理组合的 6 个测试在几何 API 更新后重新构建验证。

## 海面渲染参考路径

`OceanRendererBuilder` 准备 shader 与固定拓扑，`frameBuilder` 借用当步统一水面，
`publish` 验证并上传 owning 顶点投影，`draw` 在当前 3D pass 绘制。不累计独立海洋时钟，
不拥有船舶或水面仿真。本节描述 CPU 投影参考路径；GPU 驻留路径见后文。
normal、尾浪泡沫和水平 Jacobian 都来自同一水面；着色器按压缩量表现浪尖白沫，
按持久尾浪 coverage 表现航迹泡沫，并使用环境立方体、Fresnel 与太阳高光。
浪尖白沫目前是瞬时压缩响应，尚无完整破碎浪泡沫输运。

资源由 Graphics 拥有，renderer 使用 provider weak lifetime；provider 销毁后调用应返回
StaleHandle，renderer 先销毁则释放自己的 mesh/shader。后者已在图形测试覆盖，
provider 先销毁仍需专门集成测试。public header 只前置声明图形模块类型。
GLSL 使用生成的 SPIR-V；WGSL 提供匹配源码但尚无 WebGPU 运行证据。
重生成命令为 `python3 scripts/compile_ocean_shaders.py`，需要 glslangValidator。

Vulkan 实机测试 `rendererPublishesSharedSurfaceAndFoam` 通过 16 条断言：
真实绘制并由引擎 getPixel 读回，验证海面颜色、泡沫响应、无效上传保留原帧和 renderer 释放。
Lavapipe + X11 + Khronos validation 层下没有有效性错误；有既有未使用顶点属性性能提示。
这是像素回归证据，不代替后续可驾驶示例的 MCP 截图/录像验收。
主机构建中的全部 20 个海洋 CTest 已通过（6.54 秒），JUnit 为零失败/跳过，
输出没有断言警告或 Vulkan 有效性错误。数值核心更新后的 13 例 ASan/UBSan 通过。

## GPU 频谱投影

`OceanGpuSpectrum` 共享 immutable 初始频谱系数，独占设备 buffer/pipeline/sequence。
调用方通过 `frameBuilder(time).submit()` 注入时间；GPU 演化三个位移和三个速度复数场，
执行二维 radix-2 逆 FFT，再打包为六个平面的 float buffer。正常提交没有 CPU 读回。
`readbackBuilder(token).build()` 是显式、昂贵的诊断路径，用于 CPU/GPU 同源对照。
两个实现读取相同 seed 产生的初始系数，GPU 并不再持有一个海况或时钟权威。

相位每 16 仿真秒在 CPU double 域重定位一次，GPU 只接收短时间差；这避免长时间
运行时 float 时钟失去小步增量精度。只在相位区间变化时上传系数，其余帧在 GPU 内演化。
每次合法提交开始就使旧 token 过期；错误时间在触及设备前拒绝，保留上一帧。
后端提交失败会封存该投影，必须重新构建，避免在未完成的 command recording 上继续追加命令。
token 同时包含对象身份和 revision，不能从另一个 GPU 海洋读取帧。
band view 只允许同步立即消费，不能跨下次提交或 owner/provider 销毁保留。
Graphics retirement subscription 在设备销毁前释放全部计算资源，无持有强 provider 引用。

目前 GPU FFT 使用 Vulkan；缺少可用计算设备或其他后端返回 Unsupported，调用方必须
显式选择 CPU 路径。WebGPU 的绘制 WGSL 已提供，但 GPU FFT 的 WGSL 后端尚待补齐。
Vulkan GPU 结果已接入下述驻留海面消费端；WebGPU 驻留海洋尚未实现。

首轮默认三个 64² 频段逐格对照通过，包含海流、负时间、跨相位区间和一亿秒时间点；
Lavapipe 实测最大位移差约 1.2e-6 米、速度差约 1.92e-6 米/秒，没有 Vulkan 有效性错误。
跨后端验收容差仍为位移 0.005 米和速度 0.05 米/秒，不宣称位级一致。
128² 和 256² 单频段逐格对照也通过，最大位移差分别约 9.25e-7 和 8.30e-7 米。
不可用设备分支在独立进程测试中返回失败，而非静默冒充 GPU 成功。

## GPU 驻留海面消费端

`OceanRenderBackend` 显式选择 CPU 参考或 GPU 驻留路径；不支持的后端报告 Unsupported，
不会把 CPU 顶点上传冒充 GPU。驻留路径保持固定分级网格，GPU FFT 将位移写入一个
按频段排列的 float atlas buffer，随后同设备复制到 RGBA8 数据纹理。四个通道保留
一个 float 的原始位，shader 通过 texelFetch 重建，不使用颜色空间转换或硬件插值。
顶点 shader 使用与 CPU 相同的周期 Catmull-Rom 权重和解析导数求位移、法线与压缩量。

海面中心按每频段周期在 double 中取余，显示原点也在 double 中相减后转 float，
避免把一亿米级绝对坐标送入浮点纹理坐标计算。尾浪通过只读 `gridView` 同步上传
原始高度/泡沫，shader 重复相同的边缘衰减与链式导数；它没有第二份尾浪仿真权威。
尾浪与谱时间戳不一致时整帧拒绝。当前局部尾浪仍由 CPU 求解，不称为全 GPU 流体。

两组数据纹理交替发布。新数据只写 inactive 组，所有复制、尾浪上传及参数校验成功
才切换可见帧；GPU producer 后续重用或销毁不能修改已经发布的画面。
`Shader::sendFloatBlock` 只操作既有 uniform storage，整批验证后复制，不建立另一份参数权威。
该共用 API 不改变 backend 接口，且不做每帧字符串键查找。
首次使用或尺寸改变会分配纹理，其余帧复用；GPU copy 和局部尾浪上传目前是同步提交。
连接选择：频谱/尾浪到 renderer 为已知消费者的 1:N 高频读取，整帧发布有原子性要求，
因此采用直接类型化调用、revision token 和双缓冲；Graphics retirement 为低频 1:N、
provider 不知道具体消费者的生命周期通知，采用已有 Subscription。没有引入全局事件总线。

## 海况过渡数值核心

OceanSeaTransition 是持有两端点谱的不可变计划，不另建可变计时器。
输入相同 tile 分辨率/长度、重力和洋流；浪高、周期、风向、seed、choppiness、
海平面可改变。五次权重 w=u^3(10-15u+6u^2)，端点 w'、w'' 为零。
位移线性混合；速度额外包含 w'*(D1-D0)，首频段承载海平面变化率，
因此普通 OceanSpectrumFrame 可继续用于水面查询、浮力和 CPU 参考渲染。
区间外直接使用对应端点；计划及其 owning frame builder 可在原谱对象销毁后继续构建。
