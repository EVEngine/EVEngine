# 程序化生成模块设计 — `procgen`

日期：2026-08-08
状态：Phase A/B 已实现（`src/modules/procgen/`）
存放：`docs/`

## 已确认方向

| 项 | 决定 |
|----|------|
| 一期重心 | **地图**（地形 Tilemap / 地牢 / 特殊格子结构） |
| 二期重心 | **贴图**（像素风 PBR/调色板贴图：土壤、石材、水面、天空等） |
| 运行时机 | **运行时生成**为主（可同步；可选后台线程，结果回主线程应用） |
| 输出形态 | **可配置**（内存 Grid / 写入 `TileLayer` / JSON / PNG 预览等） |
| 第三方库 | **允许**；Phase A 使用 **DTL**（`external/DungeonTemplateLibrary`） |
| 格子存储 | **语义 id**（`Semantic::*`），经 palette 映射为 tile GID |
| 风格目标 | **像素 / 低模 RPG**（格子友好、调色板、低复杂度网格） |

非一期目标：Substance 级节点材质编辑器、植物学级植被、GPU 百万级 scatter。

## 目标

提供引擎内可载入模块 `procgen`，专门负责**可复现、可扩展**的程序化内容生成：

1. 常见地图结构：噪声地形、生物群系着色、BSP 地牢、Cellular Automata 洞穴、Drunkard Walk、迷宫等
2. 统一算法注册表：内置算法 + 用户 C++/插件/脚本算法
3. 输出适配器：同一生成结果可落到多种形态
4. 为二期贴图预留同一套 `Recipe` / `seed` / 注册表模型

与现有模块关系：

- **消费** `math`（噪声、hash、可种子随机）
- **写出** `map.TileLayer` / 对象层数据
- **可选** `thread`（后台生成）+ `event`（完成回调）
- **不替代** `map`：`map` 负责表示与渲染；`procgen` 只负责填充数据

设计语言对齐 [模块设计.md](./模块设计.md)、[RPG系统设计.md](./RPG系统设计.md)：`Module` facade + string key + 可插拔注册。

## 非目标（一期）

- Material Maker 式节点图 UI
- 无限流式大世界 chunk 流送（可后补；一期固定宽高）
- 自动 autotile / Wang tile 完整解算（可留扩展点）
- 3D 树草石头网格生成（三期候选）
- 编辑器可视化节点编排（DevTools 后期）

## 核心抽象

```text
Procgen (Module facade)
  ├─ GeneratorRegistry     string algorithmId → GeneratorFn
  ├─ Grid2D / HeightField  中间结果（与渲染解耦）
  ├─ Params                string→string|number 参数表 + seed
  ├─ OutputSpec            输出形态配置
  └─ apply* adapters       Grid → TileLayer / JSON / …
```

### `Params`

全部用 string key（与仓库绑定原则一致）：

```text
Params {
  seed: uint32
  width, height: int
  values: map<string, string>   // 算法私有参数，解析由算法自己负责
}
```

脚本侧提供类型化 setter，避免重载：

```squirrel
p <- procgen.newParams()
p.setSeed(12345)
p.setSize(64, 48)
p.setInt("roomMin", 5)
p.setInt("roomMax", 12)
p.setFloat("fill", 0.45)
p.setString("palette", "dungeon_default")
```

同 `seed` + 同算法 + 同参数 ⇒ **字节级可复现**（算法必须使用传入 RNG，禁止读全局 `Math` 随机态，除非显式文档约定）。

### `Grid2D`

格子中间表示（一期主输出）：

```text
Grid2D {
  width, height
  cells: uint32[]     // 语义由 palette / channel 解释，默认 = tile GID 或语义 id
  meta:  map<string, string>  // 可选：biome 名、算法 id、版本
}
```

可选附属层（按需生成，不强制）：

| 层 | 类型 | 用途 |
|----|------|------|
| `height` | float[] | 噪声高度 [0,1] |
| `biome` | uint8[] | 生物群系 id |
| `mask` | uint8[] | 可行走 / 房间 / 走廊标记 |
| `objects` | MapObject[] | 楼梯、出生点、宝箱点等 |

### `OutputSpec`（可配置输出）

```text
OutputSpec {
  target: "grid" | "tilelayer" | "json" | "png"
  // tilelayer:
  layer: TileLayer*          // 已有层则就地写入；空则由 apply 新建
  palette: string            // 语义 id → GID 映射表名
  // json / png:
  path: string               // 可选落盘；空 = 只返回内存/字符串
  pngChannel: "cells" | "height" | "biome" | "mask"
}
```

一期实现优先级：`grid` → `tilelayer` → `json`；`png` 作为调试预览（可选）。

### 注册 API

```text
// C++
GeneratorRegistry::registerAlgorithm(id, fn);
// fn: (const Params&, Rng&, Grid2D& out, string& error) -> bool

// 脚本（一期可后置）：注册 squirrel 回调填充 Grid2D
procgen.registerScriptAlgorithm(id, function(params, grid) { ... })

// 插件：动态库导出 eve_procgen_register(Registry*)
```

用户自带算法只需实现「读 Params → 写 Grid2D」，不必碰渲染。

### 推荐第三方（允许，按需接入）

| 库 | 用途 | 接入方式建议 |
|----|------|--------------|
| **Dungeon Template Library (DTL)** | BSP/洞穴/迷宫等格子算法 | header-only 或挑选算法移植；BSL |
| **FastNoise2**（可选） | 高性能/可 tile 噪声、节点序列化 | 二期或地形性能不够时再链；一期先用 `math` |
| **fast-wfc**（可选） | 规则驱动特殊结构 / 像素拼贴 | 作为算法插件 `wfc.tiled`，不进默认必选依赖 |

一期默认：**`math` + 自研/DTL 少量算法**，不强制 FastNoise2/WFC。

## 脚本 API 草案

入口：`procgen <- eve.Procgen()`

```squirrel
procgen <- eve.Procgen()
p <- procgen.newParams()
p.setSeed(42)
p.setSize(80, 50)
p.setInt("maxRooms", 18)
p.setInt("roomMin", 5)
p.setInt("roomMax", 11)

// 1) 只拿 Grid（可再加工）
grid <- procgen.generate("dungeon.bsp", p)
if (grid == null) {
    // procgen.lastError()
}

// 2) 直接写入已有 TileLayer（运行时换图）
layer <- map.newLayer(80, 50, 16, 16)
out <- procgen.newOutput()
out.setTarget("tilelayer")
out.setLayer(layer)
out.setPalette("dungeon_default")
procgen.generateTo("dungeon.bsp", p, out)

// 3) 语义 → GID 调色板（像素 RPG tileset）
procgen.setPaletteGid("dungeon_default", "wall", 1)
procgen.setPaletteGid("dungeon_default", "floor", 2)
procgen.setPaletteGid("dungeon_default", "corridor", 2)
procgen.setPaletteGid("dungeon_default", "door", 3)

// 读取附属信息
n <- grid.getObjectCount()
// name/type/x/y … 与 map 对象层字段对齐，便于脚本刷怪/放楼梯
```

约定：

- 无重载；失败返回 `null` / `false`，错误字符串 `lastError()`
- `generate` **默认同步**（运行时主线程）；地图 256² 量级应可接受
- 可选：`generateAsync(id, params, output, doneEventName)` 走 `thread`，完成 `event.push`

## 与 `map` 的衔接

```text
procgen.generate* → Grid2D
       │
       ├─ applyToLayer(layer, palette)  → TileLayer.setTile / fill
       ├─ applyObjects(mapModule)       → Map::setObjects（出生点等）
       └─（可选）export Tiled-like JSON  → 可被 Map::loadFromFile 再读
```

`TileLayer` 已有 `setTile` / `getTile` / `fill` / `resize`，一期适配器只写 GID，不创建纹理；tileset 仍由游戏资源绑定。

像素 RPG 建议流程：

1. 美术提供固定 tileset（墙/地/水/草…）
2. `palette` 把算法语义 id 映射到 GID
3. 运行时 `generateTo` 刷新层数据，摄像机/渲染不变

## 像素 / 低模风格约束

- 默认正交格子；iso/hex 只做投影消费侧（生成仍在逻辑格网上）
- 语义格子种类宜少（墙/地/水/沙/石/门…），靠 tileset 表现风格
- 噪声地形用硬阈值或少量阶梯，避免写实平滑混合
- 对象点输出整数格坐标（或格心像素），方便对齐 16×16 / 32×32

#### 六边形星球网格约定

- 实现采用细分二十面体的对偶网格，不依赖第三方几何库。
- 细分等级为 `n` 时，单元数为 `10 * 4^n + 2`；固定有 12 个五边形，
  其余单元为六边形。这是欧拉示性数决定的球面拓扑约束。
- `radius` 控制球半径；`tileInset` 只收缩每个单元的边界，收缩后重新归一化，
  因而所有顶点仍落在同一球面上。
- 每个单元使用独立顶点并扇形三角化，便于后续按单元设置材质、地形高度或
  选择状态；当前 recipe 输出统一法线与球面 UV。
- 拓扑测试验证索引范围、有限且单位长度的法线、半径、单元数量及 12 个五边形；
  渲染测试通过 EVEngine 的 3D 管线读取帧缓冲并编码 PNG，输出到测试构建目录的
  `out/hex_planet.png`。

#### 线性可拼接结构（Linear Structures）

通用方法 `LinearStructure`（`src/modules/procgen/algorithms/LinearStructure.cpp`）用一个
**可拼接单元段**（沿 X 轴 `[0, segLength]`，`x=0` 与 `x=segLength` 截面一致）重复 `segments`
次生成连续的结构。原语为轴对齐盒（`addAABB`）与任意朝向横梁（`addBeam`，用于交叉腿/斜撑），
每个盒子按面生成独立的法线与 UV。UV 使用绝对世界坐标 × `uvRepeat`，因此木纹/砖纹在单元接缝处
连续平铺。

共享参数：`segments`、`segLength`、`height`、`depth`、`thickness`、`scale`、`uvRepeat`。
用法与其它 mesh recipe 一致：`procgen.generateMesh("mesh.stonewall", p, gfx)`。

## 风险与对策

| 风险 | 对策 |
|------|------|
| 主线程生成卡顿 | 默认小地图；大地图走 async；算法复杂度文档化 |
| 全局 `Math` 随机污染可复现性 | 算法只用 `Params.seed` 派生的局部 `Rng` |
| GID 与美术 tileset 不对齐 | palette 外置，游戏自己绑 GID |
| DTL/FastNoise2 体积或许可 | 按算法可选编译宏；默认不硬依赖 |
| 与 Tiled 编辑器工作流冲突 | procgen 产出可被覆盖；也可导出 JSON 再手工改 |
