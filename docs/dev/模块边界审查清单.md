# 模块边界审查清单

日期：2026-09-15
状态：可执行清单（`docs/dev/模块边界审查台账.md` 是本清单对全仓的首次执行结果）
适用范围：对**单个模块**做存量审查，或对改动过的模块做变更审查。
上位规范：`docs/dev/模块接口契约与机制选型规范.md` 是需求来源；本清单是它的执行方法。

## 1. 与既有清单的分工

`模块接口契约与机制选型规范.md` §6 的三张清单是**改动视角**（「这次改动该满足什么」）。本清单是**模块视角**（「这个模块现在处于什么状态」）。二者规则编号一一对应，不重复定义规则。

本清单不重复下列已有门禁，只引用其结果：

| 已有机制 | 负责 | 本清单的处理 |
| --- | --- | --- |
| `scripts/module_depgraph.py --check` / `--check-layers` | include 图、分层方向、公共头泄漏 | B-04 直接引用，不重新判定 |
| `scripts/check_architecture_contracts.py` + `architecture_contracts.json` | 契约条目字段完整性、改动行 API 形状 | E 组的「是否已登记」引用它；「是否已存在」由本清单判定 |
| `scripts/check_quality_metadata.py` | TODO/HACK/FALLBACK/allowlist 预算与信封 | S-02 直接引用 |
| `scripts/check_bindings.py --strict` | binding gap | E5-01 引用 |
| `scripts/module_boundary_audit.py` | 本清单的机械取证器（只读，不做门禁） | 提供 §3 表中标注「audit」的字段 |

## 2. 分层与结论等级

模块按清单强度分三层，`module_boundary_audit.py` 用同一规则识别：

| 层 | 范围 | 适用 |
| --- | --- | --- |
| **Tier A** | runtime 领域模块（名字不以 `_editing`/`_editor` 结尾，且不含 `cmdline`/`devtools`/`import`/`cook`/`target`/`demo`） | 全部检查项 |
| **Tier B** | 编辑/编辑器卫星（`*_editing`、`*_editor`） | 全部检查项，但 M-02/M-03 判 **N/A**（这些模块按 `cmake/modules.cmake:eve_module_is_authoring_facet` 定义不进入 runtime profile） |
| **Tier C** | 工具模块（`cmdline`、`devtools`） | B/E/S 全查；M 组按「非 runtime profile 可用便捷原语」判据审查 |

每个检查项对每个模块给出五种结论之一：

- **PASS** —— 机械与人工证据均满足判据。
- **CANDIDATE** —— 机械信号命中，但需要人工阅读才能定性。**CANDIDATE 不是 FAIL**。
- **FAIL** —— 判据明确不满足，需登记整改项（含 owner）。
- **N/A** —— 该层不适用，**必须写明理由**。
- **UNVERIFIED** —— 该判据所需的工具尚不存在（当前唯一情形是 B-03 的符号引用图，见规范 §8.2 G-6/G-7）。**UNVERIFIED 不得记 PASS**（`R-BOUND-1`）。

## 3. 检查项

### B 组：模块身份与可裁剪性

| ID | 检查内容 | PASS 判据 | 取证 | 依据 |
| --- | --- | --- | --- | --- |
| **B-01** | 源码目录可解析且与 manifest 一致 | `src/modules/<DIR>`（或 `src/engine/<name>`）存在，且归属该模块的源文件数 > 0；不与他模块重复扫描同一目录 | audit `root` / `files`；`cmake/modules.cmake` 的 DIR 规则 | `R-BOUND-2` |
| **B-02** | 模块名与职责相符，不是伪模块 | 能说出一条独立职责与一份唯一权威状态；不出现「总是同开同关、一对一耦合」 | 人工 + manifest `DEPS`/`OPTIONAL_DEPS`/`GROUP` | 整合总清单 §「每个独立 module 证明职责…」 |
| **B-03** | 裁剪主张指明层次并给出对应证据 | 写明 L1/L2/L3/L4（规范 §1.3）；L2 用符号引用或关掉该模块的 configure→compile→link→启动四连测；**不得用 include 图** | 符号引用图（**尚未落地**）或实测 profile；audit 只提供 manifest 的 DEPS | `R-BOUND-3`、`R-BOUND-4` |
| **B-04** | 分层方向无反向边 | `module_depgraph.py --check-layers` 通过 | 该脚本（已接入 CI） | 协作约定 |

### E 组：六个面（规范 §3.1）

| ID | 检查内容 | PASS 判据 | 取证 | 依据 |
| --- | --- | --- | --- | --- |
| **E1-01** | 能力面完整 | 模块内每个 `cap::provide<X>`/`cap::addListener<X>` 的 `X` 都有 `capabilityName` 声明，且已在模块的 `module-interface` 条目 `provides` 中登记 | audit `declares` / `provides` | `R-FACE-1`、`R-FACE-2` |
| **E1-02** | 无恒缺席接口 | 不存在「已声明并被查询、但仓内无人提供」的接口；若确实为可选，必须有显式的缺席路径与 fallback | audit `--capabilities` 中 `provided_by` 为空的条目；`--findings` 的 E2-ORPHAN | `R-FACE-4` |
| **E1-03** | 无死能力 | 不存在「已提供但仓内无任何消费方」的接口 | audit `--capabilities` 中 `provided_by` 非空而 `consumed_by` 为空的条目 | `R-FACE-3` |
| **E1-04** | 无重复声明 | 同一接口类型名不在多个模块各自声明 `capabilityName` | audit `--capabilities` 中 `declared_by` 长度 > 1 的条目 | `R-FACE-4` |
| **E2-01** | 依赖面完整 | 每个 `cap::query<X>`/`cap::forEach<X>`/`cap::forEachUntil<X>`/`ModuleManager` 查找都已登记，并标注必需或可选 | audit `consumes` / `convenience` | `R-FACE-1` |
| **E2-02** | 可选依赖有证据 | 每个 `OPTIONAL_DEPS` 都有**模块级** `optional-capability` 条目：present 探针、absent 探针、fallback 可观察 | audit `E2-OPT` + catalogue（`src/**` 的全局条目**不算**模块证据） | `R-FACE-2`、整合总清单「optional capability 同时测试 present/absent」 |
| **E2-03** | `common/` 未被污染 | 该模块向 `common/` 新增的只有机制、无领域语义的值类型与信封套 | 人工（对照 `R-FACE-5`） | `R-FACE-5` |
| **E3-01** | Link 契约 | 每个注册的 Link 种类有 `link` 条目，含 `symbols`/`create`/`ownership`/`destroy_order`/`restore`/`stale` 六字段 | audit `links`（`LinkKind`/`registerLinkKind`/`LinkOps`）+ catalogue | `R-FACE-2` |
| **E3-02** | ECS System 契约 | 每个系统有 `ecs-system` 条目，含 `entity_scope`/`view`/`read_set`/`write_set`/`structural_changes`/`events`/`services`/`phase` | audit `ecs`（`SystemContract`/`registerSystem` 等）+ catalogue | `R-FACE-2` |
| **E4-01** | 事件面声明 | 每个 `Observer`/`Subscription` 成员的事件类型、顺序语义、派发时机、重入性有说明；回调内增删订阅安全 | audit `observers` + 人工核对 `@reentrancy`/`@thread` | `R-FACE-1` |
| **E5-01** | 脚本面与 C++ 面一致 | `SSQ_REG`/`expose(ssq::Table&)` 暴露的 `eve.*` 类与方法都已登记，且语义与 C++ 公共面一致 | audit `script_binds` + `make check/bindings` + 人工 | `R-FACE-1` |
| **E6-01** | 协议面（仅 `devtools`） | MCP/LSP/DAP 工具方法名与返回形状已登记 | 人工 | `R-FACE-1` |

### M 组：机制选型

| ID | 检查内容 | PASS 判据 | 取证 | 依据 |
| --- | --- | --- | --- | --- |
| **M-01** | 四轴推导 | 新增/改动的跨模块交换按基数/频率/关注者可知性/原子性取值，且推导出的机制唯一；无「调用方便」理由 | 人工（规范 §4.1 表） | `R-MECH-1` |
| **M-02** | 热路径 | 承担每帧工作的文件已声明 `hot_path`；其**新增行**不含 `getModInst`/`requireModInst`/`ModuleManager::getInstance`/`cap::query`/`cap::forEach`/`cap::forEachUntil` | audit `hot_candidates`（按文件名启发式的候选）+ 改动行 diff | `R-MECH-2`、`R-MECH-5` |
| **M-03** | 便捷原语不侵入 runtime | runtime profile 的模块代码中不出现 `getModInst`/`requireModInst`/`ModuleManager::getInstance`；若出现，必须位于 composition root、adapter 或明确的边界函数，并能指名该函数 | audit `convenience`/`M3`；人工定性位置 | `R-MECH-3`、`R-MECH-4` |
| **M-04** | 未新增第三套 provider 注册表 | 新 provider 家族复用 `cap::` 或已收敛的机制；自造的注册表类型/句柄必须是本模块自己拥有的 | audit `homemade_registry`/`M2`；人工区分「自造」与「复用 `editing::` 机制」 | `R-COHESION-3` |
| **M-05** | 无模块内 feature flag | 新增裁剪粒度到模块为止 | 人工 | `R-MECH-6` |

### C 组：成本可见性（**改动行语义，不做存量全量判定**）

> 方法论结论（实测，见台账 §5）：成本**形状**无法在存量上判别。名字触发在全仓命中 500+ 条，按值返回拥有型容器命中 1446 条，都不是「昂贵」的证据。因此 C 组只在改动行上判定。

| ID | 检查内容 | PASS 判据 | 取证 | 依据 |
| --- | --- | --- | --- | --- |
| **C-01** | 昂贵 API 有 `@cost` | 本次改动新增的公共 API 若成本档位为昂贵，其 Doxygen 块含 `@cost`，写明**相对量级、摊销维度与副作用** | 改动行 diff + 人工 | `R-COST-1`、`R-COST-5` |
| **C-02** | 未用默认参数区分成本 | 同一操作的便宜与昂贵路径有不同名字或不同返回类型 | 改动行 diff | `R-COST-2` |
| **C-03** | 无第二种更便宜的写法 | 同一操作在代码中只有一个入口 | 人工 | 规范 §5.1 |
| **C-04** | 便宜操作无仪式 | 未给便宜操作加 builder / `*Options` / `*Desc`；判据是「调用者有没有可能误以为它便宜」 | 改动行 diff + 人工 | `R-COST-4` |

### S 组：结构与维护性

| ID | 检查内容 | PASS 判据 | 取证 | 依据 |
| --- | --- | --- | --- | --- |
| **S-01** | TU 规模 | `.cpp` ≤ 1000 行；超出者按既有 section 注释拆为多个 TU（纯移动） | audit `max_cpp`/`S1` | 协作约定「Big files get split, not extended」 |
| **S-02** | 债务信封 | 新增 TODO/HACK/FALLBACK/allowlist/soft-skip 有 owner、issue、reason、移除条件或 expiry | `make check/quality` | 协作约定 |
| **S-03** | 公共头无跨模块 include | 公共头只用前置声明与 Pimpl | `module_depgraph.py` 的 `*` 标记 | 协作约定 |

## 4. 取证命令

```sh
# 全量机械取证（只读，不失败构建）
python3 scripts/module_boundary_audit.py                 # 194 模块总表
python3 scripts/module_boundary_audit.py --capabilities  # 能力面矩阵：声明/提供/消费
python3 scripts/module_boundary_audit.py --findings      # 逐模块清单发现
python3 scripts/module_boundary_audit.py --json out.json # 机器可读，供台账更新

# 引用的既有门禁
python3 scripts/module_depgraph.py --check --check-layers
ARCHITECTURE_BASE=HEAD make check/architecture-contracts
make check/quality
```

## 5. 一次审查的产出

1. 更新 `docs/dev/2026-09-15-模块边界审查台账.md` 中该模块的行：逐项结论 + 证据。
2. 补齐该模块的 `module-interface` catalogue 条目（规范 §3.2 字段）。
3. **FAIL 项**登记为整改项：owner、issue、移除条件。**CANDIDATE 项**必须由人工定性为 PASS 或 FAIL，不得留空。
4. **UNVERIFIED 项**在台账中原样保留，并注明所缺工具（当前为 G-6/G-7）。

## 6. 明确不做的事

- **不要求一次性补齐 194 个模块。** 沿用规范 §8.3 的强度策略：新增与被改动的模块必须满足全部适用项；存量按触碰补齐。本清单的价值在于**任何模块被触碰时**有一套确定的判据可执行。
- **不用本清单替代门禁。** 机械取证器是只读报告工具；门禁的落地见规范 §8.2（G-1..G-7）。
- **不把 CANDIDATE 当结论。** 机械信号只回答「值得看哪里」，不回答问题是否存在。
- **不用 include 图回答可裁剪性。** B-03 在符号引用图落地前一律记 UNVERIFIED。
