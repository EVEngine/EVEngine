## 一、问题

剧情、任务、经济与世界状态之间的“当条件满足就发生”是涌现玩法的基础设施。
若每帧或每次状态变化都对全部规则做 `O(规则数)` 求值，上万条规则会立刻拖垮模拟。

本模块把“条件 → 效果”做成**数据驱动、可索引、可延迟结算**的通用引擎，
题材语义（任务进度、入账、开场白）留在任务/经济/剧情模块或脚本策略里。

## 二、设计原则

1. **事实与规则分离**：`FactStore` 只保存规则可见的只读事实；规则定义不可变。
2. **按变更唤醒，不按帧扫描**：每条规则声明 watch keys；事实变更只唤醒订阅者。
3. **边沿触发默认**：条件从假变真才激活（Rising）；持续为真不重复刷屏。
4. **非重入**：激活入队，`drain()` 统一结算；结算中产生的新变更继续入队，不内联递归。
5. **确定性顺序**：同 tick 多条激活按 `(priority DESC, ruleId ASC, sequence ASC)` 排序。
6. **跨模块不硬焊**：内置 `fact.set`；`economy.*` 经 `IEconomy`；其余经
   `IEmergenceActionHandler` 监听器或脚本消费激活日志。
7. **复用 `decision::Condition`**：条件树、解释结果与技能/卡牌条件同源，避免第二套 AST。

## 三、核心数据结构

```text
RuleDefinition
  id, priority, fireMode(Rising|Level), once, cooldownTicks
  condition : decision::Condition
  watchKeys : 从 AST 抽出的 fact 键（可显式覆盖）
  actions   : [{ kind, args:Value }]

FactStore
  values / tags / attributes / resources / states / authorities
  → 实现 EvaluationContext，供 Condition::evaluate

WatchIndex
  key → sorted unique ruleId 列表

RuleEngine
  catalogue + factStore + watchIndex + pending eval set + activation queue
```

### 3.1 Fact 键约定

| Condition 叶子 | Fact 命名空间 | 写入 API |
|---|---|---|
| `compare` / `value` | `value:<key>` | `setValue` |
| `hasTag` | `tag:<tag>` | `setTag` |
| `hasAttribute` | `attr:<key>` | `setAttribute` |
| `hasResource` | `resource:<key>` | `setResource` |
| `stateEquals` | `state:<key>` | `setState` |
| `authorityCheck` | `authority:<scope>` | `setAuthority` |
| `policyCall` | `policy:<name>`（声明的 dependencies） | 外部策略 |

未声明 watch 且含 `policyCall` 而无 dependencies 的规则在注册时失败——
否则引擎无法保证“不全表扫描”。

### 3.2 火控语义

| FireMode | 行为 |
|---|---|
| `Rising`（默认） | 仅 `prevPassed=false && nowPassed=true` |
| `Level` | 每次唤醒且条件为真时激活（仍受 cooldown / once 约束） |

`once=true`：成功激活后禁用，直到 `resetRule(id)`。
`cooldownTicks`：以 `drain(tick)` 注入的仿真 tick 计量。

## 四、热路径复杂度

设 `R` = 规则总数，`W(k)` = 订阅键 `k` 的规则数，`C` = 单规则条件求值成本。

| 操作 | 复杂度 | 说明 |
|---|---|---|
| `set*` 且值未变 | `O(1)` | 无唤醒 |
| `set*` 且值变化 | `O(W(k))` | 仅标记订阅者 dirty |
| `drain` | `O(Σ dirty · C + A log A)` | `A` 为本批激活数 |
| 全表扫描 | **不做** | 注册期强制可索引 |

上万规则、每次只改一个冷门键时，工作量约等于该键上的少量订阅者，与 `R` 无关。

## 五、与任务 / 经济 / 剧情的组合

```text
世界系统 ──setFact──► RuleEngine ──drain──► Activation
                                              │
                    ┌─────────────────────────┼─────────────────────────┐
                    ▼                         ▼                         ▼
              fact.set（内置级联）      IEconomy（economy.*）   IEmergenceActionHandler
                    │                                                   │
                    └──────────► 再 dirty ──► 同批或下轮 drain           │
                                                                        ▼
                                                         quest.notify / story.begin / …
```

推荐动作词表（稳定字符串）：

| kind | args | 执行方 |
|---|---|---|
| `fact.set` | `{domain,key,value}` | RuleEngine 内置 |
| `economy.credit` / `economy.debit` | `{player,type,amount}` | `cap::query<IEconomy>()` |
| `quest.notify` | `{topic,target,amount}` | Handler / 脚本 |
| `quest.activate` | `{id}` | Handler / 脚本 |
| `story.begin` | `{eventId}` | Handler / 脚本 |
| `emit` | `{type,payload}` | 仅写入激活日志，供 UI/遥测 |

游戏脚本典型编排：

```squirrel
local engine = eve.Emergence().newEngine();
engine.replaceCatalogueJson(rulesJson);
engine.setValue("gold", 0);
// … 经济模块入账后镜像到 fact …
engine.setResource("gold", economy.get(0, "gold"));
local n = engine.drain(tick);
for (local i = 0; i < n; i++) {
    local act = engine.activationAt(i);
    // 或依赖已注册的 IEmergenceActionHandler
}
```

## 六、持久化

- 目录：`eve.emergence.rules` schema v1（定义侧，可热替换，失败保留旧目录）。
- 运行时：`snapshotJson` / `restoreJson` 保存 fact + 每规则 `passed/fired/cooldownUntil`；
  未知字段拒绝；失败事务性回滚。

## 七、非目标（首版）

- 不做完整 Rete 共享 alpha 网络（可后续对高频叶子做共享 memo）。
- 不内置剧情演出机或任务状态机（已有 `StoryEvent` / `QuestSystem`）。
- 不在 `update(dt)` 里隐式全量扫描；时间条件应写成 fact（由外部时钟写入）。
