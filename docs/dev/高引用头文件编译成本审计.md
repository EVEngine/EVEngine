# 高引用头文件编译成本审计

本文记录 `make stats/build` 对直接引用影响最高的 20 个工程头文件的
逐项审计。排序指标是 `直接引用翻译单元数 × 头文件源码字节数`；它用于发现
值得人工检查的候选，而不是把头文件行数当作真实编译耗时。真实对象文件大小
仍以同一报告中的 `.o/.obj` 数据为准。

## 审计结果

| 头文件 | 直接引用数 | 模板 | 结论与处理 |
|---|---:|---:|---|
| `graphics/Graphics.h` | 153 | 0 | 多接口基类、按值 GLM 参数及内联默认实现都需要当前依赖；将宽泛的 `glm/glm.hpp` 收窄为实际使用的矩阵和 vec2/3/4 头。本轮不做高风险公共 API 拆分，后续应按 2D、3D、资源和后处理接口继续迁移消费者。 |
| `physics/World3D.h` | 44 | 0 | Box3D ID、查询所有权、快照及多个 STL 容器均直接构成公开签名或成员；保留。 |
| `common/Module.h` | 164 | 2 | 已把模板中的 `unordered_map` 查找和懒创建移入 `Module.cpp`；本轮继续删除未使用的 `<cstdint>`。 |
| `graphics/vulkan/Graphics.h` | 18 | 0 | 后端状态按值持有 frame arena、compute pass、shadow、cluster 和 GPU-driven 布局；依赖真实且仅后端消费者引用，保留，并把宽泛 GLM 聚合头收窄为实际类型头。 |
| `common/Result.h` | 84 | 5 | 开放类型参数不适合集中显式实例化；组合器需要 functional/type-traits/optional。补上实际使用但此前依赖传递包含的 `<vector>`。 |
| `climbing/Climbing.h` | 22 | 0 | 公开数据模型按值组合 anchor、telemetry、query、time、value 和容器；若继续优化应先拆 authoring/runtime API，不能简单前置声明。 |

| `window/Window.h` | 77 | 0 | string/vector 构成 message-box 和 display-mode 公共值类型；保留。 |
| `graphics/Volumetric.h` | 54 | 0 | string、GLM 矩阵/向量及 `unique_ptr` 都是成员；其余图形对象已使用前置声明，无额外清理。 |

## 本轮原则

1. 只删除能由声明和成员使用情况证明不需要的包含，不依赖偶然的传递包含。
2. 指针或引用类型优先前置声明；基类、按值成员、内联访问和常量来源保留完整定义。
3. 模板只有在参数集合封闭且存在真实 `.obj` 证据时才考虑 `extern template`；
   `Result<T>`、capability interface 和 identity tag 都是开放集合，不适合盲目集中实例化。
4. 大型聚合 API 的进一步拆分会触及公共 API 和模块边界，应作为带契约测试的独立重构，
   不以删除 include 为目的强行改变所有权或值语义。
