# 脚本契约架构映射：第一阶段

日期：2026-10-12
状态：首条映射已接入生成器、SDK API 目录及既有 MCP 查询；验证结果见 PR。不是完整架构图或运行时因果追踪。

## 范围与使用

落实 [Semantic World Database 设计 PR](https://github.com/EVEngine/EVEngine/pull/524)的第一阶段：从实际脚本接口查到绑定、C++ 实现、状态 owner 与测试。选择 `eve.SceneNodeRef.setVisible`，通过既有 `eve_api_get` 的 key `scene/SceneNodeRef.setVisible` 查询，不增加平行工具。

离线生成：

```sh
python scripts/generate_binding_contracts.py --modules scene --platform win32 --json-output eve-api.json
```

不传 `--modules` 表示源码目录中的完整候选集合，不代表某个构建全部可用。实际构建使用其启用模块和平台生成 API 目录；裁剪 scene 后该契约完全缺席。未知 key 仍使用已有未找到响应。

## 单一来源与证据

签名、脚本名、绑定位置与直接 C++ 目标来自实际 `addFunc`。`source` 给出注册位置，`cppSymbol` 仅在直接成员目标可确定时提供，lambda / 动态包装不猜测唯一内部目标。

领域信息由 scene 拥有的 [`binding_architecture.json`](../../src/modules/scene/binding_architecture.json)提供：owner、写入字段、测试引用和限制。它不重复参数签名，不改变运行时状态，也不把旧 bool API 改成新协议。生成器验证真实实现定义、owner / 字段锚点及实际测试登记，坏引用或启用模块中的绑定消失导致生成失败。

映射返回 `architecture.status=mapped`、实现 / owner 源码位置、写入字段、测试引用、`inputHash`、证据类别和限制。hash 覆盖绑定源文件、元数据及实现 / owner / 测试证据的规范化内容，不包含绝对工作区路径；它是源码证据指纹，不是运行结果或整套二进制身份。平台另由契约 `platforms` 声明。

证据性质为 `static-binding+reviewed-owner+test-reference`：owner 和 writes 是经过审阅的声明，锚点存在不证明所有权或全部副作用已被自动推导；测试引用不表示本次测试已通过。未接入 owner 元数据的接口返回 `architecture.status=unknown` 及原因，不输出虚构关系。

直接绑定的别名保留自己的 key 和绑定位置，共享实现及领域映射；当前实际案例没有增加新别名，别名规则由生成器 fixture 验证。元数据和映射证据文件是构建生成步骤的显式依赖，改变后重新生成，避免 SDK JSON 与运行时注册内容漂移。

## 真实行为与边界

链路为 Scene.cpp 注册 → SceneNodeRef::setVisible → host/node 解析 → SceneHost 拥有的 SceneNode.visible 更新及 subtree dirty 标记。无效节点返回 false。该映射不宣称已经追踪后续渲染、导航、物理或全部动态脚本关系，也不提供世界事务。

新增脚本组合测试调用真实绑定，并从 SceneHost 查询字段，验证成功修改和无效节点；独立 MCP stdio 测试读取真实 `eve_api_get`，解析 JSON 并区分 mapped / unknown。生成器测试覆盖别名、动态未知、模块裁剪、移除绑定、注释伪证据、失效引用、路径越界、指纹失效及可重复生成。

## Schema 与代码的分工

第一阶段由 JSON 声明代码无法可靠推导的领域信息（状态 owner、写入字段、测试关联与限制），由绑定源码提取脚本名、参数签名、注册位置和直接 C++ 目标。两者通过 C++ 符号连接，生成结果不作为另一个人工维护源。这里使用静态源码提取，没有加载脚本执行反射，也没有自动推断动态调用关系。

后续持久化类型 ID、版本迁移、字段单位与约束、关系基数和修改权限应使用显式领域 Schema；脚本导出结构和已声明注解可通过提取或隔离反射生成。运行时读写与因果关系需要独立追踪证据。代码事实与声明契约不兼容时报告错误，不静默覆盖；这些后续能力尚未实现。

## 演化策略

`eve.binding-api` v1 增加可选信息，保留现有字段及调用语义；内部 `architecture` mapped 记录携带 `schemaVersion=1`。消费者忽略未知字段并检查 status；不认识 mapping 版本时停止使用架构证据。领域侧车必须以支持的 schema / version 加载，不接受未知版本。

扩展第二个领域前评审元数据结构、测试引用粒度和生成依赖登记方式。不自动将字符串目标解析、注释或事件名当作已验证因果边。现阶段不承诺源码提取覆盖所有 C++ 表达式，无法证明的关系保持未知。
