# 物理烘焙重采样误差基线

本次测量回答：同一次真实仿真的帧序列降低录制频率后，生产播放器相对原始帧的偏差有多大。
它不测物理解算器相对现实的误差，不比较不同后端，也不代表碰撞、撕裂或高速特效的最坏情况。

## 可复现方法

测试源：`test/integration/physics-bake/resampling_error.cpp`，宿主 `unit_test_physics`。
Linux GCC Debug，实际调用 World3D、Cloth3D、Rope3D 和生产 capture/track 接口，无窗口/GPU。

- 参考：固定外部步长 1/120 秒、240 步，共 241 帧，重力 (0,-9.81,0)，无随机输入。
- 刚体：0.5 m 立方体，从 (0,3,0) 下落，线速度 (2,0,0) m/s、角速度 (0,3,0) rad/s，阻尼为零，无地面。
- 布料：8×8、间距 0.2 m，初始 XZ 平面，顶边固定，使用该版本 Cloth3D 默认约束/阻尼。
- 绳索：16 节点，从 (0,3,0) 到 (3,3,0)，第零节点固定，其余使用该版本 Rope3D 默认参数。
- 分别保留每 1/2/4/8 帧，对应 120/60/30/15 Hz；各片段包含相同首尾时刻。
- 源世界/布料/绳索销毁后，按原始全部 241 个时刻调用生产 track 采样。参考是 owning 捕获值，不重新跑一次仿真。
- 位置误差为每对象/顶点欧氏距离；最大值跨时间与顶点，RMS 为这些距离平方的均值开根。
- 旋转误差为归一化四元数绝对点积对应的最短夹角 `2 acos(clamp(abs(dot)/(norm(a)norm(b))))`，单位 rad。
- 布料每档 15424 个顶点样本，绳索 3856 个，刚体 241 个。内部 solver 子步沿用实现，120 Hz 指外部参考帧率。

运行（使用正常主机依赖环境）：

```sh
cmake --build build/linux-debug --target unit_test_physics -j4
ctest --test-dir build/linux-debug --no-tests=error -R 'physics.bake.(deform|rigid)ResamplingErrorAgainstLiveReference' -V
```

## 测得结果

所有 120 Hz 位置/顶点误差为零，保留关键帧的位置误差均低于 1e-5 m。
刚体 120 Hz 最大旋转误差 7.30e-8 rad，来自浮点归一化/夹角计算。

| 采样率 | 刚体位置 max / RMS (mm) | 布料顶点 max / RMS (mm) | 绳索顶点 max / RMS (mm) | 刚体旋转 max / RMS (rad) |
|---|---:|---:|---:|---:|
| 60 Hz | 0.342 / 0.240 | 0.889 / 0.131 | 0.328 / 0.0630 | 2.49e-7 / 5.74e-8 |
| 30 Hz | 1.366 / 0.991 | 3.635 / 0.531 | 1.262 / 0.259 | 4.21e-6 / 2.76e-6 |
| 15 Hz | 5.452 / 3.971 | 8.758 / 1.984 | 4.677 / 1.033 | 3.16e-5 / 2.29e-5 |

本组场景的回归预算：60 Hz 最大位置/顶点误差 <1 mm，30 Hz <5 mm，15 Hz <10 mm；
刚体最大角误差 <1e-4 rad。测试同时要求场景实际运动，避免静态/空采集误通过。
这些是固定测试场景的预算；选择生产采样间隔应对目标资产重复测量，不能从此推导任意特效精度。

测试包含所有参考时刻，RMS 含误差为零的关键帧，因此不能称为“仅插值帧 RMS”。
没有测 120 Hz 参考时刻之间的误差、接触瞬态、碎块角运动、粒子生灭/外观或序列化误差；
这些是独立验收维度。本轮保持现有插值算法，没有以测量结果偷偷更换算法或来源身份。

原始本地日志：`/tmp/evengine-bake-error-final-tests.log`。本表为功能精度测量，没有 CPU/GPU 性能结论。

## 粒子实时表现与生灭对照

`physics.bake.particleReplayMatchesLiveAppearanceAndLifetime` 使用真实 CPU 发射器、种子 314，
以 1/64 秒步长运行 1 秒，每 8 步发射一个粒子，共 8 个 birth。寿命 0.2 秒、速度 10–20、
重力 Y=30、尺寸 1→3、RGBA 随生命变化、旋转有非零 spin，并使用 4 帧 atlas。
该二进制可精确表示的时间步用于隔离生命周期合同，不证明任意时间戳都能无损转为 float。

每个外部 tick 保存实时 `evaluateParticleAppearance` 值及 birthSerial，随后结束录制并销毁
发射器，再通过生产 `buildParticleTrack` 重建独立轨道。比较全部 64 个参考时刻的可见身份集合
与 x/y/w/h/rotation/RGBA/UV 共 13 字段，每字段绝对容差 1e-5（各自原单位）。
额外验证 8 个死亡事件：精确死亡时刻不可见、前一个可表示 float 时刻仍可见；终点为空。
这同时覆盖活粒子数组压缩后的身份保留。测试要求尺寸、透明度和旋转实际变化，避免静态假阳性。

Linux Debug 的 `unit_test_particles` 对照测试通过，1638 个断言，无窗口/GPU。
日志 `/tmp/evengine-bake-particle-reference-tests.log`。此为完整采样率下的表现一致性证据，
不把它称为降采样误差基线、GPU 粒子录制、跨平台确定性或像素级渲染对照。

## 房屋碎块资产降采样反例

新增独立工具 `test/profile/physics_bake/collapse_error.cpp`，链接生产用纯播放库，
对已存储资产采样后按 stride 重新捕获，再逐骨比较。输入显式给定参考频率，
不把 frameCount 当作时间戳证据。当前结果来自 cottage-faacc0039a21c49593ac0b817c5651d6.evecollapse，
507 骨、16 秒；60 Hz 参考网格共 487227 个姿态。原始日志
`/tmp/evengine-collapse-error-measurements.log`。

| 4 | 241 | 2.24256 | 0.00756723 | 0.821093 | 881 |

三个稀疏版本的位置峰值均在 7.98333 秒、骨 427。该定位尚不能证明峰值
由碰撞、状态切换还是源姿态不连续引起，需要进一步对照原始求解与生产者日志。
这组反例证明平均误差小并不足以接受降采样；当前房屋示例保留逐步捕获，
不把这里的稀疏重建作为生产资产。此结果以资产 sampler 为参考，不证明原始

的解析旋转：120 Hz 捕获、240 Hz 查询，角误差必须小于 1e-5 rad；只存首尾
则中点误差超过 3.14 rad。源先销毁，再做采样。它固定了最短弧插值的适用边界，
并非实际碎块高速碰撞验证。纯运行时 CTest 25/25 通过。

诊断工具现在输出峰值前后 stride 个参考网格点，日志

因此该位置峰值不是同一骨的 Attached/Detached 标签切换；源资产本身在一个

无需修改播放器来掩盖这份输入；下一步用独立、可控的真实落地样本隔离碰撞段误差。

## 真实拆散碎块落地对照

`test/integration/physics-bake/collapse_collision_reference.cpp` 在真实 World3D 中
创建 welded-boxes fixture，施加 strain 并执行 detach，再为两个碎块设置
(0,8,0) rad/s 角速度和零阻尼。静态地面上表面为 y=0，重力 -9.81 m/s²，
外部步长 1/240 秒、480 步，无随机输入。参考值直接来自活实例的 owning
BonePresentation，与生产 capture 的输出分开保存。世界和实例销毁后才做比较。

用例确认两骨从 y>2.9 下落、0.5 秒时 y<2，结束时 y 在 (0.3,0.8)，排除
无地面的自由落体或全静态夹具。每档比较 962 个姿态；保留帧位置误差 <1e-5 m、
角度误差 <1e-6 rad，所有采样状态一致。稀疏帧误差为测量值，不是任意场景保证。

主机 GCC Debug 构建 exit 0；CTest `physics.bake.collapseCollisionReplayMatchesLiveReference`
