# 可组合 2.5D TileSet 资产管线

日期：2026-08-24  
状态：基础契约与参考实现已落地

## 设计原则

本功能与 `editor` 模块采用同一种产品边界：EVEngine 提供稳定协议、基础构件和可运行参考，不提供一个假设所有项目流程相同的完整成品导入器。

项目拥有以下决定权：

- 输入目录、命名与 GID 规则；
- 自动分析或人工标注 pivot/footprint 的方式；
- atlas 算法、外部工具与构建农场；
- gameplay 标签、阻挡、成本和项目自定义字段；
- 编辑器 UI、检查器和预览呈现；
- 产物缓存、增量构建和发布策略。

引擎只拥有两个边界：阶段协议和 `eve.tileset/1` 运行时契约。

## 组合结构

```text
project tile-pipeline.json
        │
        ├─ built-in stage: scan
        ├─ project stage: naming / metadata / external packer
        ├─ built-in or replacement stage: analyze / pack
        └─ built-in or replacement stage: emit
                         │
                         ▼
              atlas + eve.tileset/1 manifest
                         │
            ┌────────────┴────────────┐
            ▼                         ▼
  TileLayer runtime             project editor host
  region/pivot/depth            overlay/inspector/preview
```

基础实现位于 `tools/tile-pipeline/`。阶段签名为：

```python
def stage(context: PipelineContext, options: dict) -> None:
    ...
```

插件导出 `register(registry)`，以带命名空间的名称注册阶段。阶段可插入、替换或完全绕过内置步骤。Python 工具不是规范本身；任何工具只要生成相同 manifest 都可与运行时组合。

## 运行时契约

`TileLayer.loadTilesetManifest(path)` 载入独立 TileSet，不修改地图尺寸或 GID。每个 tile visual 支持：

- `region [x,y,w,h]`：不规则 atlas 区域；
- `pivot [x,y]`：区域内与投影格原点对齐的点；
- `sortBias`：对 `depthY` 的项目可调偏移；
- `footprint`、`walkable`、`cost`：与视觉同源保存的 gameplay 元数据；
- 未识别字段保持为工具侧扩展空间，运行时无需理解所有项目语义。

规则 atlas 的 `firstGid/columns/tilewidth/tileheight/margin/spacing` 路径保持不变。没有 visual 记录的 GID 自动回退原有规则 atlas 算法。

脚本也可直接调用 `setTileVisual` / `setTileMetadata`，因此程序化工具或实时编辑器不必先落盘 manifest。

## 编辑器组合

不新增“2.5D 编辑器窗口”。项目编辑器继续使用：

- `EditorSession` 组织工具生命周期；
- `ScriptEditorTool` 实现项目手势；
- `IEditorOverlay` 显示逻辑菱形、视觉 bounds、pivot、footprint 和路径；
- `IEditorInspector` 编辑同一 manifest 中的字段；
- `TileBuffer` / `Brush` 编辑逻辑 GID，`TileLayer` 负责最终投影预览。

推荐项目工具把 manifest 当成唯一编辑数据，保存后触发 pipeline 或直接热重载 TileSet。这样命令行、编辑器和 CI 消费同一契约，而不是维护三份配置。

## 可观察性

`Map` 暴露最近一次收集的：

- `getLastVisibleTileCount()`；
- `getLastCustomVisualCount()`；
- `getLastAtlasCount()`。

这些只是无 UI 的计数构件。项目可以把它们放进自己的调试 HUD、遥测或预算门禁。后续 chunk/culling 也应沿此原则追加指标，而不是硬编码性能面板。

## 扩展与兼容

`schema` 使用 `eve.tileset/1`。v1 读取器忽略未知字段；新增项目字段不要求升级引擎。改变 `region/pivot` 语义才需要新主版本。工具应把源文件、pipeline 配置和 stage 列表写入产物追踪信息，以便复现。

当前参考 packer 是确定性的 shelf packer，目标是可理解、可替换和零第三方依赖，不是追求最优利用率。生产项目可换成 TexturePacker/Aseprite/内部服务，并保留 `emit` 或自行生成契约。

## 验证基准

`examples/iso-grid-walk` 是垂直切片：原始独立 PNG 经项目 JSON 生成 atlas/manifest，三个显示 TileLayer 直接消费 manifest，逻辑 TileLayer 继续承担拾取与 A*。示例不再逐纹理手工绘制。
