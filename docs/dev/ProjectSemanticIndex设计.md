# Project Semantic Index：项目语义索引

日期：2026-10-12。状态：首条真实链路已实现；其余领域与大型项目能力仍是后续设计。关联：[架构行为图与任务上下文](架构行为图与任务上下文.md)。

## 目标与知识边界

引擎接口图解释引擎能力，项目索引解释当前游戏的内容与连接。Agent 不应只得到一组脚本和数据文件，而应能够查询任务、事件、流程、场景实体、脚本符号、生成工具及引擎契约的身份、类型、来源、关系和版本。

显式 Schema 描述领域含义和约束；源码／结构解析描述实际符号与字段；关系图连接依赖和流程；向量检索将来用于自然语言候选召回；运行时追踪将来提供实际执行证据。向量相似度不能代替引用检查、规则校验或运行证明。

首条链路选择真实 `rpg-classic` 项目：清剿史莱姆任务领奖 → `quest.completed` 事件 → `onQuestCompleted` 脚本 → `quest.slayer.marker` 场景节点 → `SceneNodeRef.setVisible` → 项目回归探针。该场景节点控制任务 NPC 的完成标识。任务和奖励仍以 RPG 原有 owner／事务为权威，索引不修改游戏状态。

## 来源与声明

`game.semantic.json` 使用 `eve.project-semantic` v1，声明项目 ID、稳定语义节点 ID、节点角色、来源选择器和关系。它不重复接口签名，也不是游戏状态存档。JSON ID 选择器可以要求字段存在；脚本选择器以唯一函数符号定位，并可检查函数体中的声明锚点。引擎接口选择器必须在当前构建注册表中存在。

解析器同时收集项目 JSON 的对象、数组和字段类型，以及 EveScript 函数等源码元数据。领域节点由显式声明关联到这些实际记录。未带稳定语义 ID 的结构位置只是导航地址，不承诺跨结构重排保持不变。

证据分开记录：JSON 字段与脚本符号为解析结果；任务／事件／实体关系为已检查来源的项目声明；引擎契约来自当前链接构建；测试节点表示可运行测试的引用。引用存在不表示本次测试通过，也不表示任意动态脚本调用已经被证明。项目文本始终作为不可信内容，不作为 Agent 的指令。

## 增量更新、删除与重命名

扫描当前项目内容集，按内容摘要判断变化。未改变的文件复用解析记录，仅重解析新增／修改文件，随后重建跨文件关系并发布候选快照。新增、修改、删除和唯一内容匹配的重命名分别报告。

被删除文件的记录必须移除；缺失／歧义来源的节点和关系必须报告未知，不能继续返回旧有效关系。文件重命名后，显式语义节点通过 JSON ID 或唯一符号重新定位，身份不依赖旧路径。索引不自动修改游戏代码中的文件引用；例如 `dofile` 仍指向旧文件时，应报告断裂，直到项目修复引用。

无效清单、扫描失败或超出输入预算不得发布半个快照，也不得把上次成功结果伪装成当前索引。普通来源文件解析失败应成为可见诊断，并使相关关系失效。当前实现是进程内增量缓存；持久索引、后台文件监听、并发多 Agent 提交与 MVCC 属于后续工作。

## 有版本的 Agent 上下文包

版本摘要覆盖项目 ID、清单、当前文件路径／内容摘要及所引用引擎契约。绝对工作区路径不进入摘要。版本表示内容证据身份，不是帧号或完整二进制身份；文件改动、删除、重命名和引擎契约变化都必须使它失效。

刷新工具提供版本、来源统计和已声明语义入口。查询工具支持按种子或类型检索。既有 `eve_task_context` 增加项目模式，返回任务描述、相关项目子图、字段／符号证据、来源、引擎契约、测试引用、未知项及版本。`expectedRevision` 不匹配时拒绝旧上下文，并提示重新获取；不静默替换调用者的预期版本。

输出使用节点、深度和 JSON 字节预算。截断与预算拒绝可见，未知覆盖可见；任务上下文不得自称完整项目。输入扫描也有文件数量、单文件字节、总字节和解析深度上限。忽略构建／依赖／缓存目录，不跟随项目内符号链接，不执行索引到的代码。

## 实施与后续范围

当前实施范围：原生开发工具服务、JSON 结构与 EveScript 元数据解析、显式链路验证、增量刷新和版本上下文；真实项目和真实脚本回归测试验证链路。刷新为显式调用，查询会核对当前内容版本。

### 首条实现的使用方式

桌面 devtools 提供 `eve_project_index_refresh`、`eve_project_index_query`；已有 `eve_task_context` 通过 `projectDir` 切换到项目模式。索引清单不自行调用 AI，也不执行清单内的代码或工具。调用方在开始任务和实际修改前刷新并核对证据版本。

```json
{"projectDir":"<rpg-classic 的绝对路径>"}
```

先将上述参数传给 `eve_project_index_refresh`，再将返回的 `revision` 传给 `eve_task_context`：

```json
{
  "projectDir":"<同一绝对路径>",
  "seed":"quest:quest.slayer",
  "task":"修改任务完成时 NPC 的场景标识",
  "expectedRevision":"<刷新返回的 SHA-256>",
  "maxNodes":64,
  "maxDepth":8,
  "maxBytes":32768
}
```

项目上下文使用 `eve.project-context` v1，含项目 ID／目录、版本、节点、边、来源文件／JSON Pointer 或行号／内容摘要、字段定义或函数片段、引擎契约、测试引用和诊断。`declarationsResolved` 只表示本次声明检查没有诊断；`coverage=partial-project` 明确不承诺自动理解整个游戏。无种子查询可按 `kind` 与 `query` 筛选；例如 `kind=json_integer` 查询原始 JSON 整数字段。双向邻域提供候选影响，不能推断动态分支的实际执行。

输入限额：512 个受支持文件、单文件 2 MiB、总量 32 MiB、JSON 深度 64、结构节点 16384、语义节点 256、声明关系 1024。支持 `.json/.nut/.dnut/.md`；`.dnut` 暂作不透明文件记录。输出限额：节点 1–256、深度 0–8、载荷 1024–65536 字节，项目模式默认 64／8／32768。最多缓存四个项目；每次仍读取并摘要文件，仅解析阶段增量复用，修改后重建关系。当前不是百万文件索引器，应先补持久化、依赖级重建和领域适配再放大规模。

缓存由主 MCP poll 线程拥有；返回 JSON 独立拥有数据，没有运行时裸指针。候选发布前复核读集；文件系统并不提供事务快照，稍后的改动仍须重新核对版本。错误码包括 `project_index_failed`、`stale_project_revision`、`unknown_seed`、`invalid_query`、`context_budget_exceeded`。普通来源错误进入 `diagnostics`，断裂关系不会出现在返回子图。

项目的事件日志只承担临时显示投影，不进入 RPG 存档。脚本生成明确的 UUIDv4 格式事件 ID；使用玩法 RNG，不承诺跨运行的持久身份或安全随机性。领奖事实由原有 RPG 事务确认，读档／新游戏按权威任务状态恢复 Scene 可见性，避免伪造完成事件。持久因果日志须另行设计存档与身份来源。

### 验证入口

`test/mcp_project_index.cpp` 验证完整六类链路、上下文版本、文件复用、内容修改、中文路径重命名、删除、坏清单／来源、歧义、预算及 MCP stdio；`test/rpg_classic_semantic_index.cpp` 真正执行项目的 `quest_scene.nut` 与 `tests/quest_scene_probe.nut`，检查任务领奖前后、事件内容和原生 SceneHost 节点状态。已有真实主脚本编译和双任务存档恢复测试继续作为回归。

```sh
ctest --test-dir <engine-build> -R 'projectIndex|semanticQuestEventSceneRuntime' --output-on-failure
```

测试引用与本次验证结果分离。索引返回测试引用不代表任意将来的修改已经通过测试，也不把来源声明提升为完整静态调用图或运行时因果追踪。

下一步按领域增加版本化适配器：对话／故事 DSL、Scene／Prefab、资源引用、编辑器与项目导出工具、生成器输入输出和规则 Schema。适配器应共享身份、证据、删除失效及诊断协议。二进制资源、动态调用目标、运行时事件因果、持久搜索索引、向量数据库和完整语言 AST 尚不属于首条实现。

验收必须覆盖：真实任务领奖前不产生完成事件，领奖后事件驱动场景状态；索引能返回完整六类链路与引擎契约；不变文件不重解析；修改／删除／重命名使版本变化且不会泄露旧关系；坏清单、坏引用、路径边界、预算和旧版本拒绝都有测试；通过真实 MCP 调用获取项目上下文。
