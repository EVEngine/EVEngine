# Database 数据库模块

`database` 模块使用 third-party 中的 **POCO Data**。当前内置并注册 SQLite Connector；`connect(connector, connectionString)` 保留 POCO Connector 名称，因此在链接相应 POCO Connector 后可使用 MySQL、PostgreSQL、ODBC 等后端。

## C++ API

```cpp
auto *database = eve::database::Database::create();
std::unique_ptr<eve::database::Connection> db(database->connectSQLite("save/game.db"));
db->execute("CREATE TABLE IF NOT EXISTS player (id INTEGER, name TEXT, hp REAL)");
db->insert("player", {{"id", int64_t(1)}, {"name", "Ada"}, {"hp", 100.0}});
auto rows = db->query("SELECT * FROM player");
db->update("player", {{"hp", 80.0}}, "id=1");
db->remove("player", "id=1");
```

`Value` 支持 NULL、64 位整数、浮点、字符串及布尔值。表名和列名始终由模块引用；`whereClause` 与 `execute/query` 是原始 SQL，只应由可信代码构造。

### ORM

`Mapping<T>` 明确描述表名、SQL 类型、主键和字段读写函数，避免运行时反射。`Repository<T>` 在映射之上提供建表以及类型安全的 insert/find/all/update/remove，才是模块的完整 ORM 层：

```cpp
struct Player { int64_t id; std::string name; };
eve::database::Mapping<Player> players{"player", {
  {"id", [](const Player& p) -> Value { return p.id; },
         [](Player& p, const Value& v) { p.id = std::get<int64_t>(v); }, "INTEGER", true},
  {"name", [](const Player& p) -> Value { return p.name; },
           [](Player& p, const Value& v) { p.name = std::get<std::string>(v); }}
}};
eve::database::Repository<Player> repo(*db, players);
repo.createTable();
repo.insert(Player{1, "Ada"});
Player loaded;
repo.find(int64_t(1), loaded);
loaded.name = "Grace";
repo.update(loaded);
auto all = repo.all();
repo.remove(int64_t(1));
```

### ECS 导出

`exportECS` 接收任意可迭代 ECS View，以及把 View 元素转换为 `Row` 的 mapper。所有行处于同一事务中；失败时自动回滚。这种适配方式不要求 ECS 组件具备反射，也能直接用于 `ecs::View`。

```cpp
auto view = ecs::View<PlayerEntity, PlayerEntity::Stats>();
db->exportECS("player", view, [](const auto& item) {
  auto [stats] = item;
  return Row{{"id", int64_t(stats->id)}, {"hp", double(stats->hp)}};
});
```

## Squirrel API

模块入口为 `eve.Database()`，连接对象类型为 `DatabaseConnection`。脚本使用 JSON 对象传递动态列值，查询也返回 JSON，避免丢失 SQL 的动态列结构。

```squirrel
database <- eve.Database();
db <- database.connectSQLite("save/game.db");
db.execute("CREATE TABLE IF NOT EXISTS player (id INTEGER, name TEXT, hp REAL)");
db.insertJson("player", @"{""id"":1,""name"":""Ada"",""hp"":100}");
db.updateJson("player", @"{""hp"":80}", "id=1");
local json = db.queryJson("SELECT * FROM player ORDER BY id");
db.remove("player", "id=1");
db.close();
```

脚本也可创建以表名和主键为身份的运行时 ORM Model，之后不必在每次操作时重复传表名或拼接 where：

```squirrel
players <- db.model("player", "id");
players.insertJson(@"{""id"":2,""name"":""Lin"",""hp"":90}");
local player = players.findJson("2"); // id 参数是 JSON 标量，也可传 @"""player-2"""
players.updateJson("2", @"{""hp"":95}");
local allPlayers = players.allJson();
players.remove("2");
```

### 排序、过滤与分页

对于大量人物数据，不能把全表读入内存后再用脚本排序。`DatabaseQuery` 会组合 SQL 过滤、排序和分页，并校验运算符、引用列名和值：

```squirrel
// 统率 >= 80，按统率降序、年龄升序，只取第 21~40 名。
local q = officers.query();
q.where("leadership", ">=", "80");
q.orderBy("leadership", false);
q.orderBy("age", true);
q.limit(20);
q.offset(20);
local page = q.allJson();
local total = q.count(); // count 忽略分页，返回满足过滤条件的总数
```

C++ 的 `Repository<T>::select` 使用相同查询器并返回类型化实体：

```cpp
auto candidates = officerRepo.select([](Query& q) {
    q.where("force_id", "=", int64_t(3))
     ->where("loyalty", "<", int64_t(70))
     ->orderBy("leadership", false)
     ->limit(50);
});
```

## 面向《三国志 10》规模数据的设计评估

仅有最初的 `Row + insert/update/query` **不满足**此类游戏：它会迫使脚本拼 SQL、全量加载后排序，而且无法表达稳定主键和实体生命周期。本模块现在将 API 分为三层：

1. `Connection`：迁移、复杂联表和调试所需的底层 SQL 逃生舱。
2. `Repository<T>`：C++ 游戏系统使用的类型化实体 CRUD、建表和查询。
3. `DatabaseModel + DatabaseQuery`：脚本使用的运行时模型、组合过滤、复合排序、count 和分页。

推荐把数据正规化，而不是为每个人物建立独立表。例如：

```sql
CREATE TABLE officers (
  id INTEGER PRIMARY KEY, name TEXT NOT NULL, force_id INTEGER,
  leadership INTEGER, war INTEGER, intelligence INTEGER,
  politics INTEGER, charisma INTEGER, loyalty INTEGER, age INTEGER
);
CREATE TABLE officer_skills (officer_id INTEGER, skill_id TEXT,
  level INTEGER, PRIMARY KEY(officer_id, skill_id));
CREATE TABLE relationships (from_id INTEGER, to_id INTEGER,
  kind TEXT, affinity INTEGER, PRIMARY KEY(from_id, to_id, kind));
CREATE INDEX idx_officer_force_leadership
  ON officers(force_id, leadership DESC);
CREATE INDEX idx_relationship_target ON relationships(to_id, kind);
```

具体任务与执行位置：

- “列出曹操势力统率最高的 20 人”：`force_id = ?` + `leadership DESC` + `limit(20)`，由数据库索引完成。
- “找忠诚低于 70 且智力高于 80 的可登用人物”：组合两个 `where`，不把数千人物加载进 ECS。
- “显示人物关系”：关系属于多对多表，应使用联表 SQL或专用 Repository，而不是塞进人物 JSON 字段。
- “进入战斗场景”：数据库负责持久化；只把参战人物投影到 ECS，战斗结束后在事务中回写变化。ECS 不应成为全世界人物数据库的常驻副本。

当前边界也需要明确：查询器目前支持单表 `= != < <= > >= LIKE`、复合排序和分页；复杂 JOIN、聚合报表仍通过 `Connection::query` 使用明确 SQL。生产项目下一阶段应增加迁移版本、外键声明、批量 upsert、事务/Unit of Work、后台只读连接池与领域缓存失效机制，而不是把这些隐式塞进 ORM。

导出的脚本 API：

- `Database.connect(connector, connectionString)` / `connectSQLite(path)`
- `DatabaseConnection.isConnected()` / `close()`
- `execute(sql)` / `queryJson(sql)`
- `insertJson(table, objectJson)` / `updateJson(table, objectJson, whereClause)` / `remove(table, whereClause)`
- `DatabaseConnection.model(table, primaryKey)` → `DatabaseModel`
- `DatabaseConnection.from(table)` → `DatabaseQuery`
- `DatabaseModel.insertJson(objectJson)` / `findJson(idJson)` / `allJson()` / `updateJson(idJson, objectJson)` / `remove(idJson)`
- `DatabaseModel.query()` → `DatabaseQuery`
- `DatabaseQuery.where(column, op, valueJson)` / `orderBy(column, ascending)` / `limit(count)` / `offset(count)`
- `DatabaseQuery.allJson()` / `firstJson()` / `count()`
