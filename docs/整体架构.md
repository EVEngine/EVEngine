EVEngine整体架构
============

### 目标

创建一个能够在游戏运行中快速重载状态进行修改测试的2d游戏引擎，方便游戏的原型设计和快速修改。在游戏中代码的修改能快速反应到当前的游戏运行状态上。

### 基本技术选型

框架 C++20、cmake、zeroerr

脚本语言 squirrel
  一款带类和多态的脚本语言非常适合游戏，这个语言本身也是为此而设计的

脚本绑定 simplesquirrel
  这个绑定库非常好用，可以简单地把C++类导出并支持squirrel继承C++类

图形系统 vulkan
  vulkan是opengl的替代，选用其的主要原因是mac下opengl不再更新，并且不能使用compute shader
  vulkan整体写起来复杂，但优化上限较高，潜力很大


### 核心特性

1. 类似love的简版引擎，可选节点树支持
2. 解释运行，在文件夹中放好脚本和资源，直接在当前目录就可以用引擎运行游戏
3. 热重载，随时监听文件系统变动，脚本和资源改变时可以不重启引擎直接刷新
4. 状态热更新，代码修改时，对应被影响到的游戏状态机会自动刷新
5. 运行快照，可以在游戏运行中的任意帧中断、恢复、记录、重新执行、刷新代码后重新执行
6. 脚本反射，假如你继承了类，可以根据模型自动生成编辑用的GUI
7. ORM模型，在有数据库的时候会联动数据库
8. 开发工具，可以在运行时临时修改对象的状态，并提供写入初始数据的功能

### 接口设计原则

squirrel因为采取类C语言设计，这类尽可能地采用以下设计原则来建立接口：
1. 避免使用enum，直接使用string作为枚举参数类型，避免类似love的复杂string mapping，且string的长度需控制在15个字符以内，用值传递，接口内需尽量避免多次字符串比较
2. 单返回值设计，squirrel不支持多返回接口
3. 只有在真正有会导致崩溃的问题时抛出异常，其他可以解决的，不采用异常
4. 所有模块类采用C++端分配和内存管理，squirrel侧在获取模块后不会负责析构模块
5. 所有其他类采用squirrel端内存管理，squirrel侧主动创建对象并负责析构
6. 尽量在squirrel中使用继承来扩展已有C++类来实现功能
7. 能用多个参数解决问题时，避免过多地使用结构体，一般只有4个参数及以上有必要定义结构体，能使用pair或tuple时可以使用。
8. 默认值支持，大部分函数可以通过默认值减少参数的输入，C++中的默认值和squirrel的默认值一致
