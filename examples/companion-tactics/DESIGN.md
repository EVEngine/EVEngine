# 队友 AI：能力驱动的协作框架

## 目标与已实现边界

目标是让角色根据自身能力、队伍需要和玩家指挥自主行动。当前以 2D 战术沙场验证决策、协调和执行闭环；相同决策设计可以接到 3D 动作角色。本例不修改引擎公共 API，不建立新模块或新的实体继承体系。

真实运行链：公开的敌人预警/队友状态 → 候选行动合法性 → 效用评分 → 治疗预约 → `NpcAiWorld` 黑板/状态转换 → 游戏宿主执行 → 效果与决策观察。

每个队友使用原生 generation handle。宿主每次决策写入 `intent`，调用 `NpcAiWorld.tick`，并读取实际 `activeState` 决定执行。无自定义并行状态机；`unit.state` 仅是该次快照的展示/执行投影。原生 task service 目前没有脚本扩展入口，所以技能执行位于示例宿主，没有伪装为 C++ task service。

## 能力与策略

技能描述包含效果语义、距离、施法时间、冷却、消耗和强度。候选行动明确携带技能索引、目标、分数和原因。相同技能能装备给不同队友；治疗权重、保护权重、攻击权重决定偏好。

评分前排除死亡目标、不匹配阵营、资源不足、冷却和过远目标。治疗收益取有效回复量并加濒危奖励；保护要求存在已公开的临近威胁；攻击受集火目标和命令加权。当前任务获得少量分数加成。施法具有承诺期，危险或新命令可取消。

四种命令：

- 均衡：按效用选择，空闲回到玩家附近的编队位置。
- 集火：提高进攻权重，优先当前玩家选择目标；紧急避险仍优先。
- 保护：提高治疗/护盾权重，只攻击玩家附近的敌人。
- 撤退：取消当前施法并回到玩家，禁止队友进攻；自保躲避仍生效。

当前目标信息在开放且无遮挡的小竞技场内可见。没有视线遮挡或感知噪声。AI 仅能使用已经生成的攻击预警，不能读取未开始的攻击。

## 动态站位与支援时效

站位是攻击、治疗、保护都要考虑的独立策略，不再只在空闲时跟随固定偏移点。
下限为 120 像素：大于本例最大以角色为中心的危险圈半径 88 加角色半径；这减少同一目标范围攻击波及队友的概率，不保证任意大范围攻击都无法同时命中。
上限从角色最紧迫的支援技能射程减去 25 像素余量得到：Bastion 护盾射程 210，对应 120–185；Lumen 治疗射程 250，对应 120–225。理想距离分别为 155、180。参数属于本例尺度，不是所有游戏的固定米数。

每次选点采样围绕玩家的 16 个角度、3 个半径，加当前位置。代价同时考虑离玩家过近/过远、两名队友间至少 120 的间距、互助射程、敌人近身压力、技能目标在施法结束时的预计位置、移动成本，以及其他队友的已选目标点。玩家位置使用短期速度预测；边缘候选点裁剪到场地内。旧目标点通过分数滞回保留，移动允许 8 像素停止区，避免不停微调。

普通选点每 0.3 秒重新评估，行动/目标变化立即重算；危险反应继续每 0.1 秒检查。正常移动速度 195，掉出支援带时以 235 追赶，超过玩家 180 的移动速度。普通攻击必须先恢复支援距离，且不能在施法过程中预计掉出支援带；紧急治疗和护盾一旦到达合法施法位置即可施放，不必机械地走到理想点。

玩家突然改变移动方向、导致队友施放普通攻击时掉出支援带，则下次决策取消攻击并追赶；取消仍不扣资源。测试同时检查持续移动过程中的真实技能射程，以及突发移动时的攻击取消。

技能就绪时，支援 ETA = 进入安全射程的移动时间 + 施法时间 + 0.1 秒决策余量。面板还计入当前施法锁定、冷却剩余和法力恢复等待；冷却/回蓝可与赶路并行，已在对该目标施放该技能时显示剩余施法时间。护盾只有 ETA 加 0.05 秒安全余量早于攻击落地才会成为候选；执行也记录 deadline，过期取消，不扣资源。ETA 是当前直线路径和当前速度假设下的估计，不包含障碍物寻路或未来移动变化。技能候选先检查冷却和法力。

危险评估检查沿当前直线移动、在攻击落地时实际会处于哪里，防止终点安全但途中受击。躲避落点还考虑回到支援带和队友间距；避险优先，允许暂时离开理想范围。固定阵容仲裁仍是软约束优化：边界拥挤、不可兼容危险圈、施法锁定和突发方向改变时，不承诺瞬时满足全部距离约束。当前没有障碍物或角色碰撞求解。

画面上的小空心圆是选中的站位点，细线显示队友与玩家的支援关系，玩家周围的圈显示 120 下限、185 护盾带和 225 治疗带。侧栏 `GAP` 是实际距离，`SUPPORT` 是上述支援 ETA；Play Host 同时发布两名队友距离、彼此距离和 ETA。

## 协调与动作生命周期

治疗预约由宿主统一持有，按固定队友顺序仲裁。只有一个队友能预约一个治疗目标。每次 10 Hz 决策重新检查资格并更新预约；施法完成、取消、目标死亡、施法者死亡或销毁世界立即释放。此小规模开放场景采用确定顺序，尚未实现轮转公平或跨队伍预约。

动作分为选定、接近、施法、提交或取消。提交前再次检查存活、距离、法力；成功才同时扣资源、启动冷却和应用效果。取消不消耗资源。两名队友与玩家使用相同 `start/finish/damage` 路径，敌人伤害也进入同一 `damage`，护盾先扣再扣生命。

威胁包含源、圆心、半径、剩余时间。躲避采样 16 个落点，综合所有活跃危险圈和编队距离选择落点；以 350 像素/秒实际移动。死亡的攻击源取消尚未落地的攻击。该实现没有障碍物扫掠、无敌帧或位移技能，因此不可宣称已解决一般 3D 导航安全。

## 权威、生命周期、时间与成本

- 单一权威：`CompanionSimulation` 拥有所有战斗事实；renderer 和 `companionObservation` 只读投影。没有同步另一份 `CombatRuntime` 血量。
- 关系：角色表只含本例固定的五个槽位，目标是 roster 内索引，不是跨域身份。波次重生前所有相关死亡施法已取消。reset 丢弃整个 roster，不复用旧的动作引用。
- 原生 Link：simulation 拥有 `NpcAiWorld`，销毁顺序为释放施法/预约与 agents，之后丢弃 world。native 销毁测试确认 handle stale。禁止外部持有该 world 的 agent。
- 重载：禁用自动 hot reload。R / Play `reset` 完整重建世界和 AI agent。示例没有存档恢复或网络复制承诺。
- 线程：所有宿主和 AI 操作在游戏线程串行执行，无锁、无跨线程 callback、无跨帧借用 C++ 指针。
- 时间：注入 `dt=1/60` 和单调 tick，决策每 6 tick 一次；render 累积时间并保留积压，每帧最多处理 12 步。不使用墙钟或 RNG。保证同一二进制/同一输入序列的确定性，跨平台浮点位级一致性未承诺。
- 成本：行动候选约为队友数 × 技能数 × 角色数；站位约为队友数 × 49 ×（角色数 + 危险数），每 0.3 秒或行动变化时评估；危险落点约为队友数 × 16 × 危险数。行动评分在 10 Hz，执行在 60 Hz。支援带在角色创建时派生，选点上下文每批计算一次。原生模块实例在初始化取得，没有运行时模块字符串查找。
- 格式：原生 behavior 使用已有 schema version 1；Play contract 使用 `evengine.game-agent-contract` version 1，遵守引擎已有校验。没有新增持久格式或自定义迁移。
- 依赖：`npc_ai`、`font`、`keyboard` 是显式必需模块；缺失应由加载器报告，不提供静默替代。这里没有宣称 L1–L4 模块裁剪能力。

## 接入正式动作 RPG 的下一步

先保留策略与技能语义，替换宿主适配边界。战况读取通过 typed observation，动作输出接到 `IAbilityIntentSource` / `AbilityControllerRuntime`，移动接到战斗 locomotion 与 navigation，生命与治疗统一归正式属性/效果权威。当前 `CombatRuntime` 脚本 facade 缺少治疗入口，不能使用负伤害绕过合同。

跨域对象改为现有 `SubjectRef` / typed handle 并逐次验证 generation。队伍协调由战斗宿主服务拥有，向策略提供有限作用域借用；低层 AI 不向上 include 战斗模块。机制选择遵守 R-MECH：低频一对一调用使用显式服务，热点批量快照/意图，跨域关系使用 Link；不引入字符串 capability 查询到每帧循环。

联机阶段由服务器提交最终技能/资源/伤害，客户端呈现已确认动作并做适度预测。网络 snapshot 必须另行定义 schema、版本、未知字段和原子恢复；本例没有网络层。正式引擎修改需补 module-interface、公共 API 的 Result/所有权/线程契约、provider 缺失与裁剪证据、组合测试以及 `make check`。不能把本例的脚本成功视为这些验证已经完成。

## 本例验收

`verification.nut` 直接创建独立模拟并运行实际 native AI。断言互斥预约、有效治疗、护盾吸伤、危险取消及无消耗、位移避险、撤退锁进攻、目标死亡清理、native handle 失效以及两次 3600 tick 状态一致。`verify.py` 通过正式 Play Host 调用测试和命令，采集真实 engine readback 及观察结果。

站位额外断言：重叠出生后分散且留在支援带，队友之间保持治疗射程，持续移动的玩家到达场地边缘后的重新集合，分散站位下护盾赶在攻击前生效，拒绝赶不及的护盾，终点安全但路径在落地时危险的情况。

适用架构要求：单一权威、组合、Result 检查、生命周期、注入时间及真实运行证据。没有 C++ API、ECS System、模块边界或存储格式变更，因此不新增这些层面的 catalogue/编译测试。没有申请或采用规则豁免。
