# White Horizon / 滑雪大冒险

从高处向右下滑行的 2D 物理滑雪示例。顺着雪坡逃离雪崩，越过岩石与松树，
收集金币，在起伏跳台上自然腾空。镜头同时向右、向下跟随，1.2 公里赛道包含
初雪、松岭和雪原三个阶段，各有不同的天空配色。

## 运行

仓库根目录：

```powershell
make run/win32-debug GAME=examples/ski-adventure
```

Linux 已构建环境：`cd examples/ski-adventure && ../../build/linux-debug/src/engine/eve run`。
使用 SDK 时，在本目录执行 `<SDK>/bin/eve run`。

## 操作与规则

| 按键 | 功能 |
| --- | --- |
| Space / W / 上方向键 | 开始、跳跃；空中按住后空翻 |
| S / 下方向键 | 蹲伏，降低阻力 |
| A / 左方向键 | 刹车，增加阻力 |
| P | 暂停 / 继续 |
| R | 重新开始 |

松开跳跃键后，角色逐渐调整到坡面方向。成功完成整圈翻转再落地可以加分，
落地姿态偏差过大会摔倒。跳跃支持提前 140 ms 按键缓冲、离地后 80 ms 容错，
不支持空中连续跳跃。跳台是向上翘起的实体雪坡，速度和接触约束决定腾空，
无需按键，也不靠接近跳台时额外施加冲量。
撞击后速度不足时可以主动跳跃越过坡唇；不要在上坡段持续刹车，否则会停下并倒滑。

撞击或摔倒会减速、缩短雪崩距离，随后有 1.8 秒保护时间；撞过的障碍会破碎，
不再阻挡本局滑行。金币与成功翻转能拉开雪崩距离。雪崩追上即失败，抵达终点即胜利。
三个奖章目标为完成赛道、收集 40 枚金币、完成 3 圈翻转。
得分 = 距离米数（最多 1200）+ 金币 × 25 + 成功翻转圈数 × 250。
最高分仅保留在本次进程中。暂停冻结模拟，重新开始清空上一局的输入和障碍状态。

## 代码与资产

| 文件 | 职责 |
| --- | --- |
| `main.nut` | 生命周期、键盘与玩家等价动作、观察投影 |
| `scripts/course.nut` | 坡面、跳台、分段碰撞采样共用的赛道定义 |
| `scripts/game.nut` | 原生物理、输入缓冲、接触消费、计分、单一阶段状态 |
| `scripts/render.nut` | 镜头投影、缓存纹理、人物姿态、粒子与 HUD |
| `game.agent.json` | `eve_play` 动作与状态合同 |
| `tools/verify.py` | 使用真实玩法路径的自动验收与引擎截图 |
| `tools/generate_masks.py` | 使用 Python 标准库重建三个原创几何遮罩 |

字体随示例提供，授权见 `assets/FONT-NOTICE.txt`。圆形、山峰和线段使用初始化时
加载的微型 PNG 遮罩，减少逐扫描线绘制调用；雪道保留分段绘制。雪花、滑痕和
金币粒子在本地生成，粒子最多 160 个，滑痕最多 60 段，无外部服务或资源下载。
观察值 `drawCalls` 统计脚本提交的绘制调用，不等同于 GPU 底层 draw call。

## 物理与状态契约

`config.nut` 声明键盘、字体和物理模块。模拟在主线程以 120 Hz 固定步长运行，
单帧累计时间上限为 0.1 秒，过载时减慢模拟。世界坐标 +Y 向下，整体雪道向右下降，
跳台局部向上弯曲。重力 980 px/s²，换算为 30 px/m；距离与速度使用相同比例。

角色使用原生 Box2D 动态圆形刚体、静态分段坡面、原生障碍碰撞体。
重力、低摩擦和接触约束负责贴坡、加速、飞跃和落地；蹲伏和刹车改变阻力，
主动跳跃沿坡面法线施加冲量。角色位置和速度只有原生刚体一个真源。
空中旋转是街机姿态和落地计分，刚体本身固定旋转；雪崩是游戏追逐规则。

`phase` 唯一拥有 ready / riding / paused / won / lost 状态，胜负不会同时成立。
接触事件在物理步进后消费，fixture 修改不发生在物理回调内。世界拥有刚体与 fixture，
游戏存续期间不单独销毁。重开先停用角色再重置并激活，确保同一雪段重新生成接触；
同时恢复障碍 sensor、接触缓存与输入。关闭游戏由物理 owner 统一释放。

`ski` 是每帧生成的观察投影，不参与反向修改模拟。`game.agent.json` 提供
`restart / jump / tuck / untuck / flip / release / brake / unbrake / pause` 动作，
与键盘共用玩法入口，不直接修改分数或位置。自动翻转应先 `flip` 再 `jump`，
完成一圈后 `release`。合同采用引擎 schema v1，未知字段遵循 Play Host 的拒绝策略。
本例不实现存档、恢复或热重载；固定赛道与步长不代表跨平台逐位确定性。
验收采用状态条件与数值容差，不承诺墙钟驱动输入产生相同回放。

## 验证

仓库布局与启动检查：

```sh
python3 scripts/check_examples.py
MIN_RUN_SECONDS=2 bash scripts/smoke_examples.sh ski-adventure
```

可通过 `EVE=/absolute/path/to/eve` 指定已有 SDK。完整玩法验收：

```sh
python3 examples/ski-adventure/tools/verify.py --eve /absolute/path/to/eve --suite all
```

也可选 `--suite controls` 或 `--suite course`，`--output` 指定证据根目录。
每次生成独立目录，包含运行日志、MCP 事件、源码和引擎哈希、通过/失败报告，
以及引擎 readback 截图。全程只用 `eve_play` 玩家动作，不使用 `eve_eval` 注入状态。
需要可运行 Vulkan 的桌面环境；Linux 无显示器时按仓库说明配置 Xvfb 和软件 Vulkan。
验收会打开并在结束时关闭其自身启动的游戏进程。

检查覆盖同位置重开、向右下滑行、跳跃与空中禁止连跳、暂停、碰撞、刹车、翻转计分、
无按键跳台腾空、三阶段通关、得分和雪崩失败。使用 SDK 运行所得结果只证明该 SDK
上的示例行为，不等价于重新构建当前引擎源码。视觉截图仍需人工检查。
