详细描述

脚本组件（eve.component 登记过的）在场景 inspector 里的属性与写回通道。

一个提供方服务**所有**脚本组件：componentType() 是固定槽 "eve.script-component"，具体是哪个 组件由 SceneComponentPayloadRef::component 里的稳定 id "<节点>|<组件名>@<版本>" 决定。这样编辑器里 所有脚本定义出来的组件集中在一类下，而它们的名字与版本（热重载不变的那两个身份）仍然逐条可见； 换成"每个组件类型一个提供方"就需要随脚本登记/热重载动态增删提供方，代价与收益不成比例。

对象 id 含义
SceneComponentPayloadRef::target 场景**宿主名**（TargetId 就是宿主名）
SceneComponentPayloadRef::object 节点 id
SceneComponentPayloadRef::component 稳定组件 id："<节点 id>\|<组件名>@<版本>"
备注
写走 IDomainOperationTarget + staging（ScriptComponentOperationTarget）：编辑器 的事务/撤销契约要求"能克隆出候选、能原子发布候选"，所以字段写回不能是一条直通的 setter。 字段值落在引擎侧存储里，脚本侧下一次读就看见新值——不需要再通知脚本。
字段的**类型**与**默认值**取自注册表里那份声明 schema（scriptComponentDeclaredSchema）， 不从当前值猜：否则脚本某次写入换个类型，inspector 的字段类型就会跟着漂。由此**可写 = 脚本里给了非 null 的默认值**——那才是类型与默认值的来源；声明成 null 的字段与登记已丢的 组件只读，但当前值照样显示（"有组件但没类型"看得见，而不是被静默藏掉）。

◆ HostResolver

using eve::scene_editor::ScriptComponentPayloadProvider::HostResolver = std::function<std::string(const scene_editing::TargetId&)>

编辑器目标 id → 场景**宿主名**。

自动化创建的编辑器目标 id 是**调用方选的**（eve_editor_target_create 的 target 字段），不 等于宿主名；宿主名是创建那个目标时才知道的事实（scene-host 目标的 host 请求字段）。 所以这条映射由创建目标的模块注入（SceneEditorModule），提供方不猜。

返回
每次调用返回一个**拥有**的 vector：调用方持有结果，提供方不保留指针。 @cost 与节点上挂着的脚本实例×其已登记组件数成正比，每次调用一次 vector 分配；编辑器只在 选中/刷新 inspector 时调用，不在逐帧路径上。
